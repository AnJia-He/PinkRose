# 小程序 WebGL 探针（2026-09-23）

> **这是探针，不是产品代码。** 它是为了回答一个问题而写的，答案拿到之后
> 它的使命就完成了。**别把它当成小程序版的 RuiXing。**

## 问题

RuiXing 现在是个浏览器应用。要在小程序里做，渲染那一层（手写的 WebGL）
必须重写 —— 但重写之前得先知道：**那套东西在小程序里跑不跑得动？**

具体三个子问题：

1. 小程序支不支持 WebGL2？（我们的着色器第一行是 `#version 300 es`）
2. **单边纹理上限是多少？** —— 这条被坑过：浏览器里那台手机只给 **4096**，
   而手机拍的照片长边 6560，直接画不出来（详见
   `docs/superpowers/plans/2026-09-22-conversational-editing-verification.md` §14）
3. 自报的上限**是不是真的**？—— iPhone 那条面积上限就是**静默失败**：
   不报错、画布全白。所以探针必须真画一遍、把像素读回来数颜色。

## 答案：跑得动，而且比浏览器宽裕 4 倍

**同一台手机**（Mali-G925-Immortalis MC12），两个环境：

| | 浏览器 | **小程序** |
|---|---|---|
| WebGL2 | ✅ | ✅ |
| **单边纹理上限** | **4096** | **16384** |
| 3200 万像素的照片（长边 6560） | ❌ 画不出来 | ✅ **绰绰有余** |

**这是这次探针最值钱的一条**：同一块 GPU，浏览器只给 4096，小程序给 16384。

也就是说 —— 我们 2026-09-23 上午为浏览器写的「超限就自动缩小」
（`src/render/limits.ts` + `src/image/resize.ts`），**移植到小程序之后是多余的**。
那套东西留着不碍事（它按设备自报的上限判断，宽裕的环境自然不触发），
但要知道它在那儿是为了浏览器，不是为了小程序。

## 还没搞懂的（如实记）

**照片按原尺寸（1536×2048）上传时报错 1281（INVALID_VALUE），缩到
1152×1536 就过** —— 可上限是 16384，尺寸离边还远。不知道是：
- 我们探针的用法问题（比如 `wx.createOffscreenCanvas` 有别的限制），还是
- 小程序/驱动的真实行为

**不挡路**（真正的实现里画布按屏幕尺寸来，不会按原图尺寸），但记在账上。
哪天真做小程序，第一件事就是把它验清楚。

## 探针自己犯过的三个错（都值得记）

三次里两次是**探针本身错了**，不是小程序不行：

| # | 症状 | 真正的原因 |
|---|---|---|
| 1 | 每一档都报「1 种颜色 = 静默失败」 | **采样点按 1024×1024 撒，但那块画布 CSS 只有 60rpx** —— 缓冲区没这么大，采样全落在外面，读回来一律是 0。把"没读到"报成了"画不出来" |
| 2 | 最大那档报 1281 | 直接把 `canvas.createImage()` 的对象传给 texImage2D。改成先画进离屏 2D 画布再上传 |
| 3 | 三个画布全报「节点拿不到」 | `q.node()` 单独写了一行、**没接住返回值**，然后拿原来的 q 去 exec —— 那个查询根本不知道要取节点 |

**教训**：探针得出的结论，先怀疑探针。第一版那个"全是静默失败"的结论看着
很吓人、很像重大发现，其实只是尺子坏了。**改完必须能在模拟器上跑出一致的
结果（数字和眼睛都对得上），再去真机。**

## 怎么重跑

需要**微信开发者工具**（本机装在 `D:\微信web开发者工具\`）。

1. 工具里：设置 → 安全设置 → **服务端口打开**（不开 CLI 用不了）
2. 起 CLI（PowerShell，注意工具装在中文路径下，从 Git Bash 直接调会被编码搞坏）：
   ```powershell
   $d = (Get-ChildItem 'D:\' -Directory | Where-Object { $_.Name -match '开发者工具' }).FullName
   & (Join-Path $d 'cli.bat') auto --project 'D:\RuiXing\spike\miniprogram-webgl' --auto-port 9420 --trust-project
   ```
3. 跑驱动（它会点按钮、轮询报告、截图）：
   ```
   npm i --no-save miniprogram-automator
   node spike/miniprogram-webgl/run-probe.cjs
   ```
4. **真机那一步得手动**：工具里点「预览」→ 手机微信扫码 → 点两个按钮

### 自动化能干什么、不能干什么

**能**：驱动**模拟器**，点按钮、读输出、截图 —— 用来把我自己写错的探针筛掉。

**不能**：回答"手机上跑不跑得动"。**模拟器跑在电脑的显卡上**
（实测 RENDERER 是 `ANGLE (Intel, Intel(R) UHD Graphics)`），
而手机是 `Mali-G925`。**两者的结论可以不一样，实测已经不一样了。**
