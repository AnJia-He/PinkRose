# 作品集（第二段）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「保存」真的把图留下来 —— 存进作品集、按天看得到、能改名、能下载、能删，点开还能看到这张图是怎么改出来的。

**Architecture:** 图片存硬盘（`data/photos/<随机串>.jpg`），数据库只记文件名。存储抽成一个 `server/storage.ts`，以后换云存储只改它。后端加一组 `/api/works*` 接口，每条查询都带 `user_id`（§6.1 的数据隔离）。前端加一个左栏导航 + 两个新界面（作品、详情页），并把「保存」从"自动下载"改成"存进作品集"。

**Tech Stack:** 沿用现状 —— 前端 React + TS + Vite（零 UI 库、手写 CSS），后端 Node 24 手写 `node:http` + `node:sqlite`，测试 vitest。**零新依赖。**

## Global Constraints

**每一条都是设计文档里的规矩，逐字抄下来。任何任务的要求都隐含包含这一节。**

- **零新依赖。** `dependencies` 永远只有 `piexifjs` / `react` / `react-dom`
- **每条查询都带 `user_id`** —— 数据隔离靠它。**变异：把 `user_id` 从任何一条 SQL 里去掉 → 那条测试必须红**（§6.1，spec 说这是"最重要"的一条）
- **删除 = 数据库记录 + 硬盘文件一起删。** 只删一边 = 硬盘慢慢堆满再也找不回来的垃圾（§4.4）
- **替换一张的顺序是「写新文件 → 改记录 → 再删旧文件」** —— 顺序不能反，先删旧的、写失败就丢图了（§4.4）
- **文件名必须是随机串**，不能是 1、2、3 —— 顺序数字的话，别人改一下数字就拿到你的图（§4.3）
- **详情页的网址里用 `id`，不用名字** —— 中文名会变成一长串 `%E4%B8%AD`，而且改完名链接就失效（§3.5.1）
- **配方必须分成两栏**：`调色`（能套到别的图）和 `AI 编辑`（套不走）。
  **变异：在接口里把两者合成一个数组 → 必须红**（§3.5.1）
- **AI 编辑那栏不给「套用」按钮** —— 给了就是在骗人（§3.5.1）
- **界面不许出现裸字段名**（`exposure` 这种）（§3.5.2）
- **参数名表只有一份** —— 挪进 `shared/`，微调面板和详情页都从它取。
  **变异：在页面上再写死一处 → 必须红**（§3.5.2）
- **`exposure` 的显示名是「亮度」**，不是"曝光"。**内部字段名不动**（改了会牵动 shader）（§3.5.2）
- **参数范围 -100 ~ +100**（主流刻度，已经是对的，别动）（§3.5.2）
- **保存不再自动下载** —— **变异：把自动下载加回保存流程 → 必须红**（§3.4）
- **删除确认只说「删了就找不回来了」** —— 不许说"你电脑上那份还在"，那是骗人（§3.5）
- **永远不自动删用户的东西**（§6.6）
- **「保存失败」必须当场给一个能拿到图的按钮** —— 他那一刻的目的是"拿到图去发朋友圈"，作品集存不进去是**我们这边的限制**，不该让他连图都拿不到（§6.6 ①）
- **凡告诉用户「不行」，都要同时告诉他「那怎么办」** —— 只说"不行"的地方都是死胡同（§3.7）
- **本地环境**：绑 localhost、走 HTTP、没有域名。不写部署相关的东西
- **★ 接口测试里的「必须抛」要指名道姓** —— `.rejects.toThrow()` / `expect(...).toThrow()`（**不带参数**）
  **任何**抛都能让它过，包括跟这条断言想守的东西**毫无关系**的那种。
  正确形状是 `toThrow(/这个仓库自己抛的那句话/)`。
  **变异：让守卫改抛别的错 → 那条断言必须红。**
  （这个形状在本段的第一个任务里抓到过两次，其中一次靠的是完全无关的 `ENOENT`。
  `storage.test.ts` / `db.test.ts` 里那几处当时就修了；**下面各任务里的那几处是后来扫出来补的** ——
  这是一条**会重复犯**的形状，不是一次性的清理。）

## 这一段里我自己拍的五个板（设计文档没写）

调研之后才发现的缺口。**每条都是我的裁定** —— 写在这儿，让做的人知道"为什么是这样"，也让验收的人一眼看到我替你定了什么。

### ① 图怎么传上去 —— **还是 base64 走 JSON，不开上传通道**

今天全仓库**没有任何上传通道**：三张图（route / suggest / edit）全是 base64 data URL 走 JSON，`readJsonBody` 已经有 12 MB 上限。
作品集沿用这条路，**不引入 multipart** —— 零依赖下自己解析 multipart 是一大坨容易出错的东西，而这条路已经被三个 AI 接口验证过了。

**存的不是上传的原始照片，是"导出用的那个 blob"**（`src/export/save.ts` 里 `buildExportBlob` 的产物，JPEG 含 EXIF）。
理由：详情页的「下载」就是把这份原样给他 —— **存的和下载的必须是同一个东西**，不然会出现"我下载到的和我看到的不一样"。

**太大的图**：导出后的 JPEG 一般 1 MB 上下（长边已经缩过），base64 后约 1.4 MB，离 12 MB 很远。
但**失败也必须有明确的说法**：超了就是 413，前端要说人话。

### ② 缩略图 —— **保存时前端顺手生成，一起传上去**

⚠️ **设计文档的接口清单里没有缩略图。** 但作品页一次摆 60 张，全取原图是几十 MB。

前端**已经有** `makeThumbnail(source, maxSide = 160)`（`src/core/thumbnail.ts`，返回 JPEG data URL）。
所以：保存时**同时传一张缩略图**，存成第二个文件（`data/photos/<随机>.thumb.jpg`），配一个 `GET /api/works/:id/thumb`。

**为什么不把缩略图塞进数据库**（那样列表一次就带回来了，省掉 60 个请求）：
§4.3 定死了「数据库只记文件名，不存图片本身」。2500 张 × 10 KB = 25 MB 塞进 SQLite 不算离谱，
但那条规矩的**理由**（"别把库撑爆"）在真实产品里只会更重要。**不为方便破它。**
列表仍然是「先拿名单，再一张张取图」—— 那正是 §3.5 写的两段式。

### ③ 列表一次全给，分组 / 搜索 / 懒加载都在前端

`GET /api/works` **一次性返回该用户全部作品的元数据**（id / alias / 时间 / 大小 / 有没有缩略图），**不分页、不带图**。2500 条约 250 KB。

> §3.5 原话：「**名单本小，一下子全拿出来；图片大，一张一张拿。**」—— 就是这个意思。

**搜索为什么不在后端**：作品没起名时，显示名是**渲染出来的**（`9月25日 14:30`）。
§3.5 说「搜『9月25』就等于按日期搜」—— 那后端就得把那个中文时间串也拼出来。
拼得出来（格式化放 `shared/works.ts`，两边共用一份），但**分组、搜索、懒加载三件事是在同一个列表上做的**，
拆成"后端搜 + 前端再分组"只会让边界变模糊。所以：**格式化进 `shared/`（两边都能用），搜索这一版放前端。**

> ⚠️ §10 的测试表把「搜作品」写成**接口测试**。按上面这条，它落在 `shared/works.ts` 的纯函数上 ——
> **这是对 spec 的一处偏离，已记进台账 Ruling。**

### ④ 配方里那几句「原话」从哪来 —— 从 `messages` 里拣，不新建结构

⚠️ 调研的发现：**今天没有任何结构在持久化"用户用 AI 做过哪几句原话"**。

| 看着像能用的 | 为什么不行 |
|---|---|
| `card.editPrompt` | 它是给**图片模型**的英文 prompt；而且全流程只活在函数入参 / `pendingRef` 里，没有任何持久结构接住它 |
| `pendingRef` | 只有**当前这一趟**那一句，下一次就被覆盖 |
| `Snapshot`（撤销栈） | 有 `params`、没有原话 —— 它是"参数的历史"，不是"说过的历史" |

**裁定：`Recipe.edits` = 保存那一刻，`messages` 里所有 `role === 'user'` 的 `text`。**

三条理由：

1. **那正是「用户在屏幕上看到、并说出口的话」。** 走「点建议卡片」那条路时存进去的是 `card.label`
   （`App.tsx:412`）—— 而**屏幕上显示的就是那句话**，他看到的是它、点的也是它。
   用户自己打的字和卡片标签，在界面上地位一样，**都是"他说的话"**。
2. **`messages` 在换图时会被清空**（`App.tsx:336`）—— 所以它天然就是"**当前这张图**的对话"，
   不是"整个会话的"。正好是配方要的粒度。
3. **不需要任何新状态。** 不用新加一套记录，也就没有"哪天忘了同步"的可能。

⚠️ **坚决不记 `editPrompt`。** 它是我们的实现细节（给图片模型的英文 prompt）。
用户原话出现在详情页上是对的；一段英文 prompt 出现在那儿是错的。

### ⑤ 「套用调色」在没有图的时候 —— 禁用 + 说清楚，不许"套了再说"

调研发现两件事：

- **改 `params` 从来不 push 快照** —— 滑块、预设、重置、参数卡片，一个都不 push
  （快照只在 `runGenerate` 生成成功后推一次，`App.tsx:220-231`）。
  所以「套用」就该和它们**同级**：裸调 `setParams(recipe.params)`。
  **不要自作聪明去 push 快照** —— 那会凭空多出一种"参数也算一步"的行为，
  而撤销栈是给"生成式编辑"用的（`Snapshot` 里还有一张 GPU 位图）。
- **没有图的时候**：`setParams` 照改 state，但界面上**什么都不显示**
  （工作区 / Canvas / 微调面板全由 `{image && ...}` 把守），
  而且下一次 `onPick` 会**无条件** `setParams(ZERO)`（`App.tsx:335`）——
  **套用的那套参数会悄悄丢掉。**

**裁定：没图时按钮禁用**，旁边一句「先回修图页传一张照片」。
不做"套了再引导去上传" —— 那几个数会被 `onPick` 清掉，那就成了骗人（§3.7 那条铁规矩）。

## Task 1: 存储层

**Files:**
- Create: `server/storage.ts`
- Create: `server/storage.test.ts`

**Interfaces:**
- Consumes: 无
- Produces:
  ```ts
  export type Storage = {
    /** 存一份，返回它在这层里的名字（随机串 + 扩展名）。调用方只管拿这个名字，别自己拼路径 */
    save(bytes: Uint8Array, ext: string): Promise<string>
    /** 按名字读回来。名字不合法、或文件不在 → 抛 */
    read(name: string): Promise<Uint8Array>
    /** 删掉。文件本来就不在 = 成功（删两次不该炸） */
    remove(name: string): Promise<void>
    /** 多大。不在 → 抛 */
    sizeOf(name: string): Promise<number>
  }
  /** root 是这一层的根目录。生产传 `data/photos`，测试传临时目录 */
  export function createStorage(root: string): Storage
  ```

**为什么要有这一层**（§4.3 原话）：本地用硬盘，以后上线换云存储（OSS / S3），**上面那层代码不用动**。
所以 `server/works.ts` 里**只许**调这四个方法 —— **不许出现 `node:fs`，不许拼 `data/photos/...` 这样的路径**。

```ts
    expect(await s.read(name)).toEqual(bytes)
```

```ts
 * 这一层**只认名字，不认路径**：调用方给它的是 `save` 返回的那个随机串，根目录由它自己拼。
 * 所以名字里带 `/` 或 `..` 一律拒 —— 那种名字本来不该出现，出现了就说明有脏东西在往里塞。
 */
const NAME_OK = /^[A-Za-z0-9_-]+\.[A-Za-z0-9]+$/
const EXT_OK = /^\.[A-Za-z0-9]+$/

export type Storage = {
  save(bytes: Uint8Array, ext: string): Promise<string>
  read(name: string): Promise<Uint8Array>
  remove(name: string): Promise<void>
  sizeOf(name: string): Promise<number>
}

export function createStorage(root: string): Storage {
  // 根目录先建出来 —— 第一次存的时候 data/photos 还不存在
  mkdirSync(root, { recursive: true })

  const pathOf = (name: string): string => {
    if (!NAME_OK.test(name)) throw new Error(`不合法的文件名：${name}`)
    return join(root, name)
  }

  return {
    async save(bytes, ext) {
      // 扩展名也过一遍守卫 —— 它同样是调用方给的
      if (!EXT_OK.test(ext)) throw new Error(`不合法的扩展名：${ext}`)
      // 16 字节随机 = 32 个十六进制字符。
      // **不能是 1、2、3** —— 顺序数字的话，别人改一下数字就拿到你的图（§4.3）
      const name = randomBytes(16).toString('hex') + ext
      await writeFile(pathOf(name), bytes)
      return name
    },
    async read(name) {
      return new Uint8Array(await readFile(pathOf(name)))
    },
    async remove(name) {
      // force: true —— 文件本来就不在也算成功。
      // 删两次不该炸：批量删里"它已经被别处删过了"是**正常情况**，不是错误（§3.5）
      await rm(pathOf(name), { force: true })
    },
    async sizeOf(name) {
      return (await stat(pathOf(name))).size
    },
  }
}
```

新建 `shared/works.ts`：

```ts
import type { Adjustments } from './adjustments.ts'

/**
 * 作品的**元数据** —— 不含图，也不含配方。
 *
 * 列表接口一次把这个用户的全部元数据给出去（§3.5：「名单本小，一下子全拿出来」），
 * 图再一张张取。所以这个结构要**小**：别往里加会变大的东西。
 */
export type WorkMeta = {
  id: number
  /** 用户起的名字。**空 = 用最后改动的时间当名字**（§3.5） */
  alias: string | null
  createdAt: number
  updatedAt: number
  bytes: number
  /** 有没有缩略图。没有的时候前端退回取原图（前端生成缩略图可能失败，见 Task 6） */
  hasThumb: boolean
}

/**
 * **配方**：这张图是怎么来的。§3.5.1 说它必须分成两拦 ——
 *
 * - `params`：**调色**，能套到别的图上（纯数值）
 * - `edits`：**用 AI 做过哪几句原话**，套不走 —— 只对这张照片有意义
 *
 * ⚠️ **两拦永远是分开的两个字段。** 合成一个数组 = 用户会以为"这一整套都能复用"，
 * 而「把后面那个人去掉」换一张照片就是另一回事（§3.5.1，spec 点名要变异这条）。
 */
export type Recipe = {
  params: Adjustments
  edits: string[]
}

export type WorkDetail = WorkMeta & { recipe: Recipe }

export type DayGroup = { day: string; label: string; works: WorkMeta[] }

const pad = (n: number): string => String(n).padStart(2, '0')

/**
 * `'2026-09-25'` —— 分组和排序用的键。
 *
 * ⚠️ **别拿显示名当键**：显示名今年是「9月25日」、明年会变成「2026年9月25日」，
 * 拿它当键会在跨年那天错位。
 */
export function dayKey(ts: number): string {
  const d = new Date(ts)
  return `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`
}

/** 「9月25日」；**不是今年的才带年份** */
export function dayLabel(ts: number, now: number): string {
  const d = new Date(ts)
  const year = d.getFullYear() === new Date(now).getFullYear() ? '' : `${d.getFullYear()}年`
  return `${year}${d.getMonth() + 1}月${d.getDate()}日`
}

/**
 * 这张作品在界面上叫什么。
 *
 * **没起名字就用最后改动的时间**（§3.5）—— 于是「搜 9月25」自然就等于按日期搜，
 * 一个机制两种用法。这也是为什么这个函数住在 `shared/`：它是"名字"的唯一来源。
 */
export function workName(w: WorkMeta, now: number): string {
  if (w.alias) return w.alias
  const d = new Date(w.updatedAt)
  return `${dayLabel(w.updatedAt, now)} ${pad(d.getHours())}:${pad(d.getMinutes())}`
}

/**
 * 搜索：按**屏幕上看得到的那个名字**匹配。
 *
 * 所以改了名之后，原来的日期就搜不到了 —— 那是**对的**：屏幕上没有那几个字了，
 * 还让它搜中的话，用户会看到"一堆屏幕上没这几个字的图"。
 */
export function matchesQuery(w: WorkMeta, query: string, now: number): boolean {
  const q = query.trim().toLowerCase()
  if (!q) return true
  return workName(w, now).toLowerCase().includes(q)
}

/** 按天分组，新的在前，组内也新的在前。 */
export function groupByDay(works: readonly WorkMeta[], now: number): DayGroup[] {
  const sorted = [...works].sort((a, b) => b.updatedAt - a.updatedAt)
  const groups = new Map<string, DayGroup>()
  for (const w of sorted) {
    const key = dayKey(w.updatedAt)
    let g = groups.get(key)
    if (!g) {
      g = { day: key, label: dayLabel(w.updatedAt, now), works: [] }
      groups.set(key, g)
    }
    g.works.push(w)
  }
  return [...groups.values()]
}
```

```ts
import type { Db } from './db.ts'
import type { Storage } from './storage.ts'
import type { PublicUser } from './account.ts'
import { HttpError, asObject, str } from './http.ts'
import { ZERO, applyDeltas, type Adjustments } from '../shared/adjustments.ts'
import type { Recipe } from '../shared/works.ts'

export type WorksDeps = { db: Db; storage: Storage; now?: () => number }

/** 单张图的上限。前端导出的是 2048 长边的 JPEG，一般 1 MB 上下 —— 8 MB 是很宽的余量 */
const MAX_WORK_BYTES = 8 * 1024 * 1024
/** 配方里最多记几句、每句多长。防的是"有人存一万条" */
const MAX_EDITS = 100
const MAX_EDIT_LEN = 200

const nowMs = (deps: WorksDeps): number => (deps.now ?? Date.now)()

export type WorkRow = {
  id: number; user_id: number; stored_name: string; thumb_name: string | null
  bytes: number; created_at: number; updated_at: number; alias: string | null; recipe: string
}

/**
 * 把 `data:image/jpeg;base64,…` 解成字节 + 扩展名。
 *
 * ⚠️ 这个仓库里**第一次**有人真的去解一个 data URL —— 三个 AI 接口只校验前缀就把整串
 * 转给上游了。所以这里的每一个边界都得自己守：只收 jpeg / png（导出就这两种），
 * 正则直接把"带别的东西的串"挡在外面，`Buffer.from(…, 'base64')` 对垃圾输入**不抛**
 * （`server/password.ts:66` 记过这一条），所以**不能靠 try/catch 兜底**，
 * 只能靠前面的正则先把形状卡死。
 */
function decodeDataUrl(s: string): { bytes: Uint8Array; ext: string } {
  const m = /^data:image\/(jpeg|png);base64,([A-Za-z0-9+/]+={0,2})$/.exec(s)
  if (!m) throw new HttpError('BAD_REQUEST', '图得是 data:image/jpeg 或 data:image/png 的 base64', 400)
  return {
    bytes: new Uint8Array(Buffer.from(m[2]!, 'base64')),
    ext: m[1] === 'png' ? '.png' : '.jpg',
  }
}

/**
 * 读客户端送上来的配方。
 *
 * 客户端可以完全不传（那就当"什么都没改过"）—— 但**绝不能存成 null**：
 * 详情页的"这张图怎么来的"永远要有东西可显示（哪怕是一排 0）。
 */
function readRecipe(raw: unknown): Recipe {
  if (raw === undefined || raw === null) return { params: ZERO, edits: [] }
  const o = asObject(raw)
  const edits = (Array.isArray(o.edits) ? o.edits : [])
    .filter((x): x is string => typeof x === 'string' && x.trim().length > 0)
    .map((x) => x.slice(0, MAX_EDIT_LEN))
    .slice(0, MAX_EDITS)
  return { params: applyDeltas(ZERO, asObject(o.params) as Partial<Adjustments>), edits }
}

export async function handleCreateWork(
  body: unknown, user: PublicUser, deps: WorksDeps,
): Promise<{ id: number }> {
  const o = asObject(body)
  const image = decodeDataUrl(str(o.image))
  if (image.bytes.byteLength === 0) throw new HttpError('BAD_REQUEST', '图是空的', 400)
  if (image.bytes.byteLength > MAX_WORK_BYTES) {
    throw new HttpError('BAD_REQUEST', '这张图太大了，存不下', 413)
  }

  // 缩略图是**可选**的：前端生成失败时，不该让整张图都存不进去（裁定 ②）
  const thumbRaw = str(o.thumb)
  const thumb = thumbRaw ? decodeDataUrl(thumbRaw) : null
  const recipe = readRecipe(o.recipe)

  const storedName = await deps.storage.save(image.bytes, image.ext)
  let thumbName: string | null = null
  if (thumb) {
    try {
      thumbName = await deps.storage.save(thumb.bytes, thumb.ext)
    } catch (e) {
      // 缩略图存不下不该拖垮整张图 —— 但也不能静默，不然盘满的时候没人知道
      console.error('缩略图存不进去，这张作品没有缩略图：', e)
    }
  }

  const t = nowMs(deps)
  try {
    const r = deps.db.raw.prepare(
      `INSERT INTO works (user_id, stored_name, thumb_name, bytes, created_at, updated_at, alias, recipe)
       VALUES (?, ?, ?, ?, ?, ?, NULL, ?)`,
    ).run(user.id, storedName, thumbName, image.bytes.byteLength, t, t, JSON.stringify(recipe))
    return { id: Number(r.lastInsertRowid) }
  } catch (e) {
    // ★ 插不进库就把刚写的文件收回来。不收的话它们永远留在盘上，
    // 而且**没有任何东西知道它们是什么** —— 一个查不到的 id 对应两个文件。
    await deps.storage.remove(storedName).catch(() => { /* 收不回来也不能盖掉原始错误 */ })
    if (thumbName) await deps.storage.remove(thumbName).catch(() => {})
    throw e
  }
}
```

```ts
/** 从文件名尾巴推 MIME。认不出来就按 jpeg —— 存进去的只可能是这两种 */
function mimeOf(name: string): string {
  return MIME[name.slice(name.lastIndexOf('.'))] ?? 'image/jpeg'

/**
 * 取一张**属于这个人的**作品。

 * ★ 这个函数是 §6.1「每条查询都带 user_id」的落点 —— 所有按 id 取作品的路径
 * 都必须经过它，不许有人自己写一条 `WHERE id = ?` 就完事。
 *
 * 不是他的、和不存在，回**同一句话**：分开说就等于告诉别人哪些 id 是真的。
 */
export function loadOwned(id: number, user: PublicUser, deps: WorksDeps): WorkRow {
  const row = deps.db.raw.prepare(
    'SELECT * FROM works WHERE id = ? AND user_id = ?',
  ).get(id, user.id) as WorkRow | undefined
  if (!row) throw new HttpError('BAD_REQUEST', '没有这张作品', 404)
  return row
}

export async function handleWorkFile(id: number, user: PublicUser, deps: WorksDeps) {
  const row = loadOwned(id, user, deps)
  return { bytes: await deps.storage.read(row.stored_name), contentType: mimeOf(row.stored_name) }
}

export async function handleWorkThumb(id: number, user: PublicUser, deps: WorksDeps) {
  const row = loadOwned(id, user, deps)
  // 没缩略图就退回原图。缩略图是**前端生成的**，可能失败；
  // 前端按 hasThumb 选 URL，这儿只是兜底 —— 万一两处对不上（比如文件被手工删了），
  // 让用户看到一张大图，也比看到一块白屏强。
  const name = row.thumb_name ?? row.stored_name
  return { bytes: await deps.storage.read(name), contentType: mimeOf(name) }
}
```

  ```ts
export function handleGetWork(id: number, user: PublicUser, deps: WorksDeps): WorkDetail {
  ```

```ts
/** 别名最长多少。60 个字够放下一句描述，又不至于把列表撑变形 */
const MAX_ALIAS = 60

export function handleRenameWork(
  id: number, body: unknown, user: PublicUser, deps: WorksDeps,
): WorkMeta {
  const row = loadOwned(id, user, deps)
  const raw = asObject(body).alias
  // `null` / 空串 / 全空白，都是"把名字清掉、改回用时间当名字"——
  // 那是个**有意义的状态**（§3.5），不是缺数据，所以存 null 而不是空串

  // ⚠️ **只改 alias，不碰 updated_at**（见上面那段说明）
  deps.db.raw.prepare('UPDATE works SET alias = ? WHERE id = ? AND user_id = ?')
    .run(alias, id, user.id)
  return toMeta({ ...row, alias })
}
```

## Task 8: 删、批量删、替换

**Files:**
- Modify: `server/works.ts`（加三个处理函数）
- Modify: `server/app.ts`（挂三条路由）

**Interfaces:**
- Produces:
  ```ts
  export function handleDeleteWork(id: number, user: PublicUser, deps: WorksDeps): Promise<{ ok: true }>
  export function handleDeleteWorks(body: unknown, user: PublicUser, deps: WorksDeps): Promise<{ deleted: number[]; missing: number[] }>
  export function handleReplaceWork(id: number, body: unknown, user: PublicUser, deps: WorksDeps): Promise<WorkMeta>
  ```

**三个顺序问题，每个都是"写反了会丢东西"：**

| 操作 | 顺序 | 反过来的后果 |
|---|---|---|
| **删一张** | **先删记录，再删文件** | 反过来的话：文件删了、记录删失败 → 留下一条**永远打不开、也删不掉第二次**的记录 |
| **替换一张** | **写新文件 → 改记录 → 再删旧文件**（§4.4 原话） | 反过来：新文件还没写就先删了旧的 → 写失败 = **图丢了** |
| **批量删** | 逐个删，**一个失败不影响别的**（§3.5） | 全有全无的话，12 张里 1 张有问题就一张都删不掉 |

**批量删的回报**（§3.5 点名的：「**不能静默**」）：
`missing` 是"请求里那些**不在你作品集里**的 id" —— 它们**算成功**（目标已达成），
但要**如实报出来**，不然用户看到"我说删 12 张、它说删了 10 张"会以为出错。

```ts
/**
 * 删一张。
 *
 * ★ **先删记录，再删文件。** 反过来的话（文件先没了、记录删失败），
 * 会留下一条指向不存在文件的记录 —— 那条记录**永远打不开、也删不掉第二次**
 * （因为它还在列表里，而再删一次还是同样的顺序）。反过来失败最多留个孤儿文件：
 * 浪费一点盘，**用户那边完全正常**。
 *
 * 文件删失败不让请求失败：记录已经没了，对用户来说这件事**就是成功了**
 * （§3.5 那条"目标已达成"）。但要记一笔日志，不然盘满的时候没人知道。
 */
export async function handleDeleteWork(id: number, user: PublicUser, deps: WorksDeps): Promise<{ ok: true }> {
  const row = loadOwned(id, user, deps)
  deps.db.raw.prepare('DELETE FROM works WHERE id = ? AND user_id = ?').run(id, user.id)
  await deps.storage.remove(row.stored_name).catch((e) => console.error('作品文件没删掉，成了孤儿：', e))
  if (row.thumb_name) {
    await deps.storage.remove(row.thumb_name).catch((e) => console.error('缩略图没删掉：', e))
  }
  return { ok: true }
}

/**
 * 批量删。
 *
 * §3.5：「不追求全有全无」「如实回报」「不能静默」——
 * 所以**逐个删**（一个出问题不影响别的），并把"本来就不在"的那些**报出来**。
 */
export async function handleDeleteWorks(
  body: unknown, user: PublicUser, deps: WorksDeps,
): Promise<{ deleted: number[]; missing: number[] }> {
  const raw = asObject(body).ids
  const ids = (Array.isArray(raw) ? raw : [])
    .map((x) => Number(x))
    .filter((x) => Number.isInteger(x) && x > 0)
  if (ids.length === 0) throw new HttpError('BAD_REQUEST', '没给要删哪些', 400)
  // 上限：一次别删太多，免得一个请求跑几分钟（前端一次最多选中一屏）
  if (ids.length > 500) throw new HttpError('BAD_REQUEST', '一次最多删 500 张', 400)

  const deleted: number[] = []
  const missing: number[] = []
  for (const id of ids) {
    try {
      await handleDeleteWork(id, user, deps)
      deleted.push(id)
    } catch {
      // 走到这儿几乎只有一种原因：这张**不在他的作品集里**（别处删过了）。
      // 那是"目标已达成"，不是错误 —— 但要报出来，不能静默。
      missing.push(id)
    }
  }
  return { deleted, missing }
}

/**
 * 替换一张（换图 + 换配方）。
 *
 * ★ 顺序是 §4.4 定死的：**写新文件 → 改记录 → 再删旧文件**。
 * 先删旧的话，新文件还没写成功就把旧的删了 —— 那一下失败就是**图没了**。
 */
export async function handleReplaceWork(
  id: number, body: unknown, user: PublicUser, deps: WorksDeps,
): Promise<WorkMeta> {
  const row = loadOwned(id, user, deps)
  const o = asObject(body)
  const image = decodeDataUrl(str(o.image))
  if (image.bytes.byteLength === 0) throw new HttpError('BAD_REQUEST', '图是空的', 400)
  if (image.bytes.byteLength > MAX_WORK_BYTES) {
    throw new HttpError('BAD_REQUEST', '这张图太大了，存不下', 413)
  }
  const thumbRaw = str(o.thumb)
  const thumb = thumbRaw ? decodeDataUrl(thumbRaw) : null

  const newName = await deps.storage.save(image.bytes, image.ext)
  const newThumb = thumb ? await deps.storage.save(thumb.bytes, thumb.ext) : null
  const t = nowMs(deps)

  try {
    deps.db.raw.prepare(
      `UPDATE works SET stored_name = ?, thumb_name = ?, bytes = ?, updated_at = ?, recipe = ?
       WHERE id = ? AND user_id = ?`,
    ).run(newName, newThumb, image.bytes.byteLength, t, JSON.stringify(readRecipe(o.recipe)), id, user.id)
  } catch (e) {
    // 记录没改成功 → 把**新写的**收回来，旧的一动没动：库里和盘上都还是原来那张
    await deps.storage.remove(newName).catch(() => {})
    if (newThumb) await deps.storage.remove(newThumb).catch(() => {})
    throw e
  }

  // ★ 到这儿记录已经指向新文件了，才能删旧的
  await deps.storage.remove(row.stored_name).catch((e) => console.error('旧文件没删掉，成了孤儿：', e))
  if (row.thumb_name) await deps.storage.remove(row.thumb_name).catch(() => {})

  return toMeta({ ...row, stored_name: newName, thumb_name: newThumb, bytes: image.bytes.byteLength, updated_at: t })
}
```

```ts
/** 四个动词只差一个 method 和一个 body —— 抽出来，"带不带 cookie"仍然只有一处说了算 */
function send<T>(method: string, path: string, body?: unknown): Promise<T> {
  return request<T>(path, {
    method,
    ...(body === undefined
      ? {}
      : { headers: { 'content-type': 'application/json' }, body: JSON.stringify(body) }),
  })
}

export const post = <T>(path: string, body: unknown): Promise<T> => send<T>('POST', path, body)
export const get = <T>(path: string): Promise<T> => send<T>('GET', path)
export const patch = <T>(path: string, body: unknown): Promise<T> => send<T>('PATCH', path, body)
export const put = <T>(path: string, body: unknown): Promise<T> => send<T>('PUT', path, body)
export const del = <T>(path: string): Promise<T> => send<T>('DELETE', path)
```

```ts
import { get, post, patch, put, del } from './client'
import type { WorkMeta, WorkDetail, Recipe } from '../../shared/works.ts'

/**
 * 作品集的接口。图**不从这里走** —— 它是 `<img src>` 让浏览器自己取的，
 * 所以 `fileUrl()` 返回的是一段网址，不是一次请求。

export async function listWorks(): Promise<WorkMeta[]> {
  return (await get<{ works: WorkMeta[] }>('/api/works')).works
}

export async function getWork(id: number): Promise<WorkDetail> {
  return get<WorkDetail>(`/api/works/${id}`)
}

export type WorkInput = { image: string; thumb?: string; recipe?: Recipe }

export async function createWork(o: WorkInput): Promise<{ id: number }> {
  return post<{ id: number }>('/api/works', o)
}

export async function replaceWork(id: number, o: WorkInput): Promise<WorkMeta> {
  return put<WorkMeta>(`/api/works/${id}`, o)
}

  return patch<WorkMeta>(`/api/works/${id}`, { alias })
}

export async function deleteWork(id: number): Promise<void> {
  await del<{ ok: true }>(`/api/works/${id}`)
}

export async function deleteWorks(ids: number[]): Promise<{ deleted: number[]; missing: number[] }> {
  return post<{ deleted: number[]; missing: number[] }>('/api/works/delete', { ids })
}

/**

 *
 * ⚠️ `?v=<updatedAt>` **不能去掉**：替换过一张之后 id 没变，
```

```ts
import type { DayGroup } from '../../shared/works.ts'

/**
 * 先摆几天的 —— 也就是"先摆 60 张"的那 60（§3.5）。
 *
 * ⚠️ **按天取整，不在一天中间截断。** 截断的话那天的标题会写着「9月25日 · 200 张」
 * 而下面只有 60 张 —— 用户会以为丢了 140 张。
 * §3.5 说的「分组不只是为了好看，它同时是分页的边界」就是这个意思。
 */
export function visibleGroups(groups: readonly DayGroup[], limit: number): DayGroup[] {
  const out: DayGroup[] = []
  let n = 0
  for (const g of groups) {
    out.push(g)
    n += g.works.length
    if (n >= limit) break
  }
  return out
}
```

```tsx
import { useEffect, useMemo, useState } from 'react'
import { getWork, renameWork, deleteWork, fileUrl } from '../api/works'
import { workName, type WorkDetail } from '../../shared/works.ts'
import { PARAM_LABELS, PARAM_KEYS, type Adjustments } from '../../shared/adjustments.ts'

export function WorkDetailPage({ id, onBack, onApply, canApply }: {
  id: number
  onBack: () => void
  onApply: (params: Adjustments) => void
  canApply: boolean
}) {
  const [work, setWork] = useState<WorkDetail | null>(null)
  const [failed, setFailed] = useState<string | null>(null)
  const [renaming, setRenaming] = useState(false)
  const [confirming, setConfirming] = useState(false)
  const [busy, setBusy] = useState(false)

  // ⚠️⚠️ **这个 hook 必须在所有 `return` 之前** —— 它一度被放在下面那两条
  // early return 之后，挂了「Rendered more hooks than during the previous render」，
  // 一挂载就炸（四条用例一起红）。教训和第二处：
  //
  // ⚠️ **`now` 必须是"现在"，不能图省事传 `work.updatedAt`。**
  // `workName` 把 `now` 交给 `dayLabel`，而 `dayLabel` 只在**跨年**时才补上「2023年」——
  // 传 `work.updatedAt` 的话，"已经过去多久"永远是 0，年份**永远不显示**。
  // 后果是**同一个东西在两个屏幕上叫两个名字**：作品页说「2023年11月15日 06:13」，
  // 点进详情页变成「11月15日 06:13」。而 §3.5 的「名字就是日期所以搜日期也能搜到」
  // 正是建立在"名字只有一份"上的。和 `GalleryPage` 里那条 `useMemo(() => Date.now(), [])`
  // 同一个写法、同一个理由（一次挂载只取一次）。
  const now = useMemo(() => Date.now(), [])

  useEffect(() => {
    let alive = true
    getWork(id).then(
      (w) => { if (alive) setWork(w) },
      (e) => { if (alive) setFailed(e instanceof Error ? e.message : '打不开这一张') },
    )
    return () => { alive = false }
  }, [id])

  async function doRename(alias: string) {
    setRenaming(false)
    const next = alias.trim()
    if (next === (work?.alias ?? '')) return          // 没改就什么也不做
    setBusy(true)
    try {
      const got = await renameWork(id, next || null)   // 清空 = 改回用时间当名字
      setWork(w => (w ? { ...w, alias: got.alias } : w))
    } catch (e) {
      setFailed(e instanceof Error ? e.message : '没改成，再试一次')
    } finally { setBusy(false) }
  }

  async function doDelete() {
    setConfirming(false)
    setBusy(true)
    try {
      await deleteWork(id)
      onBack()          // 删完回列表 —— 留在一个已经不存在的页面上最难受
    } catch (e) {
      setFailed(e instanceof Error ? e.message : '没删掉，再试一次')
      setBusy(false)
    }
  }

  if (failed && !work) return <section className="detail"><p className="detail-error">{failed}</p></section>
  if (!work) return <section className="detail"><p className="detail-loading">正在打开…</p></section>

  // ⚠️ 这里**不许再写 `useMemo`** —— `now` 已经提到组件顶上、所有 `return` 之前了
  // （写在 early return 之后会炸 hook 顺序，见上面那段的说明）。
  const name = workName(work, now)
  const { params, edits } = work.recipe

  return (
    <section className="detail">
      <header className="detail-head">
        <button className="detail-back" onClick={onBack}>← 作品</button>
        {renaming ? (
          <input className="rename-input" autoFocus defaultValue={work.alias ?? ''}
                 onBlur={e => void doRename(e.target.value)}
                 onKeyDown={e => {
                   if (e.key === 'Enter') void doRename((e.target as HTMLInputElement).value)
                   if (e.key === 'Escape') setRenaming(false)
                 }} />
        ) : (
          <>
            <h1 className="detail-name">{name}</h1>
            <button className="detail-rename" disabled={busy} onClick={() => setRenaming(true)}>改名</button>
          </>
        )}
      </header>

      {failed && <p className="detail-error">{failed}</p>}

      <img className="detail-image" src={fileUrl(work)} alt={name} />

      <div className="detail-actions">
        {/* 下载就是把这个文件给他 —— 和存在服务器上的**是同一份**（裁定 ①） */}
        <a className="detail-download" href={fileUrl(work)} download>下载到我的电脑</a>
        {confirming ? (
          <span className="detail-confirm">
            <span>删掉作品集里的这一份吗？删了就找不回来了。</span>
            <button onClick={() => void doDelete()} disabled={busy}>删掉</button>
            <button onClick={() => setConfirming(false)}>取消</button>
          </span>
        ) : (
          <button className="detail-delete" disabled={busy} onClick={() => setConfirming(true)}>删除</button>
        )}
      </div>

      <div className="how">
        <h2 className="how-title">这张图怎么来的</h2>

        {/* ⚠️ **两栏永远是两栏，别合**（§3.5.1）。调色是配方，AI 编辑是这张图的经历 ——
            配方能带走，经历带不走。合起来用户会以为"这一整套都能复用"。 */}
        <section className="recipe-box">
          <h3>调色</h3>
          <p className="recipe-note">这一套能套到别的图上</p>
          <ul className="recipe-params">
            {PARAM_KEYS.map(k => (
              <li key={k}>
                <span className="recipe-param-name">{PARAM_LABELS[k]}</span>
                <span className="recipe-param-value">
                  {/* 0 就不列了 —— 一排 0 只是噪音，用户要的是"改过什么" */}
                  {params[k] === 0 ? '—' : (params[k] > 0 ? `+${params[k]}` : String(params[k]))}
                </span>
              </li>
            ))}
          </ul>
          <button className="recipe-apply" disabled={!canApply} onClick={() => onApply(params)}>
            把这套调色套到我正在改的图
          </button>
          {/* §3.7：告诉用户"不行"的地方，都要同时告诉他"那怎么办" */}
          {!canApply && <p className="recipe-hint">先回修图页传一张照片，才能套上去。</p>}
        </section>

        <section className="recipe-box">
          <h3>用 AI 做的</h3>
          <p className="recipe-note">这一栏属于这张照片，套不到别的图上</p>
          {edits.length === 0
            ? <p className="recipe-empty">这一张没有用过 AI。</p>
            : <ul className="recipe-edits">{edits.map((t, i) => <li key={i}>{t}</li>)}</ul>}
          {/* ⚠️ 这里**故意一个按钮都没有**。给「套用」就是在骗人 ——
              「把后面那个人去掉」换一张照片就是另一回事（§3.5.1）。 */}
        </section>
      </div>
    </section>
  )
}
```

**Interfaces:**
- Consumes: `createWork` / `replaceWork`（Task 11）、`makeThumbnail`（早就有）、`Recipe`（Task 3）
- Produces: `export function blobToDataUrl(blob: Blob): Promise<string>`（`src/export/save.ts`）

**这一段最重要的一条**（§6.6 ①，§10 说它「**最容易漏**」）：

> **「保存」现在只做存档这一件事。所以存不进去的时候，改好的图只在屏幕上 —— 一关页面就没了。**
> **必须当场给他一个「下载到电脑」的按钮。**
> 用户那一刻的目的是"拿到图去发朋友圈"。作品集满了是**我们这边的限制**，不该让他连图都拿不到。

**另外两件（都是 §3.4 定死的）：**

- **「保存」不再自动下载。** 下载挪到作品集里，由用户自己决定要哪张、存到哪。
  > 理由：设一个"默认开"的开关很别扭 —— **用户一开始根本不知道有这么个开关**。
  > 与其藏一个他看不见的设置，不如把决定权直接摆在按钮上。顺带也不再偷偷往他的下载文件夹堆东西。
- **同一张照片第二次保存起，问一句「上次那张要替换掉吗？」**
  > 不然同一张照片改 5 遍就是 5 张几乎一样的图，作品集立刻没法看。
  > 「再存一张」仍然允许 —— 只是要用户**明确说要**。

**配方从哪来**（裁定 ④）：`edits` = 保存那一刻 `messages` 里所有 `role === 'user'` 的 `text`。
**不记 `editPrompt`** —— 那是给图片模型的英文 prompt，是我们的实现细节。

```tsx
    const canvas = canvasElRef.current

    let thumb: string | undefined

    } catch (e) {

      edits: messages.filter(m => m.role === 'user').map(m => m.text),
    }
    const body = { image: await blobToDataUrl(blob), thumb, recipe }
    if (replaceId !== null) {
      await replaceWork(replaceId, body)

    // 不新加一套提示机制）。漏了它，`saveOnce` 会闭包住旧的那一份。
  }, [params, messages, say])

    const canvas = canvasElRef.current
    const file = originalFileRef.current
    if (!canvas || !file) return
    setDelivering('save')
    setSaveFail(null)
    const name = buildFilename(file.name, 'image/jpeg')
    let blob: Blob | null = null
    try {
      blob = await buildExportBlob(canvas, file, 'image/jpeg', 0.95)
      if (savedId !== null) {

        setAsking({ blob, name })
```
