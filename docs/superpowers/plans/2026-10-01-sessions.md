# 会话落库 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 上传照片的那一刻就在服务端建一条"会话"，边改边存；关掉浏览器再回来，接着改。

**Architecture:** 新开一张 `sessions` 表（不动 `works`），一条会话 = 一张上传的照片。服务端**自己给每一步分配图片文件**（客户端不许指定文件名 —— 那是一条能引用别人文件的洞）。前端在"上传 / 每一步 / 挂载"三处各挂一下。

**Tech Stack:** Node 自带 `node:sqlite`（手写迁移，只许追加）+ 手写 HTTP 路由（精确匹配 + 锚定正则）+ React 18 + Vite。测试用 vitest。

**Spec:** `docs/superpowers/specs/2026-10-01-sessions-design.md` —— 先读它。这份计划是它的落地版，**凡它没写清的，以它为准而不是以这份为准**。

## Global Constraints

以下每一条都是这个仓库的**硬规矩**，每个任务都隐含包含：

- **迁移只许往后追加**（`server/db.ts` 的 `MIGRATIONS` 数组）。**不许改或删已经发布过的那几条** —— 用户的库是按顺序跑过来的。
- **迁移串里不许出现** `BEGIN` / `COMMIT` / `ROLLBACK` / `PRAGMA foreign_keys`（外层已经包了事务；照抄 SQLite 官方"改表"配方会**炸在开库那一步**，服务根本起不来）。
- **每条查询都必须带 `user_id`**（spec §6.1）。按 id 取任何东西都要经过一个 `loadOwned*` 函数，不许有人自己写 `WHERE id = ?`。
- **不是你的 / 不存在 → 回同一句话 + 404**（分开说等于告诉别人哪些 id 是真的）。
- **`stored_name` 这类硬盘上的文件名永远不许出门**（`server/works.ts:155` 那句注释）。
- **路由正则必须锚定整串**（`/^\/api\/works\/(\d+)$/`）—— 不锚定的话 `/api/works/1/file/../../etc` 也能匹配上。
- **GET / DELETE 不读请求体**（读它只会挂住等一个永远不会来的流）。
- **顺序同现有接口：先认人，再读体。** 没登录的人不该有资格让服务器缓冲 12 MB。
- **依赖形状**：`handle*` 收的是 `{ db, storage, now }`，而 `AppDeps` 的库藏在 `auth` 里 —— 必须写成 `{ db: deps.auth.db, storage: deps.storage, now: deps.auth.now }`，整个 `deps` 传下去编译器当场会拦。
- **不许静默**：任何被吞掉的异常都要 `console.error` 一声（盘满、权限、将来 storage 层的 bug，没有第二个地方会说话）。
- **用户看得见的文案**：中文、完整短语、不写产品做不到的事（`docs/文案规范.md`）。
- **测试是按类名 / 文案找元素的**（`App.test.tsx` 里 158 处）—— **改结构前先 grep 一遍测试，别删老类名**。

```ts
import { HttpError } from './http.ts'

/**
 * 把 `data:image/jpeg;base64,…` 解成字节 + 扩展名。
 *
 * ⚠️ 这个仓库里**第一次**有人真的去解一个 data URL —— 三个 AI 接口只校验前缀就把整串
 * 转给上游了。所以这里的每一个边界都得自己守：只收 jpeg / png（导出就这两种），
 * 正则直接把"带别的东西的串"挡在外面，`Buffer.from(…, 'base64')` 对垃圾输入**不抛**
 * （`server/password.ts:66` 记过这一条），所以**不能靠 try/catch 兜底**，
 * 只能靠前面的正则先把形状卡死。
 *
 * ⚠️ 2026-10-01 从 `works.ts` 搬到这里 —— 会话那边要用一模一样的一套。
 * 搬的时候**一个字没改**：两边各写一份的话，哪天补了第三种图片格式，
 * 只改一边就是"作品能存、会话存不进"这种半截坏。
 */
export function decodeDataUrl(s: string): { bytes: Uint8Array; ext: string } {
  const m = /^data:image\/(jpeg|png);base64,([A-Za-z0-9+/]+={0,2})$/.exec(s)
  if (!m) throw new HttpError('BAD_REQUEST', '图得是 data:image/jpeg 或 data:image/png 的 base64', 400)
  return {
    bytes: new Uint8Array(Buffer.from(m[2]!, 'base64')),
    ext: m[1] === 'png' ? '.png' : '.jpg',
  }
}

const MIME: Record<string, string> = { '.jpg': 'image/jpeg', '.png': 'image/png' }

/** 从文件名尾巴推 MIME。认不出来就按 jpeg —— 存进去的只可能是这两种 */
export function mimeOf(name: string): string {
  return MIME[name.slice(name.lastIndexOf('.'))] ?? 'image/jpeg'
}
```

```ts
import type { Adjustments } from './adjustments.ts'

/**
 * 会话的**元数据** —— 和 `WorkMeta` 同一条规矩：列表接口一次给全部，
 * 所以它要**小**，别往里加会变大的东西（比如消息、步骤）。
 */
export type SessionMeta = {
  id: number
  /** 用户起的名字。**空 = 还没起名**，显示时按 §6.3 退回原图名 */
  title: string | null
  /**
   * 用户那张照片**上传时的名字**（`古镇.jpg`）。空 = 建会话时没给。
   *
   * ⚠️ 它和硬盘上的 `original`（storage 给的不透明名字）**不是一回事**，
   * 那个永远不许出门。这一个可以出门 —— 它是用户自己的文件名。
   */
  originalName: string | null
  createdAt: number
  updatedAt: number
  hasThumb: boolean
  /** 有几步。列表上显示「3 步」比显示时间有用 */
  stepCount: number
}

export type SessionMessage = {
  id: number        // ⚠️ 助手那条的 id **同时就是**它那一步的 SessionStep.id
  role: 'user' | 'assistant'
  text: string
  at: number
}
// ⚠️ 2026-10-01 终审：这里原来还有一个 `stepId?: number`（注释写着「回到这一步靠它」）
// —— 它**从来没被赋过值**（客户端从没送过），真正对号的是"消息 id 就是步骤 id"。
// 字段已从代码里删掉，别再往回加。

/**
 * 一步。⚠️ **这里没有文件名** —— 文件名是硬盘上的东西，永远不许出门
 * （`works.ts` 那句"只给该给的"是同一条规矩）。客户端要图就去
 * `/api/sessions/:id/file/step/:stepId` 取，服务端自己知道那一步是哪张。
 *
 * `reusesPrev` = 这一步和上一步**用的是同一张图**（拖滑块那种）。
 * 客户端靠它省一次下载 + 一次解码。
 */
export type SessionStep = {
  id: number
  label: string
  params: Adjustments
  prompt?: string
  at: number
  reusesPrev: boolean
}

export type SessionDetail = SessionMeta & {
  messages: SessionMessage[]
  steps: SessionStep[]
}

/**
 * 这条会话在界面上叫什么（spec §6.3，**这个口径只有这一份**）。
 *
 * 三级退：用户起的名字 → 照片上传时的名字（去扩展名）→ 「还没说话」。
 *
 * ⚠️ 第二级**不是可有可无的**：刚上传、还一个字没说、只是拖了几下滑块 ——
 * 这是很常见的一趟，而这一趟恰恰是最需要认得出的（「古镇」「海边」一眼分得开，
 * 「3 号会话」分不开）。
 * ⚠️ 第三级也不该被当成错误：那是"这条会话确实什么都还没有"的状态，
 * 而不是一句占位文案。
 */
export function sessionTitle(
  s: Pick<SessionMeta, 'title' | 'originalName'>,
): string {
  const t = s.title?.trim()
  if (t) return t
  // 去扩展名：和 `works.ts` 的 `buildFilename` 用同一条正则
  const n = s.originalName?.trim().replace(/\.[^.]+$/, '')
  return n || '还没说话'
}
```

```ts
import type { Storage } from './storage.ts'

import { HttpError, asObject, str } from './http.ts'
import { decodeDataUrl, mimeOf } from './imagedata.ts'
import { ZERO, applyDeltas, type Adjustments } from '../shared/adjustments.ts'
import type { SessionDetail, SessionMessage, SessionMeta, SessionStep } from '../shared/sessions.ts'

export type SessionsDeps = { db: Db; storage: Storage; now?: () => number }
const nowMs = (deps: SessionsDeps): number => (deps.now ?? Date.now)()

/** 单张图的上限，和作品那边同一个数（前端导出的都是 2048 长边、1 MB 上下） */
const MAX_IMAGE_BYTES = 8 * 1024 * 1024
/** 一条会话最多几句话、几步。防的是"有人存一万条" */
const MAX_MESSAGES = 200
const MAX_STEPS = 100
const MAX_TEXT_LEN = 2000
const MAX_PROMPT_LEN = 2000
/** 标题最长多少。60 和作品别名同一个数，列表上肩并肩看着才齐 */
const MAX_TITLE = 60
/** 原图名的上限。比 `MAX_TITLE` 松 —— 手机相册里的名字能挺长，别把人家截了 */
const MAX_ORIGINAL_NAME = 120

/** 库里那一行的原样。`files` 是 JSON 数组，别的地方只该通过 parseFiles 用它 */
export type SessionRow = {
  id: number; user_id: number; created_at: number; updated_at: number
  title: string | null; original: string; original_name: string | null
  base: string; thumb: string | null
  messages: string; steps: string; files: string
}

/** 服务端自己记的一步 —— 比出门给前端的那个多一样：**这一步用的是哪张图** */
type StoredStep = { id: number; label: string; params: Adjustments; prompt?: string; at: number; image: string }

/**
 * 取一条**属于这个人的**会话。
 *
 * ★ 和 `loadOwned` 同一条规矩：所有按 id 取会话的路径都必须经过它，
 * 不许有人自己写 `WHERE id = ?`。不是他的和不存在，回**同一句话**。
 */
export function loadOwnedSession(id: number, user: PublicUser, deps: SessionsDeps): SessionRow {
  const row = deps.db.raw.prepare(
    'SELECT * FROM sessions WHERE id = ? AND user_id = ?',
  ).get(id, user.id) as SessionRow | undefined
  if (!row) throw new HttpError('BAD_REQUEST', '没有这条会话', 404)
  return row
}

const parseFiles = (row: SessionRow): string[] => JSON.parse(row.files) as string[]

/**
 * 文件名必须**在这条会话自己产出的名单里**。
 *
 * ⚠️ 说清楚它的位置，免得下一个读的人当成死代码删掉：`handleUpdateSession` 里
 * 那次调用**今天到不了**（`mergeSteps` 只从 `{原图, 新文件, 库里那一步}` 里取值，
 * 三个来源都已经在名单里）。它真正的用处是另外两处，那两处都**到得了**：
 *   · `handleSessionStepFile` —— 名字是从库里那一列读出来的，而"库里只可能存
 *     合法的名字"是个**假设**，守卫不该建立在假设上；
 *   · 将来任何一条往 `steps` 里放**外部来源**名字的路径。
 * 一句话：这是**纵深防御**，不是装饰。注释写清楚，别让它被当成"没人调"删掉。
 */
function requireOwnFile(name: string, own: readonly string[]): string {
  if (!own.includes(name)) throw new HttpError('BAD_REQUEST', '这一步的图不属于这条会话', 400)
  return name
}
```

```ts
export async function handleCreateSession(
  body: unknown, user: PublicUser, deps: SessionsDeps,
): Promise<{ id: number }> {
  const o = asObject(body)
  const image = decodeDataUrl(str(o.image))
  if (image.bytes.byteLength === 0) throw new HttpError('BAD_REQUEST', '图是空的', 400)
  if (image.bytes.byteLength > MAX_IMAGE_BYTES) {
    throw new HttpError('BAD_REQUEST', '这张图太大了，存不下', 413)
  }
  // 原图名可选（spec §6.3）。空串当没给 —— 存空串的话列表上会得到一句空标题，
  // 而不是"退回上一级"。
  const name = str(o.name).trim().slice(0, MAX_ORIGINAL_NAME) || null

  // 缩略图可选，坏姿势有两种（解不出来 / 存不下去），都只该让"这条没有缩略图"，
  // 不该让整条会话建不起来 —— 和 handleCreateWork 那条 catch 一字不差的理由。
  const thumbRaw = str(o.thumb)
  const original = await deps.storage.save(image.bytes, image.ext)
  let thumb: string | null = null
  if (thumbRaw) {
    try {
      const t = decodeDataUrl(thumbRaw)
      thumb = await deps.storage.save(t.bytes, t.ext)
    } catch (e) {
      console.error('会话缩略图用不了（解不开或者存不下）：', e)
    }
  }

  const t = nowMs(deps)
  try {
    const r = deps.db.raw.prepare(
      `INSERT INTO sessions (user_id, created_at, updated_at, title, original, original_name, base, thumb, messages, steps, files)
       VALUES (?, ?, ?, NULL, ?, ?, ?, ?, '[]', '[]', ?)`,
    ).run(user.id, t, t, original, name, original, thumb, JSON.stringify([original]))
    return { id: Number(r.lastInsertRowid) }
  } catch (e) {
    // 插不进库就把刚写的文件收回来 —— 不收的话盘上留下两个**没人知道是什么**的文件
    await deps.storage.remove(original).catch(() => {})
    if (thumb) await deps.storage.remove(thumb).catch(() => {})
    throw e
  }
}
```

```ts
/**
 * 服务端**自己**给每一步分配图片文件。
 *
 * ⚠️ 为什么不让客户端送文件名：那是一条能引用别人图的洞（见 `requireOwnFile`）。
 * 规则三条，写清楚免得下一个读的人猜：
 *   ① **第一个步骤永远是原图**；
 *   ② 库里**已有**的那几步：整个对象一律沿用库里的（历史不许被客户端改写）；
 *   ③ 新步骤默认接着上一步那张图 —— **只有"最后一个新步骤"拿这次上传的新文件**
 *      （一次 PUT 最多带来一个新文件：客户端是"改一步就存一次"）。
 */
function mergeSteps(
  prev: readonly StoredStep[], incoming: readonly unknown[],
  newFile: string | null, original: string, at: number,
): StoredStep[] {
  const byId = new Map(prev.map((s) => [s.id, s]))
  const out: StoredStep[] = []
  for (const raw of incoming) {
    const o = asObject(raw)
    const id = Number(o.id)
    if (!Number.isInteger(id) || id <= 0) throw new HttpError('BAD_REQUEST', '步骤 id 得是正整数', 400)
    const old = byId.get(id)
    if (old) { out.push(old); continue }
    out.push({
      id,
      label: str(o.label).trim().slice(0, MAX_TITLE) || '调色',
      params: applyDeltas(ZERO, asObject(o.params) as Partial<Adjustments>),
      prompt: str(o.prompt).slice(0, MAX_PROMPT_LEN) || undefined,
      at: Number(o.at) || at,
      image: '',                       // 下面两步统一补
    })
  }
  // ③：新步骤里**最后那一个**拿新文件
  if (newFile) {
    for (let i = out.length - 1; i >= 0; i--) {
      if (out[i]!.image === '') { out[i]!.image = newFile; break }
    }
  }
  // ①③：空的接着上一步；第一个是原图
  for (let i = 0; i < out.length; i++) {
    if (out[i]!.image) continue
    out[i]!.image = i === 0 ? original : out[i - 1]!.image
  }
  return out
}
```

```ts
function readMessages(raw: unknown): SessionMessage[] {
  if (!Array.isArray(raw)) return []
  return raw.slice(-MAX_MESSAGES).flatMap((m) => {
    const o = asObject(m)
    const role = o.role === 'user' || o.role === 'assistant' ? o.role : null
    const text = str(o.text).slice(0, MAX_TEXT_LEN)
    if (!role || !text) return []
    const id = Number(o.id)
    // ⚠️ 2026-10-01 终审：这里原来还抄着一份 `stepId` 的透传 —— 客户端从没送过它，
    //    「回到这一步」靠的是"消息 id 就是步骤 id"（见 `shared/sessions.ts`）。已删。
    return [{
      id: Number.isInteger(id) && id > 0 ? id : 0,
      role, text, at: Number(o.at) || 0,
    }]
  })

/**
 * ⚠️ `updated_at` 在这里**不只是"上次改的时间"，它同时是缩略图 URL 的版本号**
 * —— 和 `handleReplaceWork` 上面那段是同一条规矩。忘了 bump 不会报错、
 * 不会 4xx：用户只是**静默地**一直看到缓存里那张旧缩略图。
 */
export async function handleUpdateSession(
  id: number, body: unknown, user: PublicUser, deps: SessionsDeps,
): Promise<SessionMeta> {
  const row = loadOwnedSession(id, user, deps)
  const o = asObject(body)
  const own = parseFiles(row)
  const prevSteps = JSON.parse(row.steps) as StoredStep[]

  // ── 新图（可选）───────────────────────────────────────────────────
  let newFile: string | null = null
  const baseRaw = str(o.base)
  if (baseRaw) {
    const image = decodeDataUrl(baseRaw)
    if (image.bytes.byteLength === 0) throw new HttpError('BAD_REQUEST', '图是空的', 400)
    if (image.bytes.byteLength > MAX_IMAGE_BYTES) {
      throw new HttpError('BAD_REQUEST', '这张图太大了，存不下', 413)
    }
    newFile = await deps.storage.save(image.bytes, image.ext)
  }
  let newThumb: string | null = null
  const thumbRaw = str(o.thumb)
  if (thumbRaw) {
    try {
      const t = decodeDataUrl(thumbRaw)
      newThumb = await deps.storage.save(t.bytes, t.ext)
    } catch (e) {
      console.error('会话缩略图用不了（解不开或者存不下）：', e)
    }
  }

  const t = nowMs(deps)
  const steps = Array.isArray(o.steps)
    ? mergeSteps(prevSteps, o.steps.slice(-MAX_STEPS), newFile, row.original, t)
    : prevSteps
  // 名单：原来的 + 这次新写的。每一步引用的文件都必须在名单里
  const files = [...own, ...(newFile ? [newFile] : [])]
  for (const s of steps) requireOwnFile(s.image, files)

  // ★ 「现在这一版参数」落在**最后一步**上。`SessionPatch.params` 那段注释讲了为什么
  //   它必须单独走一个字段（客户端里 `params` 和 `history` 是两回事，拖滑块不动 history）。
  //
  //   两条刻意的窄：① **只动最后一步**，前面几步一个字节不碰 —— 客户端不能改写历史
  //   （`mergeSteps` 规则 ②）这条规矩不能因为参数就被撬开一个口子；
  //   ② **换一个对象，别原地改** —— `mergeSteps` 里 `out.push(old)` 推的是库里那条的
  //   **同一个引用**，原地改会顺手动到 `prevSteps`。今天 `prevSteps` 是当场
  //   `JSON.parse` 出来的、动它没事，但那是"今天没事"，不是"不会出事"。
  if (o.params !== undefined && steps.length > 0) {
    const last = steps[steps.length - 1]!
    steps[steps.length - 1] = {
      ...last,
      params: applyDeltas(ZERO, asObject(o.params) as Partial<Adjustments>),
    }
  }

  const title = o.title === null || o.title === undefined
    ? row.title
    : (str(o.title).trim().slice(0, MAX_TITLE) || null)
  const messages = o.messages === undefined ? row.messages : JSON.stringify(readMessages(o.messages))

  try {
    deps.db.raw.prepare(
      `UPDATE sessions SET updated_at = ?, title = ?, base = ?, thumb = COALESCE(?, thumb),
         messages = ?, steps = ?, files = ? WHERE id = ? AND user_id = ?`,
    ).run(t, title, newFile ?? row.base, newThumb, messages,
      JSON.stringify(steps), JSON.stringify(files), id, user.id)
  } catch (e) {
    // 记录没改成功 → 把**新写的**收回来，旧的一动没动
    if (newFile) await deps.storage.remove(newFile).catch(() => {})
    if (newThumb) await deps.storage.remove(newThumb).catch(() => {})
    throw e
  }
  // 换了缩略图才删旧的（旧的 base **不能删** —— 它可能还被某一步引用着）
  if (newThumb && row.thumb) {
    await deps.storage.remove(row.thumb).catch((e) => console.error('旧缩略图没删掉：', e))
  }

  const next = { ...row, updated_at: t, title, base: newFile ?? row.base,
    thumb: newThumb ?? row.thumb, messages, steps: JSON.stringify(steps), files: JSON.stringify(files) }
  return toMeta(next)
}

/**

 * 指向不存在文件的记录 —— 那条记录永远打不开、也删不掉第二次。
 * 文件删失败不让请求失败（对用户来说这件事**就是成功了**），但要记一笔日志。

export async function handleDeleteSession(

  }
  return { ok: true }
}

export async function handleSessionStepFile(

  if (!s) throw new HttpError('BAD_REQUEST', '没有这一步', 404)

  requireOwnFile(s.image, parseFiles(row))
  return { bytes: await deps.storage.read(s.image), contentType: mimeOf(s.image) }
}
```

```ts
 * 这一趟修图挂在服务端哪条会话上。null = 还没建起来（正在建、或者建失败了）。
 *
 * ⚠️⚠️ **必须是 state，不能是 ref。** 这一条是 2026-10-01 实测出来的坑：
 *   建会话是**不 await** 的（见下），所以上传之后有一段时间 `sessionId` 还是 null。
 *   而那个落盘副作用的第一句就是"没有会话就 return"。
 *
 *   用 ref 的话：用户上传完**立刻拖一下滑块**（那是这个产品最自然的第一个动作 ——
 *   落地页写的就是"拖滑块不用登录"），副作用跑起来看到 null，**直接 return**；
 *   等建会话终于回来、把 id 写进 ref，**ref 的变化不触发重渲染**，于是副作用
 *   再也不会为那一次改动跑一遍 —— **那一版改动永远不会落盘，而且不报错。**
 *   等用户刷新才发现，而那时候他已经说不清丢了什么了。
 *
 *   换成 state 之后，id 一到就重渲染、副作用自己再跑一遍 —— 竞态没了，
 *   而且比 ref 少一个概念（一个真值来源，不是两个）。

const [sessionId, setSessionId] = useState<number | null>(null)
/** 落盘的次序号。后一次回来时前一次可能还在路上 —— 只认最新的那一次 */
const persistSeqRef = useRef(0)
```

```ts
/**
 * 位图 → data URL。**送给服务端的图走这条路**（建会话要原图的字节）。
 *
 * 用 **JPEG 0.92**：这是"存下来接着改"的那一份，不是缩略图，画质要够 ——
 * 但也不是最终导出（那一步在 `buildExportBlob`，走的是 blob 不是 data URL）。
 * ⚠️ `quality` 是可以被调用方改的：**落盘那趟传 0.9**（底图会反复重传，
 * 让一点画质换体量）；建会话那趟不传 = 0.92。
 *
 * ⚠️ **编码前先 `fitWithin(..., MAX_DIMENSION)`**（下面那条 2026-10-01 评审更正
 * 就是讲这个的）：画布本身**不按 `MAX_DIMENSION` 缩**（它按图的大小开），
 * 不在这儿压的话 ≥24MP 的照片**整张**上路 → 服务端 413。
 *
 * ⚠️ 别用 `makeThumbnail` 代替：那个是 **0.7**，而且会**缩到 480**。
 * 拿它当原图传上去，用户回头再打开这张会话，底图是糊的 —— 而且不报错。
 */
export function bitmapToDataUrl(source: Sizable, quality = 0.92): string {
  // 只缩不放（`fitWithin` 自己保证）—— 比上限小的图原样过去
  const { width, height } = fitWithin(source.width, source.height, MAX_DIMENSION)
  const canvas = document.createElement('canvas')
  canvas.width = Math.max(1, width)
  canvas.height = Math.max(1, height)
  const ctx = canvas.getContext('2d', { colorSpace: 'srgb' })
  if (!ctx) throw new Error('拿不到 2D 上下文，做不了 data URL')
  // 缩图是**用户那张照片的一次画质损失**，平滑档给最好的
  // （和 `resize.ts` 那条同款理由：默认档缩出来的边缘有锯齿）
  ctx.imageSmoothingQuality = 'high'
  ctx.drawImage(source, 0, 0, canvas.width, canvas.height)
  return canvas.toDataURL('image/jpeg', quality)
}
```

`MAX_DIMENSION`（`shared/size.ts`）管的是**送给模型的载荷**；画布按图的大小开、
只按设备探到的 WebGL 上限缩过（桌面上能到 16384）。所以**要自己压**：

- [ ] **Step 5: 写 `SessionsPage.tsx`**

照 `GalleryPage.tsx` 的形状（`null` = 还没拿到，**和"没有"是两件事**）。
⚠️ 分页那一段**照 GalleryPage 抄**，包括 `visibleGroups` 和那个 IntersectionObserver
的哨兵 —— `groupByDay(...).slice(0, limit)` 切的是**天**不是**条**，而且 `setLimit`
没人调就是一段死状态（`tsconfig` 是 `noUnusedLocals: true`，`tsc` 当场会红）。

```tsx
import { useEffect, useMemo, useRef, useState } from 'react'
import { listSessions, deleteSession, sessionThumbUrl } from '../api/sessions'
import { groupByDay } from '../../shared/works.ts'
import { visibleGroups } from '../core/gallery'
import { sessionTitle, type SessionMeta } from '../../shared/sessions.ts'

/** 一次摆多少条。和作品页同一个数（§3.5） */
const PAGE = 60

export function SessionsPage({ onOpen, onNew }: {
  onOpen: (id: number) => void
  onNew: () => void
}) {
  /** null = 还没拿到。**它和"一条都没有"是两件事** —— 混在一起的话，
   *  还没加载完的那一瞬间会显示"还没改过照片"，用户会以为东西没了。 */
  const [rows, setRows] = useState<SessionMeta[] | null>(null)
  const [failed, setFailed] = useState<string | null>(null)
  const [limit, setLimit] = useState(PAGE)
  /** 正在问"这条要删掉吗"的是哪一条。**就地确认，不弹系统框**（这个产品的规矩） */
  const [confirming, setConfirming] = useState<number | null>(null)
  /** 「现在」只取一次：显示名要判断"是不是今年"，一次会话里不会跨年 */
  const now = useMemo(() => Date.now(), [])

  useEffect(() => {
    let alive = true
    listSessions().then(
      (rs) => { if (alive) setRows(rs) },
      (e) => { if (alive) setFailed(e instanceof Error ? e.message : '打不开对话列表') },
    )
    return () => { alive = false }
  }, [])

  // ⚠️ 分组和分页**复用作品页那一套**（`groupByDay` + `visibleGroups`，Step 4 刚放宽的）——
  //    别复制一份：复制的那份迟早和作品页漂开，同一天在两页里显示成两个名字。
  const groups = useMemo(() => (rows ? groupByDay(rows, now) : []), [rows, now])
  const shown = useMemo(() => visibleGroups(groups, limit), [groups, limit])
  const more = shown.length < groups.length

  /** 滚到底就把下 60 条接上。和作品页那个哨兵一模一样。 */
  const sentinel = useRef<HTMLDivElement | null>(null)
  useEffect(() => {
    const el = sentinel.current
    if (!el) return
    const io = new IntersectionObserver((es) => {
      if (es.some(e => e.isIntersecting)) setLimit(n => n + PAGE)
    })
    io.observe(el)
    return () => io.disconnect()
  }, [more])

  async function doDelete(id: number) {
    setConfirming(null)
    try {
      await deleteSession(id)
      setRows((rs) => rs?.filter((r) => r.id !== id) ?? null)
    } catch (e) {
      setFailed(e instanceof Error ? e.message : '没删掉，再试一次？')
    }
  }

  if (failed) return <p className="gallery-error">{failed}</p>
  // ★ 还没拿到（null）和拿到了但是没有（[]）**要分开说**
  if (rows === null) return <p className="gallery-loading">正在取…</p>
  if (rows.length === 0) {
    return (
      <div className="sessions-empty">
        {/* 空态那两句话的分工照作品页：主句说现状，下面那句说"那怎么办"（§3.7） */}
        <p className="sessions-empty-title">还没改过照片。</p>
        <button className="btn-primary" onClick={onNew}>去改一张</button>
      </div>
    )
  }
  return (
    <section className="sessions">
      {shown.map(g => (
        <div key={g.day} className="sessions-day">
          <h2 className="gallery-day-title">{g.label} · {g.works.length} 条</h2>
          {g.works.map(s => (
            <div key={s.id} className="session-row">
              <button className="session-open" onClick={() => onOpen(s.id)}>
                {/* `alt` 给名字：图上没字，读屏软件只能靠它 */}
                <img className="session-thumb" src={sessionThumbUrl(s.id, s.updatedAt)}
                     alt={sessionTitle(s)} loading="lazy" />
                <span className="session-name">{sessionTitle(s)}</span>
                <span className="session-steps">{s.stepCount} 步</span>
              </button>
              {confirming === s.id ? (
                <>
                  <span className="session-ask">删掉这条？</span>
                  <button className="session-del" onClick={() => void doDelete(s.id)}>删掉</button>
                  <button className="session-del" onClick={() => setConfirming(null)}>取消</button>
                </>
              ) : (
                <button className="session-del" onClick={() => setConfirming(s.id)}>删除</button>
              )}
            </div>
          ))}
        </div>
      ))}

      {/* ⚠️ 那个圈**必须转**：没有它，用户会以为到底了（§3.5） */}
      {more && <div ref={sentinel} className="sessions-more">正在取…</div>}
      {!more && groups.length > 0 && <p className="sessions-end">没有更多了</p>}
    </section>
  )
}
```

⚠️ **`sessionTitle` 不在这个文件里** —— 它已经在 Task 1 的 `shared/sessions.ts` 里写好了
（三级退：用户起的名字 → 原图名去扩展名 →「还没说话」），这里只是 import。

- [ ] **Step 6b: ⭐ 把 Task 5 的恢复抽成 `loadSession(id)` —— 列表点开某一条要走它**

⚠️ **这一条原计划里漏了，而且是承重的**：Step 5 那个 `SessionsPage` 的 props 是
`onOpen: (id: number) => void`，可**整份计划从没说过 `App.tsx` 里 `onOpen` 干什么**。
而"点开一条旧会话"是这个列表**存在的全部意义**。

**改法**：Task 5 那个恢复 effect 里**干活的那一段**（`getSession` → 解码每一步 → 重建
`originalFileRef` → 写状态）抽成一个 `loadSession(id: number)`，挂载时调
`loadSession(最新的那条)`，列表点开时调 `loadSession(点的那条)`。
effect 只剩"取列表、拿第一条、调它"。

⚠️ **抽的时候这四件事一件都不能丢** —— 它们全是 Task 5 评审一轮一轮抠出来的，
搬漏任何一条都会**静默出错**：

1. ⚠️⚠️ **`idRef.current = Math.max(...)`**（跳过接回来的最大 id）。
   丢了它：用户在新打开的那条会话里说的第一句话会和老 id 撞号 →
   `mergeSteps` 把**刚花钱生成的那一步整个吃掉**，而且「回到这一步」跳旧图。
   **这是真金白银的那一条。**
2. **`lastPersistedBaseSeqRef.current = baseSeqRef.current`**。
   丢了它：整张底图被重传一遍，服务端多存一份。
3. **`pickStartedRef`**（那个"用户已经先动手了"的闸门）。
   丢了它：用户在解码窗口里先传了照片，屏幕上会写「这是上次没做完的那张」——
   **对着他自己刚传的那张说**。
4. **`if (!alive)` 与 `releaseDecoded()`**。丢了它：切会话时把上一张的位图漏在内存里。

⚠️ **另有一条这条新路独有的**：切到另一条会话时，**当前这条的位图要关掉**
（`bitmapsToClose(history, [])` 那一路）。切五次会话不关，标签页就垮。

⚠️ **`loadSession` 一定要在同一个批次里写完所有状态**（`setHistory` / `setMessages` /
`setParams` / `setSessionId` …），别中间 `await`。中途让出的话，落盘那个 effect 会带着
**旧 history + 新 sessionId** 跑一次 —— 那等于**把 A 的活儿写进 B**。
实现时用一条测试钉住它：在 A 里改点东西，切到 B，断言发出去的 PUT **打的是 B 的 id、
而且 body 里没有 A 的那句话**。

- [ ] **Step 7: 顶栏那个「新的一张」**

设计文档 §6.4：**上传一张新照片 = 自动开一条新会话**（Task 4 的 Step 3 管着），
但顶栏还要给一个**明确**的入口，免得用户不知道自己现在在哪条会话里。

在修图页顶栏（`调色 / 下载 / 保存` 那一排）加一个「新的一张」，**只在有图时显示**：

```tsx
{/* 「新的一张」= 回到上传前那一屏去选下一张。
    ⚠️ **它不删当前这条会话** —— 那条已经在服务端存着了，左栏「对话」里还找得到。
    表现上要和"保存"区分开：保存是"把这张存进作品"，新的一张是"我再改一张"。 */}
{image && <button onClick={startNew}>新的一张</button>}
```

`startNew` = 把 `image` / `history` / `messages` / `cards` / `params` / `savedId`
和 `sessionId` 全部归零（`setSessionId(null)`），回到 `Uploader` 那一屏。⚠️ **归零前要把
`history` 里那些位图 `close()` 掉**（`onPick` 里那段 `bitmapsToClose` 是同一个道理）——
不关就是换几次照片把标签页拖垮。
