# 相机桥跨设备访问设计 —— 2026-10-19

## 目标

让 iPhone / iPad 在同一 Wi-Fi 下连接电脑上运行的相机桥，导入 tether 软件刚落盘的照片，
并在支持 gphoto2 的机型上继续使用实时取景、快门和参数控制。

本机访问保持零配置；跨设备访问必须显式开启并带访问令牌。

## 启动方式

- 本机：`npm run camera:bridge -- --dir <目录>`，仍监听 `127.0.0.1`，不需要令牌。
- 跨设备：`npm run camera:bridge -- --host 0.0.0.0 --dir <目录>`。
  - 未显式传 `--token` 时自动生成 18 字节随机令牌（base64url），打印在终端。
  - 也支持 `CAMERA_BRIDGE_HOST` / `CAMERA_BRIDGE_TOKEN` 环境变量。
  - 显式令牌少于 8 个字符时拒绝启动。
- 终端打印所有非内网 IPv4 地址，手机用 `http://<电脑IP>:8788` 连接。

## 鉴权

- 服务端 `token` 非空时，除 `OPTIONS` 外所有接口都要求令牌：
  - 请求头 `x-pinkrose-bridge-token`；
  - 或查询参数 `?token=...`（给 `<img src>` / 文件下载用）。
- 令牌比较先做 SHA-256，再 `timingSafeEqual`，不比较明文长度或前缀。
- 跨设备模式回显请求 `Origin` 以支持局域网网页；真正边界是令牌，不能只靠 CORS。
- 快门 / 参数写接口仍保留 `x-pinkrose-camera: 1` 标记。
- 照片目录仍只读，路径逃逸检查不变。

## 网页端

- 「相机桥」增加「访问令牌」输入框；本机可留空。
- 令牌保存在当前浏览器的 `localStorage`，下次连接自动带上。
- 填好令牌后可点「复制配对链接」：把地址和令牌放进 URL hash（不发给服务器），
  在 iPad / iPhone 打开后点「相机桥」会自动填好并连接，读完立即清掉 hash。
  电脑用 localhost 打开时，链接会把主机名换成桥的局域网地址，端口沿用网页端口。
  链接本身包含令牌，只通过可信渠道发给自己的设备。
- API 请求同时带请求头和查询令牌；缩略图、实时取景、转换图、文件下载走查询令牌。
- 390px 窄屏保留「实时相机」和「相机桥」两个入口；单独的「拍照」让位给系统文件选择器。
- 令牌错误时直接说「访问令牌不对」，并指向电脑终端里的那串令牌。

## 验收

- `server/cameraBridge.test.ts`：无令牌 / 错令牌 401，请求头与查询令牌都能放行，
  局域网 Origin 的 CORS 正确。
- `src/ui/CameraBridge.test.tsx`：令牌进入健康检查、照片轮询和图片 URL，并写入本地存储。
- `src/app/cameraPairing.test.ts`：地址归一化、localhost → 局域网主机名、特殊字符
  令牌往返、坏 hash 拒绝、读完清 hash。
- WebKit 390px 真实链路：网页从局域网地址打开，桥以 `--host 0.0.0.0` 启动；
  错误令牌给出可操作提示，正确令牌连接成功，实时取景可见，快门新增照片，导入后进入编辑器，
  页面无横向溢出。
