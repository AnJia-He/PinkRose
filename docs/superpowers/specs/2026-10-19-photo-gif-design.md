# 照片动图（GIF）设计 —— 2026-10-19

## 0. 背景与结论

市场常见的「照片动图 / 照片视频」在 Web 端有两个问题：

- Safari 的部分 WebKit 环境没有 `MediaRecorder` / `canvas.captureStream`，不能把
  MediaRecorder 当唯一实现；
- 服务端 ffmpeg 不是所有部署都有，也不该为了一个轻量分享功能新增上传链路。

所以先做**纯前端 GIF**：2–12 张照片，按顺序播放，循环导出。它不替代专业视频，
但覆盖聊天、表情包、轻量朋友圈分享，且苹果端、桌面端行为一致。

## 1. 编码

- `gif/gif.ts` 纯前端实现 GIF89a：
  - 所有帧共用 256 色全局调色板；
  - 调色板用中位切分（比固定色立方更能保留肤色和渐变）；
  - 每帧索引化后用 LZW 压缩；词典满 4096 时写 clear 并重置；
  - 写入 Netscape 循环扩展（可选）。
- 注意 LZW 编码器和解码器的词典进度差一步：码长必须在
  `next === (1 << codeSize) + 1` 时升，不能在相等时升，否则后续位流错位。
  这一条由测试里的最小解码器钉住。

## 2. 界面

- 入口在作品页头「照片动图」，和打印 / 拼图 / 批量处理互斥；
- 选 2–12 张，按顺序显示序号；
- 画幅：1:1 / 4:5 / 3:4 / 9:16 / 16:9；
- 宽：480 / 720 / 1080；停留：0.4 / 0.8 / 1.2 / 2 秒；
- 填满裁切 / 完整留白，留白可选底色；可关循环；
- 生成后直接在页面里播放 GIF 预览，下载文件名
  `PinkRose-motion-YYYYMMDD-HHmm.gif`。

## 3. 边界

- GIF 只有 256 色，照片会有轻微色带；文案里明确说清，不假装是视频。
- 不做音频、转场、逐帧编辑；这些留给后续真正的视频链路。
- 不改小程序。

## 4. 验证

- `gif/gif.test.ts`：GIF89a 头、循环块、帧数、LZW 子块、最小解码器还原，
  包含词典填满后的 clear。
- `ui/GifPanel.test.tsx`：至少两张才能生成、默认参数、留白底色、下载。
- 真 Chromium：生成 720×720 两帧 GIF，`ffprobe` 读到 2 帧且
  `ffmpeg -v error` 无解码错误。
- iPhone WebKit 390×844：1.75 秒生成 720×720 GIF，预览宽 362px，
  页面无横向溢出，登录后控制台无错误。
