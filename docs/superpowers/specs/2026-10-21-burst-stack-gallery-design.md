# 图库连拍堆栈设计

## 目标

作品页经常被同一段连拍淹没。连拍堆栈把相邻照片收成一组，减少浏览墙的
重复内容，同时保留单张查看、评分、颜色标签、多选、批量处理、挑最好和删除。

## 判定规则

- 优先使用 `WorkMeta.capturedAt`（EXIF 拍摄时间，保留到秒）；旧作品或程序
  生成成片没有可信拍摄时间时，回退到 `WorkMeta.createdAt`。无论哪条路都不使用
  `updatedAt`，最后编辑一张旧照片不能让它和今天的新照片组成连拍。
- 至少 5 张才折叠；相邻两张间隔不超过 1.5 秒，整组跨度不超过 20 秒。
- 中间断档超过 1.5 秒就另起一组；不足 5 张的余数原样展开。
- 只在“按时间”视图启用。“按大小”仍按单张排序，避免把找大文件这件事变复杂。
- 时间视图可在“最近编辑”和“拍摄时间”之间切换；拍摄时间视图使用同一个
  `capturedAt ?? createdAt` 口径分组、命名、搜索和连拍识别。
- 主保存和批量成片会保存用户原文件名与 EXIF 拍摄时间；服务端只留基础文件名，
  不接受客户端传路径。缺少 EXIF 时仍按保守时间规则回退，不把上传时间伪装成
  拍摄时间。
- 主保存和批量成片同时保存机身与镜头；作品详情显示来源信息，图库搜索可按
  原文件名、机身或镜头查找，也可用器材下拉框只看某台机身或某支镜头。

## 浏览与选择

- 收起态占一个作品格，显示封面、张数、起止时间和“展开看每一张”。
- 封面优先已有最高星级，其次保留标记和最近编辑；它不是“最佳照片”算法。
- 展开后使用原来的作品格，所有单张入口保持不变。
- “多选整组”只预选真实作品 ID，之后仍使用现有批量星级、颜色、相册、
  挑最好、下载和删除链路。
- 选中两张可直达现有全屏左右对比；对比层复用同一套同步拖线和键盘能力。
- “智能复查”对选中作品逐张分析缩略图清晰度和曝光，把结果写成保留 / 复查标记；
  混合建议通过一次批量请求落库，不删除照片，单张失败不拖垮整组。
- “整组挑最好”直接对整组缩略图做本机清晰度 / 曝光分析，进入多选并只保留
  推荐张；推荐句展示原因和本机评分，不声称审美判断。
- 顶部“连拍组”开关可关闭折叠；当前可见页没有连拍组时不显示这个按钮。
- 搜索和筛选先作用于单张作品，再对剩余结果折叠；筛到不足 5 张时自动展开。

## 验证

- `src/core/gallery.test.ts` 覆盖时间规则、EXIF 优先、5 张门槛、断档、
  错误使用编辑时间和组内拍摄顺序。
- `src/App.gallery.test.tsx` 覆盖收起、展开、整组多选、开关和原有作品顺序。
- `npm run check:bursts` 在 WebKit 桌面与 390px 真实创建 5 张作品，
  验证来源元数据写入、拍摄时间分组、收起、展开、整组多选、整组挑最好、
  器材搜索与筛选、详情来源信息、无横向溢出和控制台无错误。

## 边界

这是浏览层的第一个完整连拍实现，不是完整相机序列识别。下一步可结合机身
序列号与原始文件名序列，处理厂商只写整秒时间、同秒多张或跨卡导入的情况。
