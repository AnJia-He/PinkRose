# 自动透视设计 —— 2026-10-21

## 背景

现有透视校正要求用户手动拖四个角。建筑、屏幕和画框照片里最常用的
“一点透视”其实可以本地识别：左右竖边仍然接近竖直，但向上或向下收拢。
补一个自动入口能减少找线和拖角的时间，同时保留手动微调。

## 交互

- 入口在「裁剪 → 透视」第二行，按钮名「自动透视」。
- 识别期间按钮显示「识别中…」并禁用；其他控件仍可见。
- 识别成功只更新四个角，不直接提交；用户检查后按「应用透视」才写像素。
- 识别失败只给一句“没找到明显的左右竖线”，四角保持原样，用户可继续手动拖。
- 自动透视读底图 `ImageBitmap`，不读当前调色 / 滤镜后的画布，避免风格参数影响几何。

## 算法

1. 底图缩到长边 480，计算灰度 Sobel 梯度。
2. 每 3 行取最强的竖直边落点，左右半幅分开；只取局部梯度明显强于水平梯度的像素。
3. 用 RANSAC 拟合 `x = a·y + b`，保留跨度至少 45% 画面高度的线，最多每侧 4 条候选。
4. 左右各取一对线，要求上下宽度都在画面宽度的 22%–96%，且至少变化 1.8%；
   平行线不会触发自动校正。
5. 四个交点按左上、右上、右下、左下归一化，交给现有四角透视提交链。

算法不处理三点透视、鱼眼、弯曲页面和复杂遮挡；识别不到可信线条时返回 `null`，
由用户手动拖角。当前只校正垂直方向的收拢，不自动水平翻转或裁剪内容。

## 验证

- `src/core/autoPerspective.test.ts`：合成梯形通过，平行竖边和无边缘返回 `null`。
- `src/image/autoPerspective.test.ts`：从底图缩样到 480 后进入纯算法。
- `src/ui/PerspectiveControls.test.tsx`：入口、识别中禁用和进度文案。
- `src/App.tools.test.tsx`：成功只改四角不提交；失败保留四角并给可执行提示。
- `npm run check:perspective`：WebKit 1000px / 390px；合成建筑图自动检测并应用，
  普通正脸照不误判，页面无横向溢出、控制台无错误。
