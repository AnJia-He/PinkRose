# 「回到这一步」不再删后面的步骤 —— 设计（2026-10-05）

> **一句话**：点「回到这一步」只移动**"现在站在哪一步"**的位置，不删任何东西；
> 只有**从中间又生成了新东西**的时候，才把后面切掉 —— 而且切之前**问一句**。
>
> 用户原话（2026-10-05）：「用户点击回到这一步后，应该保留更改的那一步，
> 而且用户好像现在没有自己删除对话区任意一条记录的操作吧？」（后半句：对，
> 现在没有单条删除 —— 只有删整条会话；单条删除**单开一轮**，见 §9。）

---

## 1. 现在错在哪（不是"不优雅"，是会丢东西）

点一次「回到这一步」，用户**永久**失去后面所有的步骤：

| 环节 | 现在发生什么 | 锚点 |
| --- | --- | --- |
| 跳转 | `jumpTo` 把列表**截断**到那一步（含），后面的步骤从 history 里消失 | `src/core/history.ts:85` |
| 内存 | 被截掉的步骤位图当场 `close()` | `src/App.tsx:1361-1365` |
| 界面 | 后面那几条回复只剩**光秃秃的文字** —— 小图、两颗按钮全都由 `history` 派生，history 没了它们就没了 | `src/App.tsx:2035-2037` |
| 存盘 | 落盘 effect 把**截断后的** steps 送上去；服务端 `mergeSteps` **只从"这次送来的"里重建列表** —— 少送的 = 删掉 | `src/App.tsx:1458/1524`、`server/sessions.ts:261-298` |
| 刷新 | 再也回不来：steps 已经不在库里，messages 还在 —— 又是那几条光秃秃的文字 | 同上 |

也就是说：**跳转 = 一次静默删除**，而用户从来没有同意过。

## 2. 核心概念：当前位置 `cursorId`

`App.tsx` 新增一个状态：**`cursorId: number | null`** —— 现在站在哪一步
（步骤 id = 那条助手消息的 id，老约定；见 `shared/sessions.ts:29`）。

**不变量**：有照片 ⇒ history 非空 ⇒ `cursorId` 非 null 且指向 history 里真实存在的一步。

赋值点**全表**（少一处就是"你在这里"标错地方 / 切口切错位置，两种都不报错）：

| 时刻 | 值 | 位置 |
| --- | --- | --- |
| 上传建原图那一步 | `welcomeId`（欢迎语那条消息的 id —— 原图一步挂在它身上） | `App.tsx:965-970` |
| 生成成功推入新步 | `messageId`（新那步的 id） | `app/useGeneration.ts` 的 `runGenerate` 成功段 |
| 跳转 | 目标步骤 id | `App.tsx` 的 `onJump` |
| 恢复会话 | 最后一步 id（人站在最新一步） | `App.tsx:772` 那一批 |
| 归零（换照片 / 删会话 / 新的一张） | `null` | `resetEditor`（`App.tsx:1048`） |

⚠️ 必须是 `useState`，不能是 ref —— 理由和 `sessionId` 当初那条一模一样
（`sessions-feature` 记忆里的坑 ②）：「你在这里」是渲染出来的，ref 变了不重渲染。

## 3. 跳转：只动位置，一个字节都不删

`onJump(id)` 的新形状：

```
cancelPick()        // 不变：上一条歧义翻篇
cancelReplace()     // ★ 新：上一条"要切掉后面吗"就此作废（和 cancelPick 同一条规矩）
setCursorId(id)     // ★ 新：移动位置
setImage(target.base)
setParams(target.params)
setLut(target.lut)  // 2026-10-05 滤镜那条，不动
```

**删掉**原来的 `setHistory(jumpTo(...))` 和 `closeBitmaps(...)` 两行。

代价说明白：被跳过的步骤位图**不再提前释放**（它们是"还能再点回去"的本钱）。
上限没变 —— 新推入仍然由 `MAX_SNAPSHOTS = 6` 裁（`history.ts:71`），恢复出来的
本来就可以超过 6（`2026-10-01-sessions.md` Step 3 那条）。跳转不再提前还，
直到切口/裁剪时才还。

## 4. 切口：唯一会动后面的地方

### 4.1 规则

**只要"生成"从一个不是最新的步骤出发**，就：把它之后的步骤 + 那一段对话一起切掉，
再推新步。三个入口全部覆盖：说话/卡片（`applyDecision`）、「再来一版」（`onRerun`）、
点选确认（`confirmMark`）。

### 4.2 一个咽喉 + 两个显式入参

调用链上**只有 `runGenerate` 会推新步**，所以切口放在它里面（沿用这个项目
"单一咽喉"的老规矩）。它多收一个**必填**入参：

```ts
/** 这一版是从哪长出来的 + 切对话时"从哪条消息起保留"（见 4.3）。 */
origin: { stepId: number; keepFromMsg: number }
```

⚠️ **必填、不读 state**：理由和 `paramsAtStep` / `lutAtStep` 一字不差
（`useGeneration.ts:112-117`）——「再来一版」是**先跳转、再在同一个 tick 里**
调进来的，读 `cursorId` 那个 state 拿到的是**跳转前**的值。
每个调用点被编译期逼着表态：

| 调用点 | `stepId` | `keepFromMsg` |
| --- | --- | --- |
| `applyDecision`（send / 卡片） | `cursorId`（deps 进） | 本条指令那条**用户消息的 id**（见 4.3） |
| `onRerun` | `target.id`（显式；不读 state，理由同上） | 确认之后说的那句助手的 id（`mid`） |
| `confirmMark` | `cursorId` | `pending.keepFrom`（从 send 一路带过来的那条用户消息 id） |

切**步骤**：`cutAfter(prev, origin.stepId)` —— 就是现在 `jumpTo` 干的事，
**改名**（`jumpTo` → `cutAfter`，语义从"回到某一步"变成"从某一步继续：切掉它后面的一切"），
行为一字不改（截断含 id）。`history.test.ts:35-53` 的断言原样保留、改个名。

**`useGeneration` 的 deps 要加四样**（这个文件里 deps 漏一条是一个已经踩过的
静默坑，`useGeneration.ts:295-301` 有原话）：
`cursorId`、`tipId`（= `history.at(-1)?.id`，判"要不要问一句"）、
`setCursorId`（推完新步把位置挪过去）、`setPendingReplace`（说话那条路要挂确认条）。
`send` / `onCard` 还要把刚插进去那条用户消息的 id 提出来传给 `applyDecision`
（现在是内联 `nextId()`）。

### 4.3 对话怎么切：**两个 id 的区间**，不是一个

```
if (origin.stepId !== tipId) {   // ⚠️ 站在最新一步上不切 —— 见下面那一段
  setMessages(m => m.filter(x => x.id <= origin.stepId || x.id >= origin.keepFromMsg))
}
```

⚠️ **站在最新一步上不切**（`origin.stepId !== tipId` 才切）：区间里可能躺着**不推步骤**
的消息（失败 / "停了" / 纯参数话），一刀切会把它们收走 —— `App.test.tsx` 的
「接着说话不许撞号」钉着这一条。

⚠️ **为什么不能只写 `x.id > stepId` 一刀切**：用户刚说的那句话、模型刚回的那句
（包括点选那条"我不太确定…"），id **也大于**步骤 id —— 一刀切会把**用户刚打的话**
一起删掉。切掉的是**中间那段**：属于旧未来的消息。

配平（`id` 单调递增，`nextId` 全仓一个发号器）：

```
[… 第 O 步的消息(assistant, id=O) ][旧未来：U…A…U…A…][本条指令：U, mid]
                                     └──────── 切这里 ────────┘
                                        O < id < keepFromMsg
```

- 说话/卡片：`keepFromMsg` = 刚插进去的那条**用户消息** id（`send`/`onCard` 里
  `nextId()` 拿到的那个 —— 现在是内联写的，要提出来）。
- 「再来一版」：没有新用户消息，`keepFromMsg` = 确认后 `say(reply)` 的 `mid`。
- 点选：`keepFromMsg` = 当初那句用户消息 id，**跟着 `pending` 一起存**
  （`applyDecision` 里 `setPending` 时多带一个字段；`confirmMark` 用它）。

### 4.4 切**什么时候**发生：生成**成功之后**，和推新步同一个 updater

```
setHistory(prev => {
  const base = cutAfter(prev, origin.stepId)
  const next = pushSnapshot(base, { …新步… })
  for (const s of bitmapsToClose(prev, next, { protectOriginal: true })) s.bitmap.close()
  return next
})
```

- **失败 / 用户按「停止」→ 一个步骤都不切**（那两条件 `return` 在切之前）——
  花了一次没成，后面的东西不该跟着陪葬。这是"放在成功分支里"白捡的一条好处。
- 生成途中用户跳走（跳转没有 busy 闸门，是**有意**的）：结果回来照切不误，
  切完 `setCursorId(messageId)`（新步）—— 和"结果落在最新"的口径一致；
  不这么写，cursor 会指到一条已经被切掉的步骤上（死指针，且不报错）。

### 4.5 切之前问一句（本次设计唯一的 UX 取舍）

从旧步骤生成时，先出一条确认 —— 形状**照抄点选那条 `.cards` 条**（`ChatPanel` 里
现成的那一类），不弹窗：

> 后面还有 2 步，从这改会把它们去掉。　［继续改］　［算了］

- `N = history.length - 1 - index(cursorId)`。
- **「继续改」**：`say(pending.reply)` → `runGenerate(..., origin)`。
  参数/滤镜读**此刻的**（说话那条路 = 决策算出的 + 期间拖的；再来一版 = 跳转后
  = 那一步的）—— 与"这一步做完之后的状态"口径一致（`useGeneration.ts:257-261`）。
- 确认条的状态（App 里）：
  `pendingReplace = { stepId: number; editPrompt: string; reply: string; keepFromMsg?: number }`。
  `keepFromMsg` 缺席 = "确认那一刻才知道"（「再来一版」那条路）→ 确认时
  `keepFrom = pending.keepFromMsg ?? mid`。
- **两个处理函数，别合成一个**：内部失效（跳转 / 说话 / 点卡片 / 换照片）只
  `setPendingReplace(null)`、**不吭声**（用户已经走了）；只有按钮「算了」才
  在清掉之后补一句「好，那就不动这一步。」。
- **「算了」**：清 pending + 说一句收尾「好，那就不动这一步。」（不能点了没反应）。
- **确认条上的话在确认前不说**：`d.reply`（"好，这就去改。"）存进 pending，
  等「继续改」再说 —— 先说了又点「算了」就是"说了不做"。
- 失效规则**和 `cancelPick` 一字不差**：跳转 / 又说一句话 / 点卡片 /
  换照片（`resetEditor`）都清掉。少一处：确认条会停在屏上，而它说的那件事
  已经翻篇 —— 点下去切的是别处。
- **点选那条路不额外多一次点击**：它的确认条本来就要点「就改这里」才花钱，
  把同一句提醒**并进去**（渲染条件是 `marking && futureSteps > 0`）。
- 「再来一版」的顺序有个坑：**先 `onJump(id)`（`onJump` 会清掉旧的
  `pendingReplace`），再 `setPendingReplace(...)`**。倒过来 = 刚设上就被清掉。

## 5. 存盘口径（★ 最容易静默错的一条）

跳转会把 `params` / `lut` 换成目标那一步的值 → 落盘 effect 重跑 → **而服务端把
`patch.params` / `patch.lut` 写在"最后一步"上**（`server/sessions.ts:433-448`）。
不处理的话：跳到第 2 步会把**第 2 步的参数写进最新那一步** —— 刷新后画面是最后
一步的、参数是第 2 步的，谁都不报错。

**规则：只有站在最新一步（`cursorId === last.id`）时才送 `params` / `lut`；
否则整个字段不送。**

- `SessionPatch.params` / `.lut` 本来就是可选，服务端的判据是
  `o.params !== undefined`（= 不动）—— 一个字都不用改服务端。
- 白捡的好处：跳转不再产生任何**改 steps 的** PUT（今天那一趟送的是截断后的列表）。

**代价（写明白）**：跳回旧步骤后随手调的颜色，不生成新东西就刷新 → **不留**
（刷新站在最新一步）。想把"站的位置"也记住，得给 `sessions` 加列（迁移 #5），
这轮不做（§9）。

另外，`route: 'both'` 的决策在**弹确认条之前**就已经把参数增量应用了 —— 点「算了」
时那半点变化留在屏幕上，而落盘（非最新位置不带 `params`）不会存它，刷新即回退。

## 6. 界面

### 6.1 「你在这里」

`ChatPanel` 新增 `currentId: number | null`：assistant 那条若 `m.id === currentId`，
把「回到这一步」那颗按钮换成**不可点的** `<span class="bubble-current">你在这里</span>`
（同款药丸、muted、无 hover；CSS 跟着 `.bubble-jump` 那几条一起写）。

- 为什么**不只**在"跳回去过"时显示：在最新一步上，那颗「回到这一步」本来就是
  **点了没反应的按钮**（全站最讨厌的那种，`ChatPanel.tsx:136-137` 旁边那条注释
  自己说过）—— 换成位置标记，顺手把它修掉，而且任何时刻"我在哪"都有答案。
- `aria-current="step"` 挂着；它是 span 不是 button（读屏和按文字找按钮的地方
  都能分清）。
- 当前那步的小图**点了照常**调 `onJump`（跳到脚下 = 无事发生，无害）。

### 6.2 确认条

`ChatPanel` 新增 props：`futureSteps: number`、`replacing: boolean`、
`onConfirmReplace`、`onCancelReplace`。

- `replacing` 时渲染确认条（§4.5 那句话 + 两颗按钮），两颗都跟着 `busy` disabled
  （和「就改这里」同款）。
- `marking && futureSteps > 0` 时，点选那条条子里多一句同样的提醒。

### 6.3 文案（同步进 `docs/文案规范.md`）

| 用途 | 文案 |
| --- | --- |
| 位置标记 | 你在这里 |
| 确认条正文 | 后面还有 N 步，从这改会把它们去掉。 |
| 确认 | 继续改 |
| 放弃 | 算了 |
| 放弃后的收尾 | 好，那就不动这一步。 |

## 7. 验收线

1. **跳转不删**：跳到旧步骤 → 后面的小图、两颗按钮一个不少，还能再点回去；
   画面 / 参数 / 滤镜跟着回到那一步。
2. **跳转不写坏存盘**：跳完等落盘 → PUT 里 `steps` **还是全部**、
   `params`/`lut` **不出现**；刷新 → 所有步骤都在，人站在最新一步。
3. **从中间改 —— 先问**：站在旧步骤发一句话 → 出确认条（N 正确）；
   「算了」→ 什么都没生成、什么都没切、步骤一个不少，且有一句收尾；
   「继续改」→ 旧的步骤 + 那一段对话一起没了，新步骤接在切口上，底图是那一步的。
4. **「再来一版」**：旧步骤上同 3；**最新一步上不弹条**、和今天一样直接重掷。
5. **点选**：站在旧步骤上，确认条带同一句提醒；「就改这里」= 直接切口生成
   （不多点一次）。
6. **失败 / 停止不切**：从旧步骤生成失败或按停止 → 后面的步骤一个不少。
7. **正常流程不变**：站在最新一步从头改到尾，和今天一模一样（一条多余的字都没有）。
8. **你在这里**：出现在站的那一步上；恢复会话后站在最后一步。

## 9. 不做（有意）＋ 已知边界

- **不保存"站的位置"到服务端**（要动表，迁移 #5）。代价见 §5。
- **不做两条线并存的"分支"**（像 Git 那样）。工程量差好几倍，且"哪一版是最终"
  会变模糊 —— 这一轮的靶子是"不丢"，不是"分叉"。
- **不做删除单条对话记录**（用户已经问过；单开一轮 —— 它要动服务端、要定
  "删一条消息时对应的步骤/图怎么办"）。
- **服务端零改动**：`mergeSteps` 对"少送的步骤"本来就是删除语义；`params`/`lut`
  的可选语义现成；切掉的步骤图片文件留在 `files` 名单里、删会话时统一收
  （和今天截断那条路**一模一样**，不是本次引入的）。
- 切掉的那几步的**对话记录也一起没了**（连用户当时说的话）—— 这是有意的
  （留着就是现在这种光秃秃的文字），且只在用户点过「继续改」之后发生。
- **已知边界：跳转之后、生成之前说的"纯参数话"**（如「亮一点」，只改参数、
  不推步骤）：它的**对话文字**会被切口收掉，而**参数效果仍生效**（会被新那一步
  记进去）。这是区间切片的本意（那段属于被放弃的未来），但用户会看到自己的话
  消失、画面却真的变了 —— 下一轮若引入"跳转时的消息水位"再一并修。

## 10. 为什么这样切（回顾过的备选）

| 备选 | 不选的理由 |
| --- | --- |
| 跳转时截断但加提示（= 现状 + 文案） | 没解决"用户说要保留" |
| 跳转不截断、生成时**直接**切（不确认） | 会静默丢掉花过钱的几步；这个项目一直不静默丢东西 |
| 真·分叉（两条线都留） | 数据模型（线性链 + 服务端按序指派文件）要大改；UI 上要发明"分支"概念；量级差好几倍 |
| 把"站的位置"持久化 | 要动表；本轮 YAGNI，代价已写明（§5） |
