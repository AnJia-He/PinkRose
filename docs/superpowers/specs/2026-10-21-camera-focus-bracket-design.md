# 相机焦点包围设计 —— 2026-10-21

## 背景

焦点堆栈已经能把多张不同焦点的照片合成一张，但相机桥之前只能拍同一焦点。
微距、产品和风景常需要手动转对焦环，再逐张命名、导入、重新选择。
相机适配器只要暴露可写焦点位置，就可以自动完成这一段。

## 可用条件

- 相机 schema 必须有可写焦点位置字段。支持常见命名：
  `manualfocusdrive`、`manualfocus`、`focusposition`、`focusdistance`、
  `focusdrive` 或 `focus`。
- `focusMode` / 自动对焦模式不是位置，不会出现在条件里。
- 相机没有暴露可写焦点位置时，整个「焦点包围」区不显示，不拿曝光包围冒充。

## 交互

- 选择 3 / 5 张和窄 5% / 中 10% / 宽 20% 的焦点范围。
- 从当前焦点向两侧展开，数值按相机 min / max / step 或下拉选项吸附。
- 拍完恢复原焦点；任何一张拍摄失败也会尝试恢复。
- 整组照片不自动逐张替换编辑器，而是出现「用这组做焦点堆栈」。
- 点击后带着整组文件进入现有焦点堆栈工作区，并直接预填。

## 安全与兼容

- 序列与间隔拍摄 / 包围曝光互斥；运行中可随时停止。
- 范围不足、相机没有可读焦点或无法生成不重复位置时，开拍前明确拒绝。
- 真实机型仍需要在硬件上确认焦点字段的单位、方向和步长。

  3 / 5 张序列、吸附到步长、边界重复拒绝。
- `src/ui/CameraBridge.test.tsx`：焦点 PUT、3 次快门、恢复原焦点、
  整组交给焦点堆栈。
- `src/ui/FocusStackPanel.test.tsx`：预填文件；StrictMode 模拟卸载不提前释放 blob。
- `src/ui/GalleryPage.focus.test.tsx`：作品页接收焦点包围种子并自动打开目标工作区。
- `npm run check:focus-bracket`：WebKit 390px；控件可用条件、焦点序列恢复、
  整组预填、无横向溢出、控制台无错误。
