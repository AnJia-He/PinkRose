# 照片电影（2026-10-20）

## 要解决什么

用户手里有一组照片（旅行、婚礼、孩子生日），想直接发一段十几秒的视频。
「照片动图」解决的是"几张照片硬切"，但市场里的回忆视频都会让画面**缓慢运动**。
这一版把照片做成带推拉镜头的短片：

- 1–12 张照片，按选择顺序播放，可调顺序 / 删除；
- 每张 1–4 秒，全片合计不超过 20 秒；
- 镜头运动：推近 / 拉远 / 平移 / 静止；
- 转场：硬切 / 淡入淡出（0.4 秒重叠）；
- 成片画幅：原比例 / 1:1 / 4:5 / 9:16 / 16:9；
- 套用和照片相同的预设与强度；
- 可选本地配乐（自动循环到全片长度）；
- 导出 H.264 + AAC 的 MP4。

## 关键决定

### 1. 先合成帧，再用短片同一条链路编码

每张照片按时间轴生成 `round(时长 × fps)` 帧（至少 2 帧），逐帧走
`TonePipeline`（和照片完全相同的着色器），再用视频会话分批上传、
ffmpeg 编码。好处是调色、暗角、颗粒、镜头虚化都和照片一致，
而且不需要为幻灯片再写一套编码器。

### 2. 推拉是"裁小再铺满"，不会露黑边

先按 cover 把照片铺满目标画幅，再按进度放大 1.0–1.12 倍（平移固定 1.08），
放大后的画面永远盖住画布；奇数张与偶数张的平移方向相反，连续播放不呆板。

### 3. 没有源视频，所以音轨只有配乐

帧序列直接编码，`keepAudio=false`；配乐按 `replace` 模式映射为唯一音轨，
短于全片时循环、长于全片时截断。

### 4. 淡入淡出是"重渲染尾帧 + 混合"

转场不缓存整段画面：轮到下一张时，把上一张最后 `K` 帧**重新渲染一遍**，
与下一张前 `K` 帧按 alpha 混合（`(i+1)/(K+1)`），再编码。
K 取 0.4 秒对应的帧数，并保证每张至少留两帧。
总帧数 = 张数 × 每张帧数 − K × (张数 − 1)；配乐按这个总长截断。

## 上限

| 项 | 值 |
| --- | --- |
| 照片 | 1–12 张 |
| 每张时长 | 1–4 秒 |
| 全片 | ≤ 20 秒（480 帧 @24fps） |
| 画幅长边 | 1280 |

## 验证

- `src/movie/plan.test.ts`：时间轴、时长上限、推拉矩形永远覆盖画布；
- `src/movie/export.test.ts`：分批、时间轴、配乐、取消；
- `src/ui/PhotoMoviePanel.test.tsx`：选片、镜头 / 预设 / 配乐、取消；
- WebKit 390px：入口可开、不横向溢出；
- Chromium 实测：2 张各 1 秒 + 1 秒配乐 → 2.000 秒、带音轨；
  0.2 秒为测试图、1.2 秒为纯蓝（顺序正确）；同一张照片 0.1 秒与
  0.9 秒的帧哈希不同（推拉生效）。
