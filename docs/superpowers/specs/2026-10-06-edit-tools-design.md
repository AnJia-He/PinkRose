# 调色屏「工具行」· 裁剪 / 点修 / 对比（设计）

> 2026-10-06。用户原话：「**我总觉得调色界面还缺什么东西，你觉得作为一个使用修图
> 软件的用户，还要考虑到哪一些功能？结合 ai 辅助定位细节点？**」
> 看完五路实测（`docs` 外，材料在 `.superpowers/scratch/tool-survey/`）之后他定了
> 前三个，并补了一句关键约束：
>
> 「**在调色区域不走 ai 一步到位的消除，有些细节点是用户可以自己动手改的，
> AI 辅助用户 —— 因为用户想改细节点的时候对话里说不明白，可以自己进行定位修改**」
>
> 所以这三个工具的共同点：**用户定位、AI 或算法执行；不是"说一句话全交给 AI"**
> （那是对话区的事）。

---

## 1. 为什么是这三件（依据）

**五路实测**（美图网页版·真机 / 醒图 / 剪映 / 像素蛋糕 / Lightroom+PS+Google+Apple，
材料见 `.superpowers/scratch/tool-survey/SUMMARY.md`）的结论：

1. 五家里最轻的美图，工具行也有 **9 个格子**；我们**一格都没有** —— 缺的不是滑块。
2. **消除（去路人）是五家共识的重活**，而且形态收敛到三种：涂 / 一键 / 说一句。
3. **裁剪 / 旋转 / 水平矫正**三家有（两家连"AI 水平矫正"都给了），我们全站没有。
4. **对比**是标配：美图把它摆在**画布右下角、和缩放百分比同一排**（我们那排
   按钮正好在那里）；醒图是**分屏 + 拖动把手**。
5. 「AI 帮你看一眼、说哪儿不对」与「改完自动带你看」—— **五家都没查到**
   （空白 ≠ 有价值，见 §6 不做）。

**本地可行性实验**（`.superpowers/scratch/spike-select-erase/`，真机跑通，零 API 成本）：

| 能力 | 选型 | 实测 |
|---|---|---|
| 点一下就选中 | MediaPipe **Interactive Segmenter**（MagicTouch） | 6.2MB · 点一下 **6~11ms** · 真人照片上"点人选中整个人（含手里手机、不含地上影子）" |
| 涂哪擦哪 | **MI-GAN**（ONNX，`andraniksargsyan/migan`，MIT） | 29.5MB · 1024px 图 **约 2s** · 人擦干净了、周围补得顺；补过的块**略糊**，影子要另外再点一下 |

**结论：这两件事不需要云端**。全在浏览器里跑 —— 不上传、不占改图额度、
点下去就亮。这正好落在用户那句"用户自己动手、AI 辅助"上。

## 2. 范围

### 2.1 这一批做

| # | 工具 | 一句话 | 走 AI 吗 |
|---|---|---|---|
| 1 | **裁剪 / 旋转 / 水平矫正** | 画布上拉框、转正、裁掉 | 否，纯本地 |
| 2 | **点修**（涂抹 → 擦掉） | 涂哪儿擦哪儿，自动补背景 | 否，**本地算法**（★ 10-07 更正：移植 Compositor 的修补笔，零下载 —— 见 §3.2 与 §9） |
| 3 | **对比**（分屏） | 左原图 / 右现在，中间拖把手 | 否 |

**建议实现顺序：裁剪 → 对比 → 点修**。前两个是纯本地几何/视图，快且风险低，
能先把"工具行"这条架子立起来；点修要接两个模型（36MB、进度、失败路径），
放最后，也最值得单独一轮验证。

### 2.2 排队第二批（这轮不做，但设计时给它留位）

- **「说一句改这块」**：选中一块 + 一句话（"换成草地"）。要**带蒙版的编辑接口**，
  而**商汤给不了**（实测其官方文档全站 `mask` / `inpaint` / `局部重绘` 零命中）。
  备选：**阿里百炼 `wanx2.1-imageedit`**（`mask_image_url`，0.14 元/张）、
  腾讯云 `ImageInpaintingRemoval`、美图 AI 无痕消除。**接第二家云是独立的一轮**。
- **局部滑杆**（只提亮脸 / 只压天空）：要蒙版进渲染管线（多 pass），
  文档里本来就叫"子系统"，单开一轮。
- **AI 自动水平矫正**、**AI 自动找路人**（一键框选）：前者没做，后者降级成
  §3.3 的可选助手（先不做）。

### 2.3 明确不做

- 不在**修图屏**（对话区）加工具行 —— 那一屏的工具就是对话。
- 不做逐笔撤销的历史面板：**撤销 = 回到上一步**（历史转盘已经有了）。

## 3. 三个工具

### 3.0 它们住在哪：一条**工具行**

调色屏现在的排布是「左：预设栏 / 中：照片 / 右：微调面板」。**照片上方那条带子
空着** —— 修图屏在那儿是历史转盘（`.strip`），调色屏什么都没有。

- 工具行摆在那儿：**同一块地方、同一套长相**（`--raised` 底 + 一道 `--line`，
  和 `.strip` 一个语言）。三个格子：`裁剪` / `点修` / `对比`。
- **点开一个工具 → 带子下面长出第二行**（那个工具自己的控件 + 「完成 / 取消」），
  照片区照旧。这是剪映/醒图的两级工具行形状，也是我们【修图屏】已有的语言。
- 同一时刻**只有一个工具**在跑（单选，和剪映/醒图那条工具行一致）：
  ⚠️ **2026-10-06 实现期更正**：原话是"「对比」是个开关、和另外两个不冲突"，
  实现时定了口径 —— **按「对比」会把正在进行的裁剪收掉**（裁剪框丢：再进去是从默认框重来，
  **现场不会回来**；有可见反馈、可以重新裁）。
  真要"裁着的同时比一眼原图"就得把工具行改成多选（动 T1 的契约），当前判断不值当。
  另一条相关的：**「对比」开着时 `viewLocked` 与 `resetKey` 都不认它**（见 §3.3）——
  它不锁手势、也不把视图拽回适应窗口。

★ **窄屏（≤640）：这一行保留**（2026-10-06 终审定论 —— 原话是"等实现时按
`check:layout` 量"，账量完了）。第一行两颗工具照常；**第二行不折行、横着滑**
（`flex-wrap: nowrap` + `overflow-x: auto`，和窄屏那条历史带子 `.strip` 同款），
每个控件 `flex: none` 保持天然宽度，「取消 / 完成」靠 `position: sticky` **钉在
右边** —— 滑到哪里都够得着。量出来的账（`check:layout` 新增的「开着裁剪」态）：
折行时第二行 3 行 = 136px，照片被挤到 **175×116**（低于本仓 240×150 那条线 =
"看不到图"）；横滑之后第二行 **49px**，照片回到 **305×203**。
⚠️ 这条只写窄屏：桌面它折两行（92px）是**已验收的版面**（照片 479×320），
别顺手把窄屏那套规则提成全局的。

### 3.1 裁剪 / 旋转 / 水平矫正

**交互**
1. 点「裁剪」→ 照片上出现**裁剪框**：拖四角 / 拖四边 / 拖框内移动；框外用
   暗罩压住（"要留下的那块"亮着）。
2. 第二行控件：**比例**（自由 / 1:1 / 4:3 / 3:4 / 16:9 / 原始）、**左右转 90°**、
   **水平矫正**滑杆（−15° ~ +15°，实时预览）。
3. **完成 = 本地生成新的一步**（不花钱、不占额度）。**取消 = 什么都没发生**。

**三条硬规矩**

- ★ **裁剪作用在 `base` 上，`params` / `lut` 原样跟着走** —— 用户调好的滑块
  **不许丢**。理由：十五根滑块里绝大多是**逐像素**的（曝光/对比度/饱和度……），
  几何变换和它们可以互换位置、结果不变。**两个例外要认**：① **暗角**按画面中心算，
  裁完之后它跟着**新构图**重算 —— 这是对的（新构图的中心才是中心）；② 清晰度
  在贴边那一圈因为边界变了会略有不同。所以预览**必须用实现时同一套算式**，
  别让用户先看到一版、点完又变一版。
- **裁剪时视图锁在「适应窗口」**：缩放/平移手势和右下角那排按钮**暂时关掉**
  （一边裁一边缩放会让框和手指打架；这一版先做简单可靠的）。
- **裁剪出来的新一步没有 `prompt`**（没有可重跑的指令）→ 不出「再来一版」✓
  和历史里其它本地步骤一致。

**旋转 / 矫正的几何**：旋转会产生**空白角**，所以按**最大内接矩形**收框
（业界通行做法：转多少度，框就自动缩到不露空角）—— 这条要有单测钉住。

★ **角度一变，框重置回"居中的最大内接矩形"**（`App.setCropAngle`）——
包括拖「水平矫正」滑杆时**每 0.5° 重置一次**（滑杆的步进就是 0.5°）。
代价：用户先把框拖好、再去微调角度，框会被收回默认位置（拖框的成果没了）。
**这是 v1 的简化**（"转完再回来抠那个角"要按角度逐帧保住用户拖的框，
产品上还没定值不值当），记在 §3.4 已知边界里。

### 3.2 点修（点选 / 涂抹 → 擦掉）

> ★ **2026-10-07 实现期更正（口径换了，先读这段再看下面的原设计）**
>
> 用户当天提了新要求：「GitHub 上有个人把 Adobe 的东西开源了叫 Compositor，
> 看怎么能融入我们的项目，一切权力你自己决定」。扒完源码定的路线：
>
> - Compositor 是个 **macOS 原生 App**（Swift，MIT），**不能**直接嵌进网页产品；
>   能用的只有它 `Rendering/` 里那批**零依赖的 C 像素算法**。
> - 其中 `HealPixels.c`（修补笔：光环匹配找 donor 补丁 + 多网格泊松膜求解 +
>   噪点回填）正好就是点修缺的引擎 —— **已移植**到 `src/image/heal.ts`
>   （MIT，出处与原文见根目录 `THIRD_PARTY_NOTICES.md`）。
> - 于是 v1 的引擎从"MediaPipe 选 + MI-GAN 补（36MB 下载、每次约 2s）"换成
>   **纯本地的修补笔**：**零下载、点完就出**（真照片探针：小斑块 20~70ms，
>   42 万像素约 1.7s）。
> - 同一仓库的 `ContentFill.c`（PatchMatch 内容感知填充）也移植过、**被探针否决**
>   并删除：420² 以上出硬拼接缝、还会把远处内容（嘴唇）搬错位置，而且大块时
>   不比修补笔快（1100×1000：6.1s vs 4.1s）。证据脚本与产出留在
>   `.superpowers/scratch/retouch-probe/`。
> - **交互跟着简化**：v1 只有**画笔 / 橡皮**（原设计里的「智能：点一下选中」
>   是 MediaPipe 那条路，**推迟**到第二批）。「先选地方，再擦」的骨架不变。
>
> 下面的原设计文字保留（它记录的是当时的推理），但**以本块为准**。

**交互**（照像素蛋糕的骨架：**先选地方，再选干什么**）

1. 点「点修」→ 第二行出现选择方式：
   - **智能**（默认）：鼠标在照片上移动 → **光标底下那块亮起来**（半透明红）→
     **点一下选中**；`Ctrl/⌘ + 点击` = 多选。★ 10-07：**推迟**（要 MediaPipe，见上）。
   - **画笔**：画笔 / 橡皮 / 笔刷粗细，自己涂（智能选不干净时用）。
     ★ 10-07：**v1 就它一个选择方式**；旁边还有「取消 / 擦掉这里」两颗
     （「擦掉这里」没涂过时是禁用的）。
2. 选中之后，第二行长出动作：**「擦掉这里」**（本轮唯一动作）。
3. 点它 → 本地修补（小斑块毫秒级、大块几秒，超过约 0.3s 的那档盖暗罩）→
   **擦干净、自动补背景** → **变成新的一步**（能回退）。

**三条硬规矩**

- ★ **擦除作用在 `base` 上，`params` / `lut` 原样跟着走**（同 §3.1）。
  用户在**带着参数和滤镜的画面**上指位置，但**擦的是底图**；
  之后参数/滤镜再盖上去 —— 两块区域**受同一套调整**，所以不会出现"补丁颜色
  和周围对不上"。⚠️ 别改成"擦渲染后的画面"（那会把参数烤进像素里，
  用户再拖滑块就只有那块不动了）。
- ~~**模型全都本地跑**：MediaPipe 6.2MB + MI-GAN 29.5MB，按需加载…~~
  ★ 10-07：**作废** —— v1 换成移植来的修补笔（`src/image/heal.ts`），
  **零下载、不进任何模型**。原来那条"权重别挂境外 CDN"的坑随之消失
  （将来第二批真接模型时它仍然算数）。
- **掩码要外扩再用**：不外扩会留一圈没擦到的边。★ 10-07 定的数是 **2px**
  （`image/erase.ts` 的 `DEFAULT_EXPAND`，灰度膨胀、软边跟着长）；
  擦完的结果按覆盖率羽化混合（引擎内部那条 `coverage × opacity`），别硬边。

**已知边界（写在这儿，免得上线被当 bug）**

- ★ 10-07 新账（旧的 MI-GAN 那几条随引擎一起作废）：
  · **大块会"糊"**：修补笔是"搬一块最像的纹理 + 接缝算平"，几百像素以上的
    洞补出来是一片被拉匀的面（细节被抹平）—— 这是算法能力，不是 bug；
    要更清楚得走第二批（模型 / 云）。
  · **一次擦除有大小上限**：外接框 > 120 万像素就拦住（给一句「一次擦一小块」）
    —— 耗时随外接框面积涨（探针：42 万 ≈ 1.7s、110 万 ≈ 4.1s），拦的是
    "十几秒假死"，不是质量。
  · **点修里没有"拖动平移"**：拖动 = 涂抹；放大用滚轮 / 右下角那排按钮
    （锚在指针上，够得到任何位置）。要平移就先缩回适应窗口。
  · **没涂过的掩码提交不了**（「擦掉这里」是禁用的）；「取消」= 掩码当场丢掉，
    再进去是新的一张（和裁剪"现场不会回来"同一条）。
- **影子、倒影、倒下的光斑不会跟着走**：这是"你指哪儿它改哪儿"的必然结果 ——
  **再点一下影子**就行。界面上不用解释，但文档里要写死，免得以后有人当 bug 修。
- 点选**分不清叠在一起的东西**（比如人和他背后贴着的墙）；那时走画笔。
  ★ 10-07：v1 只有画笔，这条在"智能选择"落地前不适用。

### 3.3 对比（分屏）

- **入口**：照片右下角那排按钮里加一颗「**对比**」（美图就把它摆在缩放
  百分比旁边），点一下进入对比态。
- **长相**：**左右分屏 + 中间一条能拖的把手** —— 左「原图」、右「现在」。
  再点一下那颗按钮退出。
- **比的是"原图"**：和「按住看原图」**同一个"原图"**（会话最初那张），
  不另造一套说法。⚠️ 别做成"和上一步比"—— 那是另一个问题（"刚才那条指令
  生效了吗"），真要做是**第二颗按钮**的事，别把两种语义塞进一颗。
- 原图那份要**够清楚**：现在的 `originalPreview` 是缩略图（按住看够用），
  分屏要另备一份**较大的一版**（上限 2048，活着的时候留在内存里、
  恢复会话时从 `/file/original` 取）。⚠️ 别拿缩略图放大去比 —— 左边糊右边清楚，
  用户会以为是我们把照片弄糊了。
- 对比态里**缩放/平移照常能用**，两张图**同步**（同一个 transform）。
- ★ **比例不同时（裁过一刀 / 转过 90°），两半各自按自己的比例 contain** ——
  左半边（原图）会比右边上下各多出一截。"**和会话最初那张比**"这个语义使然：
  不让它多出来，就得把原图裁掉一块，"对比"这件事本身就假了。真机看过，
  观感可接受（多出来那块垫的是**照片区自己的底** `--stage-light` + `--bg`、
  **不许透出画布像素** —— 修过一轮的必修项，评审探针抓到它漏过像素）。

### 3.4 已知边界（2026-10-06 终审定案 —— 写在这儿，免得上线被当 bug）

1. **裁剪框 / 对比把手没有键盘通路**（只有指针手势）。这一批不做；
   键盘用户在裁剪那一行还能用按钮和滑杆（比例档 / 左转 / 右转 / 水平矫正），
   但**框的位置和大小拖不了**（只能吃默认框 + 比例档）。可访问性缺口记在账上。
2. **对比备图失败后，那颗按钮仍然亮着**（`comparing` 还是真、原图那份没备出来，
   屏幕上有一句「原图没取回来，这次对比先算了吧。」）。**点两下即可重试**：
   点一下是关、再点一下是开，那一下会重新走一遍备图。
3. **"不许放大"生效时是截断、不是缩放**：框大到会让输出超过原图面积时，
   `cropOutputSize` 按面积把输出**截**小（输出的右/下可能少一块）——
   不是把用户的框缩回去。只要框被夹在内接区内（`CropOverlay` 的常态）就
   **够不着**；只有"几百比一的窄长条 + 大角度"那一角能碰到（T2 评审扫过 121 个
   角度，零可达）。这是有意的取舍，见 `core/crop.ts` 的注释。
4. **三处清 `compareSrc`（换照片 / 换会话 / 重置）没有常驻单测** ——
   代码在、真机探针看过，但没有会红的守卫；动那三处时自己心里有数。

## 4. 和现有系统的交界（最容易出错的地方）

| 交界 | 规矩 |
|---|---|
| **历史 / 步骤** | 裁剪和擦除都**产生新的一步**（`label` 写"裁剪"/"擦除"），走 `useGeneration` 那条推快照的路 —— **同一个账本**，别另开一份历史 |
| **`prompt`** | 本地步骤**没有 `prompt`**（`undefined`）→ 不出「再来一版」，也**不许写成空串** |
| **落盘** | 本地步骤的图**也要存**（和生成步骤同一条路），否则刷新之后这一步是空的 |
| **`resetKey` / 视图** | 进任何一个工具都**先收回「适应窗口」**（和换会话一个待遇）；出工具不自动变 |
| **点选（红圈）** | 和「调色屏的工具」**互不干扰**：红圈是对话那条路的东西，工具只在调色屏 |
| **导出** | 导出走的是画布 → 新步骤的图就是 `base`，导出天然正确；**但 `params` 不能再叠一次**（§3.1/§3.2 那条规矩的原因之一） |
| **金标准** | 所有新步骤都必须**能"回到这一步"、能删、能被落盘** —— 它就是普通的一步 |

## 6. 已知风险

1. **质量**：小斑块好（探针 A：痘印擦完干净）、大块糊（§3.2 已知边界）。
   若用户嫌糊，升级路径是模型（LaMa 512 / 云接口）—— 第二批。
2. **性能**：小斑块 20~70ms、42 万像素 ≈ 1.7s、110 万 ≈ 4.1s（探针，本机
   无头 Chrome）。⚠️ 用户的机器可能更慢 —— 上限拦的就是这个最坏情况。
3. **大块假死**：计算是同步的（会冻住渲染）—— 慢的那档先亮暗罩再开算
   （`commitRetouch` 里那两帧 rAF）。暗罩上的转圈是 CSS 动画，冻结期间
   照转（合成器线程），所以观感是"卡但知道在干活"。
