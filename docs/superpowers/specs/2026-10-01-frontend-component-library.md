# RuiXing 设计文档 — 前端组件库

- **日期**：2026-10-01
- **状态**：设计定案，待写实施计划
- **一句话**：通用交互件别再自己手搓 —— 拿成熟库的行为和键盘，长相仍然是我们的。

---

## 1. 用户的要求（原话）

> 对于项目前端组件的搭配**不要自己手搓除非特殊的**，一律从市场上成熟的组件库中查找
> 相关适配的组件进行搭配，**小程序也是**。

同一天晚些又强调了一遍：

> 有成熟的组件库可以用我们就不需要手搓了，**现在有的也可以进行更改**，
> **重复的代码也可以封装成组件**避免"屎山代码"，**麻烦就麻烦点**，
> 结合我们的项目从主流的组件库中运用组件进行搭配。

⚠️ 这条**推翻了本项目原来的「零新依赖」**（spec §4.2、各计划的 Global Constraints、
源码注释里都写着）。**但只在前端组件这一块**：`server/` 和 `shared/` 里
"手写、不引库"的现状（`node:crypto` / `node:sqlite` / 手写 HTTP）**不在范围内**，
别顺手也去引一堆后端库。

## 2. 边界：什么算"通用件"

| 这算什么 | 怎么办 | 本项目的例子 |
|---|---|---|
| **通用交互组件** | **去找现成的** —— 无障碍、边界态、见过的坑，人家已经替我们付过学费 | 滑块、输入框（label/错误/描述的关联）、图标、按钮、弹层、下拉、日期、表格、标签页 |
| **这个产品独有的东西** | **才自己写** | **画布 + 参数渲染那一套**、对话气泡里那条「回到这一步」、照片墙、那三条横幅（通报 / 在问 / 存失败） |

判断一个新依赖该不该引，一句话：

> **它解决的是一个"难、说得清、且不碰视觉"的问题，并且不插手 DOM 吗？**
> 是 → 引。**凡是要渲染、要主题、要占布局的，仍然是我们自己的。**

## 3. 选型（2026-10-01 查过市场之后定的）

### 3.1 用 `@base-ui-components/react`（无头原语）+ `lucide-react`（图标）

**无头**＝只给行为和键盘，DOM 结构和类名仍然由我们说了算。这一条对本项目是硬要求，
因为**我们的设计系统是自己的**（`src/styles.css` 顶部那套令牌 + 三条硬约束），
而且**测试是按类名找元素的**（`src/App.test.tsx` 96 条里 62 条按 class 找）。

### 3.2 为什么不选那几个"整套的"

| 候选 | 为什么不 |
|---|---|
| **shadcn/ui** | 它是 **Radix/Base UI + Tailwind**，而且是把**源码复制进仓库**。我们没有 Tailwind，令牌是纯 CSS —— 引它等于把设计系统照 Tailwind 重做一遍 |
| **Ant Design / Mantine / Chakra** | **自带整套视觉**。我们有自己的语言（粉底、玫瑰、令牌），引进来就是天天跟它打架；它还会拿回"改设计"的权力 |
| **Radix Primitives** | 曾经是标准答案，被 WorkOS 收购后更新变慢；Base UI 是**同一批作者**重做的下一代。shadcn 官方 2026 把新项目默认切到了 Base UI |
| **全部自己写** | 下拉、弹层、滑块的无障碍**是要吃掉整个迭代的** —— 我们已经吃过一次（见 §4） |

### 3.3 版本与风险

- `@base-ui-components/react` 当前是 **`1.0.0-rc.0`（候选版，还没 1.0）** ——
  **锁死版本号**（写入 package.json 时不带 `^`），升级时人工过一遍。
- `lucide-react` 稳定版，图标 `stroke="currentColor"`，直接吃我们的字色。

## 4. 不许破的既有契约

1. **令牌是我们自己的**：库不提供颜色。新组件只许引用 `--rose-*` / `--bg` / `--panel` …
2. **类名是测试的结构锚点**：`.login-eye`、`.login-field input[name=…]`、`form.chat-input`、
   `input[type="file"]`、`.save-fail button.download`、`.actions button`（**恰好三颗**）、
   `.bubble-jump`、`.card`、`.models-row`、`.gallery-thumb` —— 换组件也要保住它们，
   否则 96 条 App 级测试会一起红。
3. **符号不许进 textContent**：`↶ ↻ +` 这些是 CSS 画出来的（`styles.css:1200` 那段
   注释写了原因：读屏会念、按文字找按钮的地方会认不出）。换图标时仍然走"装饰"这一侧。
4. **主按钮的长相只有一份**（`button.primary, .save-fail button.download, .login-submit,
   .detail-download`），别再多抄几份。
5. **本项目已经吃过的亏**（所以要引库）：导航用词只盯版式没读字、按钮被 `:hover`
   特异性顶掉 —— 都是手搓才有的那类坑。

## 5. 这一轮做 / 不做

**做**：滑块（8 条）、输入框（10 格，把 label/描述/错误用 ARIA 连起来）、
图标（emoji `👤`、内联 SVG 的眼睛、`↶ ↻ ← › ↑ ✓ ⚠️` 这些字符）、
把四种载体的主按钮收成一个组件、以及顺手把 `App.tsx` 里那几块复制粘贴合并。

**不做**（今天还用不上，用到再找）：下拉 / 日期 / 表格 / 标签页 / 弹层 / 命令面板。
⚠️ 本项目**故意不弹系统框**（通报走 `.notice` 条、删除确认就地说），
所以 `Dialog` / `AlertDialog` **暂时不引** —— 引了就会有人开始弹窗。

**小程序那一侧还没定**，而且不该现在定：先定框架（Taro / uni-app / 原生），
组件库跟着框架走。轮到做小程序时按同一套判据重新查一遍。
