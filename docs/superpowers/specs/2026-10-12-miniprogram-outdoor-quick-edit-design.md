# 小程序「户外快速修图」· 设计

> 2026-10-12。用户原话（这份文档的源头）：
> 「开始做小程序，小程序的定位很简单就是户外快速修图」
> 当场口头确认的三个决定（浏览器草图逐屏过的）：
> ① **挑风格为主 + 能说一句**（默认路径不用打字，拳头能力当后手）；
> ② **第一版就核心闭环**：选照片 → 挑风格/说一句 → 按住对比 → 存相册，裁剪/点修/作品集都不做；
> ③ **界面走「标准编辑器」布局**（照片一张干净的舞台，控制区在下面）；「说一句」修完**直接换图 + 一个撤销**，不弹确认。

## 0. 一句话

微信原生小程序：**选照片 → 挑风格/说一句 → 按住对比 → 存相册**。修图手艺（WebGL 渲染）
搬进小程序本地跑（挑风格**秒出、不花流量**）；AI 那条路继续用电脑版现成的后端
（「说一句」走网络）。界面按手机重做，不是把电脑版塞进小屏。

## 1. 定位与成功线

- **定位**：户外快速修图 —— 手机那侧是「拍完随手修、30 秒发朋友圈」。
  这是 2026-09-24 拍板的平台分工里本来就写好的：**web 是给电脑用的独立产品
  （坐下来认真修一张），手机场景归小程序**（`2026-09-21-...-design.md` §585、
  `2026-09-24-accounts-and-gallery-design.md` 开头）。本设计就是执行这条。
- **成功线（验收要用）**：
  1. 从「选完照片」到「存进相册」，走挑风格这条路 **≤ 30 秒**；途中**不需要打字**。
  2. 挑风格**秒出**（本地渲染，不等网络；目标 < 100ms 一档，真机量）。
  3. 「说一句」能出图（与电脑版同一套后端）。
- **与电脑版的边界**：调色面板、裁剪、点修、账本、对话记录、作品集 —— 全是电脑版的事，
  小程序第一版一个都不搬（见 §9）。

## 2. 技术选型（已确认）

**微信原生小程序 + TypeScript**。备选是 Taro（用 React 语法写小程序），不选它：

- 只有微信一个端 —— 跨端框架（Taro/uni-app）的价值是「一套代码多端跑」，这里用不上；
  单端时原生**功能最新最全**，中间少一层翻译（CopyPlan 选型表第三节的原话）。
- 我们最大的资产是手写 WebGL 渲染管线 —— 2026-09-23 的真机探针
  （`archive/spike/miniprogram-webgl/README.md`）就是**原生写法**跑通的：WebGL2 ✅、
  单边纹理上限 **16384**（浏览器只给 4096）。照着探针搬最稳。
- 界面反正要按手机重做（电脑版的 React 组件搬不过来），Taro「复用 React」的好处有限。
- 写原生小程序对着微信官方文档，资料最全、训练数据最饱和。

**已由探针确认 / 待实现时验清的事实**：
- WebGL2 可用、`MAX_TEXTURE_SIZE = 16384`、`MAX_VIEWPORT_DIMS = 16384`（Mali-G925 真机）。
- 图片进纹理：**先画进离屏 2D 画布再 `texImage2D`** —— 直接把 `canvas.createImage()`
  对象传进去会报 1281（探针踩过）。
- ⚠️ **遗留之谜（实现第一件事就是验它）**：探针里真照片 1536×2048 上传报 1281、
  缩到 1152×1536 就过 —— 上限明明 16384，不知是探针用法还是真实行为。探针 README
  原话「哪天真做小程序，第一件事就是把它验清楚」。
- ⚠️ `texImage3D`（管线里给 LUT 留的 3D 纹理占位）探针**没验过** —— 实现时先验；
  万一不支持，把 LUT 那半（uLutOn=0 分支 + 1×1×1 白点）摘掉即可（第一版不用 LUT）。

## 3. 架构

```
手机（小程序 mini/）
 ├─ 界面          WXML/WXSS 全新写（视觉沿用电脑版语言，见 §7）
 ├─ 本地渲染      移植 TonePipeline：挑风格/参数 → WebGL 本地画 → 秒出
 └─ 网络          「说一句」→ /api/route（缩图 640）→ 决策
                       ├─ params   → 本地套参数（瞬时）
                       ├─ generate → /api/edit（2048 + editPrompt）→ 新图
                       └─ both     → 先套参数（即时可见）再生成
电脑（现有后端，结构不动）
 ├─ 新增一个接口   POST /api/wx-login（微信静默登录，见 §6）
 └─ 复用           /api/route · /api/edit · /api/suggest（需登录，静默登录给身份）
```

### 3.1 目录与「共用哪一份」

新建 `mini/`，与电脑版并排。**不搞 monorepo 搬家**（目录结构不动 —— 最简原则，
别为「以后可能要」提前动架子）；电脑版只做一处小抽取：uniform 映射搬成独立文件（见下表与后文）。

| 东西 | 谁的家 | 小程序怎么用 |
|---|---|---|
| `Adjustments` 15 参数 + `toUnit`（`shared/adjustments.ts`） | 电脑版为源 | 同步拷贝 |
| 预设 12 个（`src/core/presets.ts`） | 电脑版为源 | 同步拷贝 |
| GLSL 着色器（`src/render/shader.ts`） | 电脑版为源 | 同步拷贝 |
| uniform 映射（从 `pipeline.ts` 的 `render()` 里**抽出来**成 `src/render/uniforms.ts`，纯函数） | 电脑版为源 | 同步拷贝 |
| 尺寸逻辑（`shared/size.ts`：2048 上限 / 32 倍数 / fitWithin） | 电脑版为源 | 同步拷贝 |
| 渲染的**平台三件事**：canvas 拿取 / 纹理上传 / 导出 | 各写各的 | mini 自己写 |
| 界面、页面逻辑 | 各写各的 | mini 自己写 |

**同步机制**：`scripts/sync-mini-shared.mjs` 把上表「电脑版为源」的文件拷进
`mini/lib/shared/`（保持文件间相对 import 关系），每个文件头加一行
「自动生成，勿改 —— 改 <源头路径>」。脚本带 `--check` 模式（对不上就红），
给以后当守卫用。**不做 npm workspace、不动电脑版 package.json**（红线）。

**为什么 uniform 映射要抽出来**：参数名 → uniform 名的一致性是最容易漂的东西，
而它是纯函数；抽出来后两边共享同一份，同时电脑版改动极小（一个函数搬个家，有测试护航）。
**平台三件事为什么各写各的**：那是真正的平台接口差异（DOM canvas vs 小程序 canvas 节点），
硬凑一层适配反倒更绕 —— 各写各的，但 GLSL、参数、预设、尺寸这些「会漂的部分」一律只有一份。

### 3.2 API 地址

`mini/lib/config.ts` 里一个常量，例如 `http://192.168.1.6:5173`（电脑的局域网 IP + vite 端口）。
- 为什么是 5173：后端**只听 127.0.0.1**（`server/index.ts`，安全审计的取舍，不动它）；
  vite dev 服务器 `host: true` 且 `/api` 原样代理到后端 —— 手机走 `电脑IP:5173` 就能到。
  防火墙 5173 的规则已有现成脚本（`手机调试-开防火墙.cmd`）。
- ⚠️ 已知并接受：vite 代理会把**全部** API 暴露给同一 WiFi（2026-10-02 审计实测过这件事，
  手机调试是有意开着的）。自己用阶段保持现状。
- 换网络（家里/公司）要改这个常量 —— 写在 README（小程序版）里。
- 以后上云：把这一个常量改成云端地址，别的什么都不用动。

## 4. 界面（布局已确认 = 标准编辑器）

一个页面（无路由），三态：**空态 / 编辑态 / 生成中（蒙层）**。

### 4.1 空态（第一眼）

- 居中：小皇帝标 + 「PinkRose」+ 一句话；下面**两颗大按钮**：
  **「拍一张」**（`wx.chooseMedia` sourceType 只给 camera）、**「从相册选」**（只给 album）。
  两个按钮而不是一个合并选择器 —— 「户外快速」省一次点击。
- 法律兜底：第一次进来**不需要登录**、不问任何信息（《必要个人信息范围规定》
  第（三十六）项：拍摄美化类基本功能无须个人信息 —— `2026-10-01-signup-funnel-design.md` §3.1）。

### 4.2 编辑态（布局 A）

```
┌──────────────────────┐
│ ‹换一张      PinkRose   保存 │   ← 顶栏
├──────────────────────┤
│                      │
│        照 片          │   ← 一张干净的舞台（黑底居中，本地实时渲染）
│     （按住看原图）      │
│                      │
├──────────────────────┤
│ ▢原图 ▢日系 ▢胶片 ▢…  │   ← 风格栏：横滑，点一下秒变
├──────────────────────┤
│ 💬 说一句,比如「把路人去掉」 │   ← 说一句入口
└──────────────────────┘
```

- **顶栏**：左「换一张」（回空态，一切归零）；中「PinkRose」；右「保存」。
- **照片区**：本地渲染；**按住看原图**（电脑版同款手势：按住 0.15 秒起算，沿用其约定）。
- **风格栏**：横滑（scroll-view scroll-x），格子 = 缩略图 + 名字。
  内容 = 电脑版**同一份 12 个预设**（日系通透/胶片/黄昏/通透提亮/暗调氛围/鲜艳/
  黑白/青橙/奶油/冷调/复古/硬朗）+ 打头的「原图」，共 13 格。
  - 点亮判据沿用电脑版契约：**全等**才亮；点「原图」= 参数归零。
  - 缩略图**真渲染**（不是 CSS filter 近似 —— 电脑版为「小图和大图不一致」追过三次）：
    照片载入时用一个离屏画布把 13 格渲染成**一张拼图**，`canvasToTempFilePath` 存一张
    sprite 图，格子用 `background-position` 切 —— 避免 13 个 canvas 节点（小程序里
    原生组件多了会卡）。缩略图只依赖**照片 × 预设**，与当前参数无关，载入时渲染一次即可。
- **说一句**：一颗输入条。点击 → 微信键盘 → 打字（也可用微信键盘自带语音）→ 发送箭头。
  - placeholder 给例子（「说一句，比如『把路人去掉』」）。
  - 发送后：缩图 640 → `/api/route`（带当前 15 参数）→ 按决策分流：
    - `params`：本地套参数（瞬时见效）；**模型那句话**（`reply`）以**一条浮条**显示在
      输入条上方，几秒后淡出（没有对话区，但「它听懂没有」要让人看得见）。
    - `generate`：进生成中（§4.3）；`both`：先套参数再生成。
    - `degraded`（后端没听懂、赌了一把）：浮条换成提醒话术（按后端已有文案口径）。
  - 路由调用的等待（1.3~1.6s）不弹蒙层 —— 输入条自身显示「在想…」。

### 4.3 生成中 / 完成

- **生成中**：照片上蒙层（暗化 + 转圈 + **真实秒数**「正在修… N 秒」+ **「停止」**）。
  秒表与停止键沿用电脑版契约（5 秒内不显示秒数、停止掐断连接）。
- **完成**：**直接换上新图** + 照片右下角一颗「**撤销**」（回生成前的画面和参数），
  不弹确认、不切页（已确认的方案）。撤销只有一层、只对生成有意义（点错风格点「原图」就回去了）。

### 4.4 保存

- 右上「保存」→ **全尺寸渲染**（离屏画布，见 §5.3）→ `canvasToTempFilePath` →
  `wx.saveImageToPhotosAlbum`。
- 首次会弹系统相册授权；被拒绝过 → 引导到 `wx.openSetting`（文案给一句人话）。
- 成功 toast「已存到相册」；失败给可重试的提示。

## 5. 核心流程的数据流

### 5.1 选照片 → 预览

`wx.chooseMedia`（原图）→ 临时文件 → `canvas.createImage()` 加载 →
主图纹理 → 按屏幕尺寸渲染。**预览用全图纹理**（探针说 16384 够，手机照片 4000×3000
远在限内），保持「所见即所得」；⚠️ 内存吃紧的机型兜底：预览纹理降级到长边 ~2400（后手，
真机测过再决定要不要启用）。

### 5.2 挑风格 / 说一句 → 本地渲染

点风格 = 预设 15 参数**整组赋值**（没写到的参数归零 —— 和电脑版同一条契约）；
渲染 = 移植的 `TonePipeline.render(Adjustments, lutAmount)`：参数先过 `toUnit`，
再逐 uniform 设置（`uniforms.ts` 共享那份映射），`drawArrays`。

### 5.3 保存/导出（全尺寸）

预览画布是屏幕大小，导出要另起一个**全尺寸离屏画布**：
- 尺寸 = 原始照片（受小程序画布上限约束，用共享的 `limits` 逻辑判断；16384 下基本不触发）。
- 用**全图纹理** + 当前参数渲染 → `canvasToTempFilePath`（PNG 还是 JPG？—— 照片用
  **JPG 高质量**省空间；实现时对比后定）→ 写相册。
- ⚠️ 12MP 全幅渲染的峰值内存是这个模块最大的风险 —— M3 真机量（见 §10）。

## 6. 后端改动（全部改动就这些）

### 6.1 新增 `POST /api/wx-login`

- 入参 `{ code }`（小程序 `wx.login` 拿的）→ 服务端拿 AppID + **AppSecret**
  调微信 `jscode2session` → openid → 找/建账号 → 发与现有登录**同一套**的 token。
- 账号存储：现有账号表加 `wechat_openid` 字段（一个 openid 对一个账号）。
- AppSecret 放 `.env`（⚠️ .env 是红线文件：不看不外传，实现时由用户从微信后台复制进去）。
- 复用现有的限流/验签/错误口径，不新发明。

### 6.2 静默登录的时机（无感）

小程序**启动后**静默 `wx.login` → 换 token 存本地（storage）。用户全程无感知：
没有登录页、没有授权弹窗（`wx.login` 拿 code 本身不弹窗；头像昵称第一版不要）。
token 失败/过期 → 下一次「说一句」前重试；还不行就在浮条上说一句人话。
**挑风格完全不需要身份**（纯本地）—— 注册墙在这里是不存在的，法律那条自然满足。

### 6.3 不用动的

- 监听地址（127.0.0.1）、hostGuard、限流、日额度、两个模型通道 —— 全部复用。
- 流量的身份：`user.id` 从 token 来 —— 微信登录进来的用户和电脑版用户同一张表，
  「以后小程序的一切都站在这套账号上」（2026-09-24 章程）。

## 7. 视觉语言

- **深色**（沿用电脑版 App 内页的拍板）：手机修图产品全行业深色，理由同电脑版
  10-03 那次 —— 界面不干扰对照片颜色的判断；而且和电脑版是一个品牌。
- **令牌**：`mini/app.wxss` 顶部手写的 `page { --… }` 镜像 `src/styles.css` 的一小份
  （强调色/中性档/圆角/间距；注释写明来源行）。不搞构建转换系统 —— 就一个小程序，最简原则。
- **字体**：MiSans 全量 4.6MB 进不了小程序主包（限 2MB）。方案：**界面固定文案
  （按钮/风格名/标题）用 MiSans 子集**（fonttools 子集化，几 KB~几十 KB）；
  动态内容（用户输入、模型回话）用系统字体 —— 避免「子集外的字变豆腐块」。
  「PinkRose」字标（Playfair 子集 woff2，1.8KB）+ 小皇帝徽章版标
  （`emperor-badge.svg`，§8 记忆：底不确定用徽章版）进主包。
- **文案**：本设计的界面文案是初稿；**实现前过一遍 `docs/文案规范.md`**（硬规矩：
  两张脸的语域、词表）。已知口径：叫「保存」（小程序存的是相册，不是电脑版的「存进作品」）；
  「换一张」「说一句」「按住看原图」沿用电脑版已有词汇。

## 8. 测试与验收

三层，缺一不可：

1. **共享文件的单测**：源头在电脑版仓库，`npm test` 照常守护（`uniforms.ts` 抽出时
   同步把 pipeline 的现有测试补上）。**mini 侧不重复建 vitest** —— 页面里几乎全是胶水。
2. **冒烟（微信开发者工具 + miniprogram-automator，探针验证过的路径）**：
   - 页面藏一个**仅开发版可见**的「加载测试图」通道（绕开系统选图弹窗，给自动化用）。
   - 冒烟脚本：加载测试图 → 点每档风格 → 每档**截图 + 数颜色** ——
     ⚠️ **这就是 GLSL 全黑哨兵**：小程序里着色器编不过同样是「每张照片全黑」，
     typecheck/构建/单测**四样全瞎**（电脑版 2026-10-05 真机抓过一次），
     这条探针必须有。风格切档之间要有**差异**（对照组思路：相邻两档颜色分布不同才算真在干活）。
   - 说一句那条路用一个 mock 后端（不进真钱）验数据流。
3. **真机验收（手动清单，用户参与）**：拍照进、相册进、风格秒出、按住对比、说一句出图、
   保存进相册、30 秒线实测。**关键结论只认真机**（探针教训：模拟器跑在电脑显卡上，
   和手机结论可以不一样，实测已经不一样过）。

每个里程碑的完成标准 = `npm test` + `npm run typecheck` 两绿（电脑版仓库）+ 上面相关层级的证据。

## 9. 第一版不做（范围锁定，别吵）

登录页/账号页/作品集/裁剪/点修/调色面板（15 个滑块）/LUT 导入/我的预设/对话记录/
「帮我想想」/多步历史（只有一层撤销）/分享卡片/小程序发布上线（类目、隐私指引、备案域名
—— 等要给外人用时再说）。

## 10. 风险与未知（如实记）

| 风险 | 什么时候验 | 兜底 |
|---|---|---|
| **1281 之谜**（1536×2048 上传报错） | M2 第一步 | 缩图路径已验证可用 |
