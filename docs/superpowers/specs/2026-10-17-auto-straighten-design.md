# 自动水平（设计）— 2026-10-17

## 0. 一句话

裁剪第二行新增「自动水平」：本地量出画面里最长的近水平边（地平线、海平面、
桌面），把「水平矫正」一次拨到对应角度。找不到可信的线就明确提示手动拖，
不硬猜。不调用模型、不写像素，用户仍可继续微调或取消。

## 1. 为什么是它

Lightroom / Snapseed / 醒图 / 美图秀秀都把「自动水平 / Auto Upright」放在裁剪里，
是旅拍和建筑照最常用的几何修正入口。现有裁剪已经有「水平矫正」滑杆，
缺的是**从画面自己读出该拨多少**这一步。

## 2. 算法

纯函数在 `src/core/horizon.ts`，像素入口在 `src/image/straighten.ts`：

1. 底图缩到长边 480 的灰度图，走 3×3 均值模糊；
2. 每列找「竖直梯度最强、且明显强于水平梯度」的点（`|gy| >= 1.5|gx|`）——
   那是这一列最像水平边的位置；竖线和 45° 斜线在这里被排除；
3. 对每列的点做 RANSAC：任取两点算斜率，统计落在同一条直线附近的列数。
   地平线会跨大量列对齐，窗框 / 树叶这类短边凑不出这么多列；
4. 用内点做加权最小二乘，得到亚像素斜率；输出角度限制在 ±15°，
   与「水平矫正」滑杆范围一致；
5. 可信线不足画面宽度 10% 时返回 `null`，界面提示手动拖。

方向约定与 `CropSpec.angle` 一致：正数 = 直线向右下斜，也 = 照片在输出里
逆时针转。预览的 CSS 仍是 `rotate(-angle)`。

## 3. 界面与交互

- 裁剪第二行新增「自动水平」按钮；
- 点击后只改 `spec.angle`，按 0.5° 档落值，框跟着重置成居中的最大内接矩形；
- 找不到可信线：顶部通报「没找到明显的水平线，手动拖一下「水平矫正」。」；
- 仍走原有裁剪链路：用户点「完成」才写进当前底图、记一笔账；「取消」什么都不发生；
- 不新增参数、不影响参数 / 滤镜 / 会话 / 作品配方。

## 4. 验证

- `core/horizon.test.ts`：0° / +5° / -7° / 12°、纯灰、噪点、竖线、45° 斜线、
  非法输入，共 8 条；
- `App.tools.test.tsx`：找到 4.2° → 拨到 4°；返回 null → 角度不动并提示；
- 真实浏览器：上传 1200×800、6° 倾斜的地平线，点「自动水平」后
  水平矫正 = 6°、canvas transform = `rotate(-6deg)`，控制台无错误；
- `npm test`、`npm run typecheck`、`npm run check:layout`、`npm run check:copy`、
  `npm run build`。
