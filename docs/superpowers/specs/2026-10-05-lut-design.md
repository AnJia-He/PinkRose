# 滤镜（LUT 导入与使用）设计（2026-10-05）

> 用户原话：**「在设置里面添加 Lut 文件的导入装置，可以在微调区和对话区能够被调用」**。
>
> 当场拍板的三件（本文照办）：
> 1. 对话区**说话 + 选择器两个都要**；
> 2. 管理界面**单独开一页**（像「模型」那样，从个人设置点进去）；
> 3. 删滤镜**先讲清代价再删**（删之前告诉用户还有几条老会话在用它）。
>
> 本文是**设计**，不是实现。实施计划另出（`docs/superpowers/plans/`）。
>
> ★ **2026-10-05 当天晚些的全站改名**：用户拍板「**全都叫 Lut**」（左栏那一格 /
> 调色面板那一栏 / 对话输入框加号里那一项 / 个人设置里那一行 / 设置里那一页的
> 标题）。本文下面凡是**引号里那句用户看得到的字**，都以这句为准 —— 表里的文案
> 已经跟着改过了，narrative 里的"滤镜"是**这个概念**的中文说法，不必逐字替换。

## 0. 一句话

用户把 `.cube` 文件从设置里导进来，之后**两个地方能用**：微调区点缩略图选、对话区
说话叫。它是调色的**最后一道工序** —— 所有滑块调完再套滤镜，和原图按强度混合。

## 1. 依据（为什么现在做、为什么这么做）

1. **设计早就写好了**：`2026-09-24-accounts-and-gallery-design.md` **§8.2** 整节就是
   LUT —— `.cube` 解析、`TEXTURE_3D`、强度 0–100、**"放管线最后且上线后不能改"**、
   存服务器、名字默认取文件名、§8.3 的呈现（缩略图用当前这张照片渲染、
   常驻只占一行）。本文**照 §8.2/§8.3 落地**，只补它们没定的部分（设置里的位置、
   对话怎么调、删除语义、接口形状）。
2. **它一直排着队**：`2026-10-04-adjust-pro-panel-design.md` §2.2 把 LUT 排进
   "第二批"（曲线之后），§2.3 写着"明确不做"。这一轮就是那一笔账。
3. **LUT 是这类产品的标配**（2026-10-04 的行业调研：八家修图产品里，
   它是"专业向多出来的一类"里出现面最广的之一）。用户导入自己收藏的滤镜，
   是"用户带自己的素材进来"这一类（和 §7 模型接入同一个性质）。
4. **不改任何既有行为**：十五根滑块、老参数、照调（`colorMatch`）、路由协议里
   能少动就少动（见 §7 的兼容写法）。

## 2. 范围

### 2.1 这一批做

| # | 做什么 |
|---|---|
| 1 | `.cube` 解析（3D）：纯函数，前后端共用，服务端**为准** |
| 2 | 服务端存：新表 + 五个接口（列 / 导入 / 取文件 / 改名 / 删）+ 删除前的用量查询 |
| 3 | 渲染：`TEXTURE_3D` + 三线性查表 + 强度混合，**排在管线最后** |
| 4 | 设置里新一页「滤镜」：导入按钮 + 列表（改名 / 删除） |
| 5 | 微调区：「滤镜」一栏（收着的），点开 = **用当前照片渲染的缩略图格子** + 强度滑块 |
| 6 | 对话区：说「用那个黄昏滤镜」能认；输入框上面那颗「滤镜」按钮点开同一套格子 |
| 7 | 存进会话每一步、作品配方；刷新 / 重开有记忆；套配方能连滤镜一起套 |

### 2.2 明确不做（这一批）

- **预设**（§8.1 的"存一套滑块参数"）—— 另一件事，这次不碰。
- **1D LUT**（`LUT_1D_SIZE`）—— 见 §6.3 的错误文案；真遇到再加。
- 别的 LUT 格式（`.3dl` / `.look` / `.cub`）—— 只认 `.cube`。
- AI 建议卡片里出现滤镜（卡片只给滑块增量，不动）。
- 用户手动调"外观/顺序"之类的东西；管线顺序是契约（§4.1）。

## 3. 数据模型

### 3.1 三样东西，名字不许混

| 名字 | 是什么 | 住哪 |
|---|---|---|
| `Cube` | **解析好的颜色表**（`size` + `n³×4` 的字节 + domain） | 只在内存里（客户端渲染、服务端校验） |
| `LutMeta` | 服务器上一条滤镜的元数据（id / 名字 / 级数 / 字节 / 时间） | 接口回给客户端 |
| `LutRef` | **这张图正用着哪个滤镜、强度多少** —— `{ lutId, amount }` | 会话每一步、作品的配方 |

`amount` 是 **0–100 的整数**（和现有一切参数同一个量纲习惯）；**选中默认 100**；
**0 = 关**（效果为零，和没套逐像素一致）。

### 3.2 ★ `LutRef` **不进 `Adjustments`**

`Adjustments` 是"十五个数字"的那个 record，被 `toUnit` / `PARAM_KEYS` / `PARAM_RANGE` /
`server/prompt.ts` / 照调的归零逻辑一路消费。LUT 是**一个引用**（还带一个 id），
塞进去会让那五处全部要处理"这一格不是数字"。

所以：**`LutRef` 是一个独立的并列字段，哪儿都跟着 `params` 一起走**
（会话快照、会话补丁、作品配方）。这也正好对上 §8.2 那句
「八参数调的是原图，LUT 再统一染一遍」—— 管线里是两道，数据上也是两份。

### 3.3 `.cube` 解析（`shared/lut.ts`，纯函数）

```
输入：文本。输出：{ size, rgba: Uint8Array(n³×4), domainMin, domainMax, title? }
```

| 认什么 | 规则 |
|---|---|
| `#` 开头 | 注释，跳过；空行跳过；CRLF 容忍 |
| `TITLE "…"` | 可选 → 当**默认名字**（没有就用文件名） |
| `LUT_3D_SIZE n` | **必须有**；`n` 只许 **2–64** |
| `LUT_1D_SIZE` | 出现即拒（文案见 §6.3） |
| `DOMAIN_MIN/MAX r g b` | 可选，默认 0 / 1；**照收**，进 shader 当 uniform（不做归一化烘焙） |
| 数据行 | `r g b` 三个浮点，**红变最快**（Iridas 规范）；条数必须恰好 `n³` |

- 数值超出 `[0,1]` 一点点（±0.001）**钳掉**，超多了报"第 N 行数值超出范围"。
- 8 bit 量化后进纹理（`RGBA8` + 三线性）—— 这是通行做法，见 §10 的取舍。
- 错误一律是**一句给用户的中文**（带行号/原因），不是英文异常。

**同一个解析器两边都用**：客户端导入前先解一遍（即时反馈）；服务端**再解一遍**
（不信前端，客户端只是体验）。

### 3.4 各处的存储

| 存哪 | 形状 | 备注 |
|---|---|---|
| 会话的**每一步** | `SessionStep.lut?: LutRef \| null` | 老数据没这个键 → 当 null |
| 会话补丁（"现在这一版"） | `SessionPatch.lut?: LutRef \| null` | 和 `params` 同一条路：服务端把它写进**最后一步**（sessions.ts 既有写法） |
| 作品配方 | `Recipe.lut: { name, amount } \| null` | **只存名字不存 id**：作品的图已经烤好了，id 没有渲染作用；套用时按**名字**去找还在不在 |
| 老数据 | 全部当 null | 不迁移、不炸（`readRecipe` / 步骤解析各加一条归一化） |

`LutRef` 的归一化（服务端与客户端各有一处，逻辑一致）：id 必须是**这个人的**、
存在的；amount 取整钳到 0–100；认不出来就 **null**。

**换一张照片 = 重新开始**：上传新照片 / 「新的一张」时，滤镜和十五根滑块一起清掉
（`resetEditor` 那一处）——它是"这张图"的状态，不是全局设置。

## 4. 渲染

### 4.1 管线位置（**契约，上线后不能改**）

```
0 清晰度（最前，原注释有理由）
1 色温 → 1.5 色彩平衡 → 2 曝光 → 3 高光/阴影 → 4 对比度 → 5 饱和度
→ 5.5 自然饱和度 → 6.5 分离色调 → 6 暗角
→ ★ 7 LUT → clamp → 出图
```

- **为什么在暗角之后**：§8.2 那句"放最后"——"所有参数调完，滤镜统一染一遍"。
  暗角是"参数那一半"的最后一件事，LUT 排在整条链的最后。
- **改了会怎样**（写给以后的人）：所有作品都是这条管线算出来的，**挪顺序 =
  所有老图点开时颜色都变**。这条写在 shader 那一行注释里。

### 4.2 查表与强度

```glsl
if (uLutAmount > 0.0) {                     // uLutAmount = uLutOn * amount
  vec3 q = clamp(c, 0.0, 1.0);
  vec3 t = clamp((q - uLutDomainMin) / max(uLutDomainMax - uLutDomainMin, vec3(1e-6)), 0.0, 1.0);
  c = mix(q, texture(uLut, t).rgb, uLutAmount);
}
```

- `sampler3D`（WebGL2 原生）；纹理 `RGBA8` + `LINEAR` + 三轴 `CLAMP_TO_EDGE`。
- 上传顺序 = `x 红最快`，和 `texture(uLut, vec3(r,g,b))` 的取样方向对得上（§9 有探针钉它）。
- `uLutOn` 是**管线自己算的**（装着 cube = 1，没装 = 0）——调用方给不出矛盾状态。
- **没装滤镜时也必须绑一个 1×1×1 的占位 3D 纹理**（构造函数里建），
  免得采样落在"没有纹理"的未定义状态上。
- 强度 0 走 `mix(..., 0.0)` → 输出 = `clamp(c)`，**和没有这一段逐像素一致**（测试钉住）。

**CPU 对照实现**（`src/core/lut.ts`，和 `tone.ts` 对 `shader.ts` 那条规矩一样）：
同一个查表 + 混合 + 插值的 TypeScript 版本，给单测用 —— "强度 0 不变"和"顺序挪前必红"
这两条**必须在没有 GPU 的测试里也能钉住**，shader 那边靠 §9.2 的真机探针复核。

### 4.3 客户端 API（`TonePipeline`）

- `setLut(cube: Cube | null)`：建/换 `TEXTURE_3D`（旧的删掉），记下 size 与 domain。
- `render(params, lutAmount = 0)`：**amount 由调用方给、cube 由 `setLut` 给** ——
  两个来源分开，是为了"换了 cube 忘了换 amount"这种错一眼看得出来。
- `Canvas` 多加两个 prop：`lutCube`、`lutAmount`；沿用既有的两条 effect 分法
  （换图才传纹理 / 其余只改 uniform）。

### 4.4 缩略图预览（§8.3 的落点）

- **用当前这张照片渲染**：先把照片缩到长边 ~256（一次），再对每个滤镜各画一张，
  裁成方形（`drawImage` cover），转 dataURL。
- 触发时机：**打开格子时、换照片时、参数变了（防抖 ~200ms，仅在格子开着时）**。
  纹理按滤镜 id 缓存在预览器里，重画只是重绘 + 读回。
- 数量上限 30（和导入上限同一个数）——最坏情况下一屏 30 张 132px 小图。

## 5. 三处界面

**清单什么时候拉**（三个入口都要它）：App 登录后拉一次；**离开 `/app/luts` 那一页时
再拉一次**（刚导入的立刻能用、删掉的立刻消失）；拉完之后对着镜子照一下 ——
**当前用的滤镜要是不在清单里了，清掉它并说一句**（§6.4 客户端那半）。

### 5.1 设置里新一页「滤镜」

- `View` 多一支 `{ kind: 'luts' }`，路径 **`/app/luts`**（F5 / 收藏 / 转发都要认，
  见 `view.ts` 的老规矩）。
- 「个人设置」多第 4 格 **「Lut」**：一行「Lut」→ 右边写 **N 个**（拿不到就整格不出现，
  沿用「模型」那一行的规矩）→ 点进去。
- 新页 `src/ui/LutSettings.tsx`（照 `ModelSettings.tsx` 的骨架）：
  - 顶上说明一句 + 一颗 **「导入 .cube」**（原生 `<input type=file accept=".cube">`）；
  - 列表一行一个：**名字 · 33 级 · 240 KB** + 「改名」「删除」；
  - 空态：「还没有导入过 Lut。」
  - 导入中 / 失败 / 成功**都要说话**（成功不弹窗，列表里直接多一行）。
- 改名：就地展开一个输入框（照「改密码」那一段的形状），重名给一句明确的话。
- 删除：**先取一次用量**（§6.2），确认块里写清算什么 ——
  有会话在用 → 「还有 2 条老会话在用这个 Lut。删了之后，它们再打开会变回没有 Lut 的样子。」；
  没人用 → 「删了就找不回来了。」

### 5.2 微调区（`AdjustmentPanel`）

- 位置：预设药丸 + 「放置预期效果照片」之下、滑块分组之上。
- 形态：**和滑块组同一个语言**（一行标题 + 折叠），标题就两个字 **「Lut」**，
  **默认收着**（§8.3："常驻只占一个按钮"）；有滤镜在用的时候标题点亮
  （和滑块"动过"同一个 `on` 待遇）。
- 展开后：**缩略图格子**（每格是当前照片 + 当前参数 + 那个滤镜渲染出来的），
  第一格是 **「不用」**；选中的那格有选中框。下面一条 **强度** 滑块（`kit/Slider`），
  只有选中了才出现。
- 一个滤镜都没有时：一句「还没有导入过 Lut。」+ 一颗 **「去导入」**（跳到 `/app/luts`）。

### 5.3 对话区（`ChatPanel`）

- 输入框上面多一颗药丸按钮 **「滤镜」**（`aria-expanded`），点开就地展开
  **同一套格子**（同一个组件，两处长得一样 —— 和"主按钮只有一份"同一条规矩）。
- 说话那条路走 §7。

## 6. 服务端

### 6.1 表与接口

```sql
-- 迁移 6
CREATE TABLE luts (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name        TEXT    NOT NULL COLLATE NOCASE,
  stored_name TEXT    NOT NULL,
  size        INTEGER NOT NULL,   -- n（2–64）
  bytes       INTEGER NOT NULL,
  created_at  INTEGER NOT NULL,
  UNIQUE(user_id, name)
);
CREATE INDEX luts_user ON luts(user_id);
```

| 接口 | 说明 |
|---|---|
| `GET /api/luts` | `{ luts: LutMeta[] }`（新的在前） |
| `POST /api/luts` | `{ name?, cube: string }` → 服务端解析、限额、存文件 + 行 |
| `GET /api/luts/:id/file` | **原文**（`text/plain; charset=utf-8`）—— 客户端拿去解析渲染 |
| `GET /api/luts/:id/usage` | `{ sessions: number }` —— **有几条会话的某一步正用着它**（逐条解析 steps 数出来，不是 SQL 模糊匹配）。删除前那句话的唯一依据 |
| `PATCH /api/luts/:id` | `{ name }` |
| `DELETE /api/luts/:id` | 删行 + 删文件 + **清掉引用**（见 6.4） |

- 全部**要登录**，认人 → 读体 → 干活，和现有接口同一个顺序。
- 文件层复用 `storage.ts`（**名字由它发、路径它自己拼**），根目录
  **`data/luts`**（`config.lutDir`，和 `photoDir` 同一套规矩）——
  和照片分开放，两边的文件就不会混在一个目录里。
- 注销账号：`handleDeleteAccount` 把滤镜文件**也一起删**（行随 `ON DELETE CASCADE`）。

### 6.2 量与限额

| 项 | 数 | 为什么 |
|---|---|---|
| 单个文件 | ≤ **8 MB** | 64 级、六位小数约 6.5 MB，留一点余量 |
| 每人条数 | ≤ **30** | 和 §8.1"发给模型的预设上限 30"同一个数；也是缩略图格子的上限 |
| 级数 `n` | 2–64 | 常见的 16/25/32/33/64 全在里头；再大就拒，文案说清 |
| 名字 | 1–30 字符，先 trim | 界面上要显示、对话里要认 |
| 计不计配额 | **计**（`storedBytes` 加上 luts） | 它是用户的文件、睡在同一块盘上；满了的文案单独一句（"先去作品集删几张，再导入新的滤镜"） |

### 6.3 报错文案（用户看到的那几句，定死）

| 情况 | 那句话 |
|---|---|
| 不是 `.cube` | 「这个文件不是 .cube 格式的。」 |
| 1D | 「这是 1D 的 Lut，暂时只支持 3D 的（常见的都是 3D）。」 |
| 级数超限 | 「这个 Lut 是 128 级的，太大了 —— 目前支持 64 级以内。」 |
| 某一行不对（不是三个数 / 数值越界） | 「这个文件读不出来（第 N 行的数据不对），可能下载的时候坏了。」 |
| 行数不对（文件被截断 / 拼接） | 「这个文件读不出来（应该有 N 行数据，实际读到 M 行），可能下载的时候坏了。」 |
| 文件太大 | 「这个文件超过 8 MB 了。」 |
| 重名 | 「已经有一个叫「黄昏」的 Lut 了，换个名字。」 |
| 条数满 | 「最多 30 个 Lut，先删掉几个再导入。」 |
| 空间满 | 「空间满了（5 GB）。先去作品集删几张，再导入新的 Lut。」 |

### 6.4 删除（用户拍板的语义）

1. 前端先 `GET .../usage`，把代价**写在确认块里**；
2. 用户确认 → `DELETE`；
3. 服务端：删行 → 删文件 → **把这个人所有会话每一步里指向它的 `lut` 清成 null**
   （不留悬空引用）；
4. **作品不受影响**：作品存的是已经烤好的图；配方里保留**名字**当历史
   （"当时用的是「黄昏」"是真话）。

**防悬空的第二道闸**：会话（PUT）和作品（POST/PUT）写入时，服务端把
**认不出来的 `LutRef` 一律清成 null**（和"文件名必须在名单里"同一路的纵深防御）——
这样客户端就算拿着过期的 id 再存一次，也进不了库。

客户端那半：App 发现"当前用的滤镜没了"（列表刷新后找不到）时，清掉状态 +
**说一句**「那个滤镜刚被你删掉了，这张照片上的也去掉了。」

## 7. 对话那条路

### 7.1 协议（`shared/protocol.ts`）

```ts
// 请求：把用户的滤镜清单带上（客户端裁到 30 条）
RouteRequest.luts?: { id: number; name: string }[]

// 响应：模型要动的滤镜
RouteDecision.lut: { name: string; amount: number } | null
//   null      = 这次不碰滤镜
//   name === '' = 把当前的摘掉（amount 无意义，服务端归 0）
//   有名字     = 套上（amount 缺省 100）
```

### 7.2 提示词（`server/prompt.ts`）

- 用户消息里多两行：
  - 「用户导入的滤镜有：黄昏、胶片黑白。」（没有就不写）
  - 「用户当前已用滤镜：黄昏（80%）。」（没用就不写）
- system 里写死三条：**只能用列表里的名字**；「不要滤镜了 / 摘掉」→ `"lut": {"name": ""}`；
  和调色一样，套滤镜**不算生成**（不需要 edit_prompt）。

### 7.3 判定与兜底（`server/validate.ts`）

- `normalizeLut(raw, lutNames)`：取整钳 0–100；名字 trim；**不在清单里的名字 → 归 null
  并把 `degraded` 置 true**（模型给了个我们没有的东西，信号要留）；
  客户端传来的清单为空时，任何名字都不认。
- **"只调滤镜"是合法的纯本地动作**：`route` 归 `params`，
  不能落进"什么都没解出来 → 走降级去花钱"那条路（既有那几条判据要跟着放宽一格）。
- `reconcile` 里把"有 lut"和"有 params"**并成一类**（都是本地、零成本那半）。

### 7.4 客户端落地（`useGeneration.applyDecision`）

| 决策 | 做什么 |
|---|---|
| `lut === null` | 不动 |
| `name === ''` | `setLut(null)` |
| 有名字 | 在本地清单里找（trim + 忽略大小写）→ `setLut({ lutId, amount })`；找不到就不动 + `console.warn`（服务端已按同一份清单验过，正常到不了这儿） |

- 套滤镜**不推快照**（和拖滑块同级，裁定 ⑤）；但**这一版的状态要落盘**
  （`SessionPatch.lut`，和 `params` 同路）。
- 助手那句回复由模型自己写（"好，给你加上「黄昏」"）。

### 9.2 真机探针（Playwright，真 GPU）

1. **零值等价**：同一张图、同一组参数，`no LUT` 与 `identity LUT + 强度 0` 的画布
   像素**逐字节相同**；把强度改成 100 → 必须不同（变异验证这条断言能红）。
2. **方向正确**：一个"红蓝对调"的合成 LUT → 画布上某个已知像素的 R/B 值确实对调了。
3. **三个入口真跑一遍**：设置里导入 → 微调区格子出现缩略图且能选中 → 对话区按钮
   点开同一套格子 → 刷新后状态还在。对话那句话的**路由请求用拦截 stub**（不花真钱），
   只验"请求里带着滤镜清单、响应里的 lut 被应用"。
4. `check:layout` 顺带跑一次新页（⚠️ 它每跑一次注册一个临时号，别连跑）。

## 10. 风险与取舍（都写下来，别以后重新吵）

1. **8 bit 纹理**：`RGBA8` + 三线性是通行做法；极端陡的 LUT 理论上可能出色带。
   真要更好就换 `RGB16F`（显存翻倍、兼容面变小）——**这轮不换**。
2. **查表在 sRGB 空间**：消费级 `.cube` 就是这么被用的（在 0–1 的显示值上查）。
   和"管线顺序"一样属于**契约**：以后换成线性空间查，所有老图会变。
3. **缩略图是"打开那一刻"的参数**：参数在格子开着时又变了，图不会实时跟
   （防抖重画是尽力而为）——它是**比较用的**，不是第二块画布。
4. **删除会让老会话变样**（用户拍板，确认块里说清）：这不是 bug，是硬删的必然代价。
5. **名字是对话唯一的对号方式**：所以名字**不许重**（表上一把 `UNIQUE`），
   而且比对忽略大小写与首尾空格。
6. **`.cube` 是文本**：8 MB 的文本走 JSON（base64 更大）—— 现有 `readJsonBody`
   上限 12 MB 够用，超了就是上面那句人话。
