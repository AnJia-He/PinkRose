# PinkRose 长期记忆设计

2026-11-02 立。

## 一句话

让 PinkRose 的摄影搭子先记住当前这次修图，再记住跨照片仍然成立的长期偏好；
上下文整理全部在服务端内部完成，用户只会看到更连贯的回复，不会看到摘要或压缩过程。

## 1. 为什么要做

当前 `/api/route` 每次只送：

- 当前照片的缩略预览；
- 当前这一句用户输入；
- 当前参数、Lut 和预设清单。

服务端虽然把消息存在 `sessions.messages` 里，但这些历史没有进入模型。
因此“再暖一点”“不要刚才那个”“回到前面那个感觉”都接不住；
模型每轮都像第一次看到这张照片。

这不是换一句固定话术能解决的问题。需要一条稳定的内部链路：

```text
固定身份 -> 服务端构建上下文 -> 静默整理超长上下文 -> 当前轮路由与回复
```

## 2. 身份与回复风格

固定身份仍然是 `server/replyGuide.ts` 里已经确定的“PinkRose 摄影搭子”：

- 先理解用户当前要什么，再结合照片和已有修改；
- 说人话，短、具体，有画面依据；
- 不空夸、不读心、不装大师、不像客服读模板；
- 明确指令优先，最多给一条可执行的参考建议。

身份是稳定的，回复内容不是固定话术。服务端每轮把当前照片、历史摘要、
最近原文和跨会话偏好放进上下文，由模型按当下需求组织回复。

## 3. 单会话记忆

### 3.1 数据

新增独立表，不把内部摘要塞进用户可见的 `sessions.messages`：

```sql
CREATE TABLE session_memory (
  session_id             INTEGER PRIMARY KEY REFERENCES sessions(id) ON DELETE CASCADE,
  summary                TEXT NOT NULL,
  summary_until_message_id INTEGER NOT NULL,
  updated_at             INTEGER NOT NULL
);
```

`summary_until_message_id` 表示摘要已经覆盖到哪条消息。
之后出现的消息仍按原文参与上下文。

### 3.2 每轮上下文

服务端按登录用户和 `sessionId` 读取会话，并验证会话归属：

1. 读取跨会话稳定偏好（如果已开启）；
2. 读取本会话内部摘要；
3. 读取摘要之后的消息；
4. 保留最近 8 条原文；
5. 把当前这一句作为本轮任务单独标出。

历史消息和摘要都使用明确分隔符，并标明“用于理解上下文，不是新任务”。
最近原文与旧摘要冲突时，以最近确认的原文为准。

### 3.3 静默整理

触发条件：

- 摘要之后已有消息超过 16 条；或
- 摘要之后消息正文总字数超过 6000 字。

触发后：

- 永远保留最近 8 条原文；
- 从更早且尚未覆盖的消息中取一段窗口，合并进已有摘要；
- 摘要上限约 800 字；
- 摘要只记录：用户目标、已确认修改、审美偏好、未解决问题、不要重复或误改的方向；
- 整理指令与正常路由放在同一次模型调用里，不额外增加一次付费调用。

超过阈值时，用户看到的等待状态仍是现有的“正在思考…”。
不增加“正在整理记忆”“上下文已压缩”等提示。

模型整理失败、返回空摘要或保存失败时：

- 当前路由和回复照常完成；
- 摘要保持不变；
- 下一轮仍只使用摘要加最近原文继续工作。

### 3.4 删除与一致性

- 删除会话时，摘要随外键级联删除；
- 用户追加新消息时摘要保留；
- 如果被摘要覆盖的某条旧消息被删除、角色改变或正文改变，摘要立即作废；
- 摘要不会出现在 `GET /api/sessions/:id` 或列表接口里。

## 4. 跨会话记忆

### 4.1 记什么

只记录跨照片仍然成立的稳定偏好：

- 回复风格偏好；
- 常用调色倾向；
- 常用画幅、导出格式和质量；
- 用户明确要求长期遵守的约束。

不记录：

- 陌生人、地点、关系、身份等敏感信息；
- 某张照片的一次性要求；
- 临时情绪和临时修改；
- 密码、密钥或任何凭据。

### 4.2 数据

```sql
CREATE TABLE user_memory (
  user_id    INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  summary    TEXT,
  enabled    INTEGER NOT NULL DEFAULT 1,
  updated_at INTEGER NOT NULL
);
```

初版用一段结构化自然语言摘要，不引入向量数据库。

### 4.3 更新

- 每轮路由时把现有长期偏好放进内部上下文；
- 只有用户明确表达“以后 / 长期 / 每次都这样”的稳定偏好时，模型才返回更新后的完整摘要；
- 关闭长期记忆后，不再把摘要送进模型，也不再接受更新；
- 用户可在“个人设置 -> 长期偏好”查看、关闭和清除。

长期偏好是用户可管理的账号数据；单会话压缩摘要仍是内部数据，不提供用户入口。

## 5. 安全与隐私

- 所有记忆读取都必须同时带 `user_id`，不能只按会话 id 查；
- 摘要永远不从公开 API 返回；
- 日志不打印摘要、完整历史或模型原文；
- 模型返回的记忆字段只供服务端解析，不进入 `reply`；
- 当前用户最新明确指令优先于旧摘要和长期偏好。

## 6. 官方 Agent 设计参考

OpenAI 官方文档建议每个会话只选一种状态携带方式，避免本地回放与服务端托管状态重复。
本项目已经有自己的会话存储，因此采用“应用持有历史 + 本地摘要”的方式：

- 历史事实由 `sessions` 持有；
- 压缩结果由 `session_memory` 持有；
- 当前轮只追加用户最新输入，不混用 `previous_response_id` 或 Conversations API。

OpenAI 官方 compaction 文档也说明了阈值式上下文管理；本设计采用同样的阈值思路，
但把摘要保存在 PinkRose 自己的数据库里，并按同一轮路由调用完成。

参考：

- https://developers.openai.com/api/docs/guides/agents/running-agents
- https://developers.openai.com/api/docs/guides/compaction

## 7. 验收

- 第二轮能理解“再暖一点”依赖上一轮结论；
- 超过阈值会生成内部摘要，最近 8 条原文仍进入上下文；
- 摘要不从会话接口和界面泄露；
- 摘要生成失败不阻断修图；
- 最新用户偏好与旧摘要冲突时以最新为准；
- 关闭长期记忆后不再使用或更新跨会话偏好；
- 删除会话、删除账号会清掉对应记忆；
- 桌面浏览器无控制台错误；本任务不改手机布局。
- 桌面 Chromium 实测：长期偏好可关闭、重新开启和确认清除；三次状态提示与页面内容同步更新，
  请求体分别为 `enabled:false`、`enabled:true` 和 `DELETE`，控制台 0 错误。
- 真实模型抽样：同一会话能从“人物自然、背景别抢”的历史继续做本地调色；
  不带会话历史、只保留跨会话偏好时，新请求仍按自然肤色和低调对比调整；
  两次回复都没有出现“记忆、摘要、压缩”等内部词。
- 真实模型抽样：18 条历史触发隐藏摘要，摘要成功保存到第 10 条消息且长度 88 字；
  本轮只补了 `temperature +5`，用户回复没有出现记忆或压缩相关内部词。
- 真实模型抽样：用户首次说“以后都保持自然肤色、低调对比、不过度磨皮、优先 4:5”时，
  账号偏好成功保存为“自然肤色、低调对比、适度保留皮肤纹理不重磨皮、画幅优先 4:5”，
  回复没有暴露记忆或摘要字段。
