# 批量逐张手动取景设计 —— 2026-10-19

## 0. 背景

批量页原来只有两条取景路：按统一画幅居中裁切，或开「智能主体构图」让本地
主体检测移动裁切框。摄影师真实导入一组照片时经常遇到第三种情况：

- 主体不在画面中线，智能检测也没认出（逆光、剪影、小主体）；
- 想故意让主体偏左 / 偏右，给文字或留白腾位置；
- 同一组里只有几张需要重新取景，其余照片继续自动处理。

这一轮补的是「逐张手动取景」：每张照片可以单独拖框、缩放，且手动框优先于
智能主体构图。

## 1. 数据契约

- 新增 `core/batchCrop.ts`，裁切框统一用归一化坐标
  `{ x, y, w, h }`，相对**转向后**的照片。
- `maxCropForAspect` 计算目标比例的最大框；宽高比按像素算，不按归一化方格
  算（否则非正方形照片会裁错比例）。
- `cropAtZoom` 以当前框中心缩放；`moveCropTo` / `moveCropBy` 只平移并钳在
  画面内；`cropPixels` 给 `cropToBitmap` 输出至少 1×1 的整数框。

## 2. 批处理接线

- `BatchExtras.crops?: Record<inputId, BatchCropRect>`。
- 像素层先做方向和翻转，再进入画幅裁切；有手动框的照片直接按手动框裁，
  **不再跑主体检测**；没有手动框的照片仍走 `smartCrop` / 居中。
- 换画幅或换方向会清空所有手动框：旧框的比例和参照系都变了，静默沿用会
  让用户看到一版、导出另一版。

## 3. 界面

- 只有选了非原图画幅，照片列表里才出现「取景」按钮；已取景显示「已取景」。
- 弹层先把方向落到一张预览图上，再让用户框选；预览和导出用同一个转向顺序。
- 交互：拖动框、点画面把框移过去、取景范围 100%~250%、重置、键盘方向键微调，
  Shift 加速。框内画三分线；框外压暗。
- 弹层沿用相机弹层的遮罩 / 面板骨架，390px 和 iPad 宽度下不横向溢出。

## 4. 验证

- `core/batchCrop.test.ts`：比例、缩放、边界钳制、像素换算。
- `batch/process.test.ts`：手动框优先，主体检测一次都不跑。
- `BatchPanel.test.tsx`：只有非原图画幅才出现逐张取景入口。
- 真实 Chromium：两张照片统一 1:1 → 拖框 + 放大到 250% → 应用 → 处理成功
  2 张，其中手动取景那张输出 432×432。
- WebKit 390×844 / 768×1024：取景弹层不横向溢出，应用按钮可达。
