# 短片调色（2026-10-20）

## 要解决什么

照片已经能修、能批量、能打印、能做动图，但用户手机里最多的"要发出去的东西"
其实是十几秒的短片。市面上的修图产品（醒图、美图、Lightroom 视频）都能给
短片套滤镜；这个产品此前只有「照片动图」（把几张照片拼起来），
**不能修一段已经有画面和声音的视频**。

这一版只做"修图"这一件事：

- 导入 MP4 / MOV / M4V / WebM；
- 剪一段或拼最多 6 段，全片合计 0.5–20 秒；每段单独拖起点 / 终点，可调顺序、可删除；
- 选 12 / 24fps；
- 成片画幅：原比例 / 1:1 / 4:5 / 9:16 / 16:9（中心裁切，绝不放大）；
- 原声默认保留，也可以静音导出（不传源片）；
- 可选一段本地背景音乐（32MB 以内）：混合原声或替换原声，音量 0–100，
  音乐比成片短时自动循环；
- 最多 10 条字幕：上 / 中 / 下、三档字号、白 / 黄 / 红，按**全片时间**
  出现和消失，直接烧进画面；
- 预览停住的任意一帧可以「截一帧存作品」；
- 套用和照片完全相同的预设与强度（`core/presets.ts`）；
- **保留原声**，导出 H.264 MP4。

多轨、转场、字幕轨不在这一版范围内（那是剪辑器，不是修图）。

## 关键决定

### 1. 逐帧在浏览器里修，不在服务端复刻一套调色

服务端用 ffmpeg 的 `eq` / `lut3d` 能近似调色，但那是**第二套实现**：
HSL、曲线、分离色调、暗角、颗粒、镜头虚化都要各写一遍，而且和照片的
观感对不上——同一个「胶片」预设，照片一个样、视频另一个样。

所以帧由浏览器渲染，走的是照片同一条 `TonePipeline`（同一个 WebGL 着色器）：
空间类效果（暗角 / 颗粒 / 虚化 / 磨皮）也逐帧真的算进去。

代价是 CPU：20 秒 × 24fps = 480 帧。界面先把帧数、成片尺寸说清楚，
导出中可以取消；这是"能出片"与"像照片"之间选后者。

### 2. 苹果端不用 MediaRecorder

Safari 的 MediaRecorder 在版本和设备之间差异大，容器也未必是 MP4。
这里沿用「照片动图」那条已经验证过的路：**浏览器出帧，本机 Node 用 ffmpeg 编码**。
iPhone / iPad 只要能播放视频，就能导出。

### 3. 原声从源视频接回来

帧只有画面。源片先流式上传到临时会话目录（上限 512MB），
编码时作为第二路输入：`-ss <起点>`（和第一帧同一时刻）+ `-map 1:a:0?` +
`-c:a aac` + `-shortest`。少了那个 `-ss`，画面从第 1 秒开始、声音却从第 0 秒
开始，剪过的片段会音画错位。
没有音轨的源片也不报错（问号），输出明确 `-an`。

多段时每段按自己的起点 `-ss`，音频 `atrim` 到与画面等长后再
`concat=n=N:v=0:a=1`；**没有音轨的段用 `anullsrc` 补等长静音**，
否则后面的声音会整体前移。帧仍然是一条连续的 `frame-%05d.jpg` 序列。

### 4. 会话是临时的

`POST /api/video/session` → `POST /:id/source`（流式）→
`POST /:id/frames`（每批 8 帧）→ `POST /:id/finish` → 直接回 MP4。
会话放在系统临时目录，进程内 Map 记归属；30 分钟没动就删，编码完成 / 取消也删。
重启丢会话没关系：前端拿 404 就重新开一次导出。

### 5. 背景音乐走同一张音频图

音乐作为额外输入（`-stream_loop -1`），先 `atrim` 到成片总长、`volume`
到用户设定的音量，再与原声链 `amix`；替换模式直接把音乐映射成输出音轨。
原声链为多段时是 `concat`，单段时是 `atrim` 后的那一路；
关掉原声但有音乐时，原声侧补 `anullsrc` 静音再混合。

### 6. 字幕烧进画面

字幕不是外挂轨：每一帧渲染完（WebGL）后拷贝到一张 2D 画布，在激活的时间段里
用 `paintCaption` 画上去，再编 JPEG。这样任何播放器、任何平台都能看到字幕，
不依赖播放器的字幕支持。时间轴是**全片时间**：多段拼接时，第二段的第一帧
从第一段的总时长开始算，换顺序 / 剪短都不会让字幕错位。

预览用一层 DOM 覆盖在 `<video>` 上（跟随 `timeupdate`），让用户先看到位置和
样式；成片以烧进画面的像素为准。

### 7. 视频人像：复用照片的肤色门控着色器

短片的人像区有三根滑杆：磨皮 / 美白 / 红润。它们不改底图，只把
`skinSmooth` / `skinBrighten` / `skinRosy` 叠加到当前预设的参数上，
由 photoshop 同一套 shader 的 **Cb/Cr 肤色掩码**控制作用范围：

- 不做人脸检测 —— 每帧都跑检测太慢（480 帧会到分钟级）；
- 肤色掩码是颜色门控，五官边缘靠双边权重保留，背景只要不是肤色就不动；
- 磨皮是 12 抽样的双边平均，强度 100 时仍保留 10% 原始纹理。

实测：肤色半区边缘能量 2.877 → 1.481（磨皮 100），蓝色背景半区
2.814 → 2.809（基本不变）。

## 上限（写在 `shared/video.ts`，前后端同一份）

| 项 | 值 |
| --- | --- |
| 时长 | 0.5–20 秒 |
| 帧率 | 12 / 24 |
| 输出长边 | 1280（宽高都偶数，H.264 yuv420p 要求） |
| 画幅 | 原比例 / 1:1 / 4:5 / 9:16 / 16:9 |
| 单帧 JPEG | 2MB |
| 每批帧数 | 8 |
| 源片 | 512MB |

- `src/video/plan.test.ts`：时间轴、尺寸偶数化；

- 真实 Chromium：3 秒 640×360 源片（含 AAC）→ 成片 640×360 / H.264 + AAC /
  3.000 秒 / 颜色与源片不同。
