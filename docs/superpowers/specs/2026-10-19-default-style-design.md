# 默认风格设计 —— 2026-10-19

## 0. 目标

设置页补上「默认风格」：用户选一套内置预设或「我的预设」，之后**新打开**的照片
从这套风格起手。它服务于两条现实路径：

- 日常多张照片保持同一套出片风格；
- 后续真实相机 / 相机桥自动导入时，每张新照片不用再从零调色。

## 1. 语义

- 只影响**新打开的照片**。设置页改默认风格时，当前正在编辑的照片一个字都不动。
- 恢复旧会话、切换已有照片、从作品详情套配方都不读默认风格。
- 默认风格是「起点」，不是锁定：用户仍可继续拖滑块、换预设或重置。
- 首步历史（「原图」那一格）记的是**套了默认风格之后的参数**，所以点回「原图」
  不会把默认风格丢掉。

## 2. 存储

偏好字段：

```json
{ "style": "portrait" }
```

- 值 = 预设 id。内置 id 是非纯数字串（`portrait` / `film`），「我的预设」是服务端
  数字 id 的字符串形式（`"42"`），两边不会撞。
- 空 / 缺失 / `null` = 不预设（原图起手）。
- **不存整套参数**：预设以后改了参数，用户下次打开新照片会自然跟上。
- 本机 `localStorage` 兜底，键 `pinkrose.defaultStyle`；登录后账号
  `users.prefs.style` 覆盖本机值。网络失败时本机值仍生效，设置页明确说
  「已保存到这台设备」。
- 账号偏好按字段合并保存：保存导出默认值不会冲掉 `style`，保存 `style` 也不会
  冲掉 `export`。

## 3. 解析与失败退路

`app/defaultStyle.ts`：

- `normalizeDefaultStyleId`：只接受 `[A-Za-z0-9_-]`、1–64 字符，其余回 `null`。
- `resolveDefaultStyle(id, mine)`：在 `PRESETS + mine` 里找；找不到（预设被删、
  账号里的旧 id、清单还没到手）回 `null`。
- 找不到时新照片照常打开，参数回 `ZERO` —— 不拿一个坏偏好把照片挡在门外。

## 4. 界面

- 设置页新增「修图偏好」分组，一行「默认风格」下拉：
  - 不预设（原图起手）
  - 内置风格（`optgroup`）
  - 我的预设（`optgroup`）
- 下拉下面一句话说清边界：「只用于下一张新打开的照片；正在编辑的这张不会变。
  相机拍到的新照片也会按它起手。」
- 账号里记的预设已被删除时，下拉如实显示「这套预设已不存在」，不静默变成
  「不预设」。

## 5. 测试

- `app/defaultStyle.test.ts`：id 归一化、本机读写、内置 / 我的预设解析、坏 id 回 null。
- `App.account.test.tsx`：
  - 选内置预设 → PATCH `/api/me` 的 `preferences.style`、写本机；
  - 下一张新照片参数等于该预设；
  - 改设置不改变当前照片；
  - 我的预设出现在正确分组并能保存数字 id；
  - 账号里的 style 在登录后覆盖本机。
- `App.test.tsx`：保存导出默认值时保留 `style`，验证偏好按字段合并。

## 6. 不做

- 不把默认风格套到恢复的旧会话 / 当前照片。
- 不存整套参数快照。
- 不把默认风格扩展成默认 Lut / 默认水印；它们各有自己的资源与强度语义。
