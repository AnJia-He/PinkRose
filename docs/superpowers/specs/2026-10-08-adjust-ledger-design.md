# 调色区账本（每版一本修改记录）· 设计

> 2026-10-08。用户原话（三句，是这份文档的源头）：
> 「就是假如我在调色区进行修改，是不在对话区的回溯区添加一个个回溯点的，
> 是我在调色区进行的一系列修修改改都是在对话区同一个回溯区展示的，然后
> 调色的回溯就是左右箭头的上一步下一步进行回溯」
> 已拍板：「**不占格**」——转盘只记对话聊出来的版本；裁剪、点修、调色都算改
> 「当前这一版」，不在转盘上留格；回退用调色屏左下角的箭头一步步退。

## 0. 一句话

**每个版本（转盘一格）带一本自己的"修改账本"**：调色区里的一切操作（裁剪、
点修、调色/滤镜/预设）记成账本上的一笔；左下角箭头在账本里前后翻（瞬间，
不用重算）；转盘只记对话聊出来的版本。落盘从"只写最后一步"改成"**哪一版改了
就存哪一版**"，且像素一律存**干净底图**——顺带修掉探针抓到的"刷新后参数应用
两次"。

## 1. 为什么这么设计（与市面对照）

- **参数派**（Lightroom / Snapseed / 醒图 / 美图）：根本不上存画面，存"做法"
  （滑块值、滤镜名），回退 = 划掉最后一笔、画面现算。泼辣官网敢写"无限撤销"。
- **像素派**（Photoshop / GIMP / Photopea）：真存画面，靠三道保命符——**上限
  封顶**（PS 默认 50 步）、**快照/出生保留**、**满了丢最老**；PS 还有暂存盘。
- 我们天然分两半：**调色 = 参数派**（只存数字，几乎不占内存，今天就是）；
  **裁剪/点修 = 像素派**（换了底图，必须留底稿才能退）。所以采用：**快照 +
  字节预算封顶 + 出生永留 + 丢最老**——就是 PS 那三道，市场验证过的标准答案。
- 明确否掉的手法：压缩存图、降分辨率留底稿（都会伤画质——"越退越糊"对修图
  工具是死罪）；这一轮也不做"记做法重放"（那是以后的升级路，见 §8）。

## 2. 现状盘点（动工前的地图，2026-10-08）

  params/lut 写回快照（只在 tip）。

## 3. ★ 探针发现的真问题：刷新后参数应用两次（本轮一起修）

**证据**（`.superpowers/probe-persist-bake.mjs`，真 Chrome、零模型花费）：

- 实验：上传 → 亮度调到 +60 → 裁剪（旋转一刀）→ 等落盘 → 整页刷新。
  画布平均亮度 **100.73 → 120.88（差 20.15）**。
- 对照组（同样调亮度、**不裁剪**）：**100.73 → 100.73（差 0.00）**。

**根因**：落盘 `patch.base = bitmapToDataUrl(el)` 的 `el` 是**画布**——画布上
跑过 `render(params)`，存下去的像素**带着参数（和滤镜）**。恢复时
`setImage(base)` + `setParams(同一套参数)` → 参数被作用**两次**。这违反 09-21
设计 §3.4 的铁律：「**参数永远不烘焙进 base**。参数只作用在最终渲染的那一刻」。
触发条件要三件同时：非零参数 + 换底图（裁剪/点修/生成）+ 刷新——所以典型的
「上传 → 说话 → 刷新」验收流（参数为 0）测不出来，一直睡着。

**修**：base 一律从**干净底图**编码（`S(V).base.bitmap`，`bitmapToDataUrl`
本来就收位图）——不再读画布。画布只留给封面缩略图（它本来就该是"现在的观感"）。
副作用是好的：画布不在（切屏）也不再拖累底图上传。

**旧数据不回溯**：库里已存的烘焙底图没法还原（谁也不知道当时参数是多少、
叠了几层）。恢复旧会话仍会翻倍——记录在案，不迁移。

## 4. 数据模型

```ts
type EditState = {
  base: DecodedImage                 // 那一刻的底图（干净、不带参数）
  params: Adjustments
  lut: LutRef | null
}

type Snapshot = {
  ...现有字段不动,
  past: EditState[]     // 当前位置之前的历史（[0] = 出生；可能被预算驱逐中间的）
  future: EditState[]   // 退过之后的位置（"下一步"走这里）
}
```

- **`base`/`params`/`lut` 三个字段 = 这一版账本的当前位置**（语义不变）——
  所有读它们的老代码（`onJump`、落盘、缩略图、重掷）一行都不用改。
- 位置显示 = `past.length + 1` / `past.length + 1 + future.length`（1 起数，
  含出生笔）。
- 不变量：
  1. 若 `past` 非空，`past[0]` = 这一版的**出生状态**（永远不会被驱逐）；
  2. `past`/`future` 里只有**换过底图**的笔持有新位图对象；调色笔的 `base`
     与相邻笔**共享同一个对象**（零内存）；
  3. 被驱逐/截断的笔，它的位图要还回去（§6 的回收清单）。

## 5. 行为契约

### 5.1 什么算一笔

- **裁剪 / 点修**：落刀即一笔（原子操作，不合并）。
- **调色 / 滤镜 / 预设 / 「原图」重置 / 照着这张调**：一次**连续调整** = 一笔；
  停手约 0.8 秒（与落盘同一档防抖）定稿。连着调几个滑块不歇 = 同一笔；
  调完歇一会再调 = 新的一笔。
- 净变化为零（拖走又拖回原值）**不记**（省掉空笔）。

### 5.2 记账规则

- 记账 = 把"改之前的状态"压进 `past`、**清空 `future`**、当前位置 = 改之后。
- **现场镜像**：调色区里参数/滤镜的现场改动**立刻**写回"当前版本的当前位置"
  （549836b 那条 effect 从"只在最新一步"放宽到"当前这一版"）——账本、落盘、
  转盘跳转读的都是它。记账时"当前位置"已经是最新值，只欠把"改之前"压进 `past`。
- 新一笔清后面是标准撤销语义（和"退到中间再生成会切掉后面"同一条）。
- **跳走再回来**：账本和位置都跟着版本走（在内存里，跳到别的版本再回来
  东西仍在）。
- 站在账本中间**继续动手**：后面那些笔作废（含它们的位图回收）。

### 5.3 箭头（调色屏左下，`ui/StepNav`）

- 组件本身不动（只收"第几 / 共几 + 两个动作"），**App 的接线换**：从"翻版本"
  改成"翻当前版本的账本"。
- 只在调色屏画；**`total > 1` 才画**（没动过 = 不摆一组按不动的按钮）；
  裁剪/点修开着时收起（沿用 39fb4d0 的判据）。
- 「上一步」= 位置 −1（当前状态压进 `future`）；「下一步」= 反过来；两头禁用。
- ⚠️ **不再用来翻版本**——版本由修图屏的转盘管（宏观=转盘，微观=账本）。
- 文案：`aria-label` 的组名从「切换版本」改成与账本对应的说法（跟着改
  `docs/文案规范.md` 与按文字找它的测试/探针）。

### 5.4 转盘与生成（不动的地方 + 明确的地方）

- 转盘只记"对话版本"：原图 + 每次生成。裁剪/点修/调色**不加格**。
- 点转盘 = 落到**那一版的账本当前位置**（不是出生、不是最新——是你最后在
  那一版上弄好的样子；和 549836b 的承诺一致）。
- 生成/重掷/「再来一版」照旧：从当前位置生成、成功后切掉后面的版本（设计
  §4.1），**账本不受影响**；新版本出生 = 账本只有一笔。

### 5.5 定稿点（flush）

有"没落定的调色"（拖了滑块还没到 0.8 秒）时，以下动作**先定稿再走**：

- 点箭头、点转盘跳版本；
- 裁剪/点修落刀（先定稿成一笔，再记裁剪/点修那一笔——顺序不能反）；
- 生成落地（挪光标之前）；
- 切会话 / 换照片（借 `flushPersist` 那套，两个 flush 一起打）。

理由：版本之间不许出现"半截笔"；用户"调完马上退"时退的必须是**他刚调的那下**。

### 5.6 已知口径

- 站在账本中间生成：用**当前所见**当底（和今天一样）。
- 删除版本/删除一步：它的账本一起走（位图回收）。
- 刷新后：账本清空（每版只剩当前位置一笔）；人落在最新一步（位置不落盘，
  不变）。

## 6. 内存

- **成本**：只有"换了底图"的笔占一份位图（裁剪/点修各一份，≤2048 长边）；
  调色笔零成本。
- **预算**：`LEDGER_PIXEL_BUDGET`——**所有版本账本里额外保留的底图总像素
  ≤ 3200 万**（初值；小照片能留十几笔、大照片自动少留；真机验收后按内存调这个数）。
- **驱逐**：超预算时丢**最早的非出生笔**（整笔丢，不是只丢位图），直到回到
  预算内；**出生笔和当前笔永不丢**；可驱逐的位图先按入账先后排队。
- **位图回收的每一站**（全都要认账本——漏一个就是泄漏或闪黑）：
  1. `pushSnapshot` 挤出版本（`history` 只留 6 步）；
  2. `cutAfter` 切版本（生成/裁剪站中间）；
  3. 删除消息/删除版本；
  4. 切会话 / 换照片（`loadSession` / `onPick` / resetEditor）；
  5. 撤销后新记账清 `future`；
  6. 预算驱逐；
  7. StrictMode 双跑（`close()` 幂等，照旧）。
  统一走一个"收集所有活位图 → 关掉不在集合里的"的纯函数（扩展
  `bitmapsToClose` 的语义），别各处手写。

## 7. 落盘（协议 + 客户端）

### 7.1 协议：`stateStepId`（`src/api/sessions.ts` + `server/sessions.ts`）

- `SessionPatch` 新增 `stateStepId?: number`：**这趟的 `params`/`lut`/`base`
  说的是哪一步的"现在"**。
- 服务端 `handleUpdateSession`：
  - `params`/`lut`：有 `stateStepId` → 写在**那一步**上（合并后必须存在，
    否则 400）；没有 → 沿用旧的"最后一步"（兼容路径，留着）。
  - `base`（newFile）：有 `stateStepId` → 落在**那一步的 `image`** 上（替换）；
    没有 → 沿用旧规则（最后一个新步骤）。
- `steps` 数组的规则②（已有 id 一律沿用库里的历史）**不动**——label/prompt/at
  仍然不许客户端改；**状态**（base/params/lut）现在通过 `stateStepId` 这个
  窄口更新。把"历史"和"状态"分开说，是这次协议改动的立身之本。

### 7.2 客户端（`App.tsx` 落盘 effect）

- 新增 `dirtyRef = { stepId, baseChanged } | null`：某版的"现在"变了（记账、
  撤销/重做、裁剪/点修、调色现场）就记上；**成功写回后**清（沿用
  `lastPersistedBaseSeqRef` 那套"写成功才记"的时序）。
- 落盘 effect（800ms 防抖沿用）：
  - dirty 存在 → 送 `{stateStepId, params: S(V).params, lut: S(V).lut,
    ...(baseChanged ? { base: bitmapToDataUrl(S(V).base.bitmap, 0.9) } : {})}`；
  - **封面 thumb 照旧从画布抓**（它=现在的观感）；画布不在就跳过 thumb 本身，
    不再拖累 base；
  - **旧的 `atTip` 规则删掉**——`stateStepId` 把"写到最后一步"的误伤从根上
    解决（站在旧版本上的改动本来就该存进旧版本）；
  - `changed` 的判据从"全局 baseSeqRef"改成 `dirty.baseChanged`。
- **版本跳转前 flush**（`flushPersist`，沿用切会话那套）：消灭"两版同时脏"。
- `baseSeqRef` 留着不动——它是**竞态闸门**的号（生成 / 裁剪 / 说话那几处），
  不再是落盘判据。

### 7.3 恢复（`loadSession`）

- 每步：base = 服务端那份（今后是**干净的**）；params/lut 照旧 → **不翻倍**。
- **步骤小图**：恢复时按"base + 那一步的参数"**离屏重画**（一张一次性 WebGL
  画布，≤6 张，几十毫秒级）。不做的话，活着时小图带参数观感、刷新后变
  "没调过色"——两条路各说各话。
  ⚠️ 滤镜那层**不进恢复后的小图**（cube 是异步到手的）——记为已知边界。
- **缩略图维护**（活着的时候）：当前版本的样子变了（记账/撤销/重做）就重抓
  一次它的小图（与定稿同拍防抖）——不然转盘那一格还显示改动前的样子。

## 8. 不做的事（这一轮）

- 不做"记做法重放"（LR/Snapseed 的绝招；以后能做——到时刷新后也能接着退）。
- 不做压缩/降分辨率存底稿（伤画质）。
- 箭头不翻版本（版本归转盘）。
- 旧会话的烘焙底图不迁移（做不到；已知）。
- 不做跨会话共享账本、不做账本落盘。

## 10. 坑与风险（动工前先读）

- **位图引用管理是这轮最容易漏的地方**（§6 那份清单，每一站都要过一遍；
  "关了还在用"= 闪黑，"没关"= 泄漏，两种都不报错）。
- **定稿点漏一个 = "半截笔"**（表现为：退一步把两件事一起退了）。
- `stateStepId` 是新的信任边界：id 必须在合并后的步骤里存在；校验写清楚。
- 恢复时离屏重画小图是唯一"新机器"——规模控制在一张临时画布，别扩成
  第二条渲染管线。
- 文档连带更新：`docs/文案规范.md`（上一步/下一步那条）、
  `docs/superpowers/specs/2026-10-06-edit-tools-design.md` 那条 2026-10-08
  的更正块要再更正一次（"版本照旧进转盘"作废）。
