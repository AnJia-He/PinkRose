# 文字工具（设计）— 2026-10-17

## 0. 一句话

工具行补上「文字」：输入内容（可换行）、选字号和颜色，在照片上拖动位置，
按「加上文字」把结果写进当前这一版的底图。它不改全局参数、不进转盘、
不写对话，账本记一笔，随时能撤销。

## 1. 为什么先做烘焙式文字

主流修图产品的文字有两种形态：

1. **可回编辑的文字层**：内容、位置、字号、颜色进会话 / 作品 schema，
   之后还能选中修改；
2. **烘焙的文字操作**：像很多手机修图 App 的"添加文字"，应用后写进底图。

第 1 种要新增图层数据模型、会话迁移、渲染顺序和导出合成，是一整个子系统；
第 2 种完全复用现有的 `app/baseEdit.ts` 骨架：

- 产出新底图 + 账本记一笔 + 可撤销；
- 不碰 `Adjustments`（50 个全局参数）和会话 schema；
- 用户马上能得到"加标题 / 日期 / 一句话"的结果。

因此这一版明确是**烘焙**的：写下后不能回来改内容或位置，要改就撤销这一笔。

## 2. 选项

```ts
type TextOptions = {
  text: string     // 原文，保留两侧空格与换行
  x: number        // 文字块中心，0~1（相对照片左上角）
  y: number
  fontPx: number   // 图片像素，12~400，默认 64
  color: string    // 只接受 #rrggbb，默认 #ffffff
}
```

- 位置是**归一化中心点**，和点选红圈 / 涂抹层同一套坐标系；
- 字号是**图片像素**，预览按屏幕缩放，成片按原尺寸，二者同一句话；
- 多行按 `fontPx × 1.2` 行高，以 `(x, y)` 为中心排开；
- 空文字（含只有空格）不能提交。

## 3. 像素引擎

`src/image/text.ts`：

1. `normalizeTextOptions` 夹位置、字号并校验颜色；
2. `textLayout` 输出每行的图片像素坐标；
3. `textToBitmap` 把底图画进 2D 画布，再按布局 `fillText`；
4. 字体用系统字体栈（中英文落到各平台的系统黑体），不嵌入字体文件；
5. 产出新底图，交给 `app/baseEdit.ts` 记账。

`createImageBitmap` 失败时由 `useText` 统一报一句人话，现场保留，用户可以再试。

## 4. 界面

- 工具行第五颗「文字」，图标 `Type`；
- 第二行：多行输入框、字号滑块、颜色选择、取消、「加上文字」；
- 照片上显示文字预览，虚线框提示可拖；拖动更新归一化中心；
- 工具开着时 `viewLocked` / `resetKey` 保持和点修一致：不禁缩放，
  拖动层自己吃掉照片上的指针事件；
- 提交中盖「正在写」的暗罩（`busy`），完成后收工具、换底图；
- 窄屏六颗工具格收紧内边距；第二行走既有横向滚动，
  「取消 / 加上文字」用 sticky 钉在右边。

## 5. 文字样式（2026-10-17 追加）

`TextOptions` 增加：

- `align: left | center | right`；
- `bold`；
- `outlineWidth` / `outlineColor`；
- `shadow`；
- `background` / `backgroundColor` / `backgroundOpacity`。

预览和成片共用同一套选项：预览用 CSS 的 `text-align`、`font-weight`、
`-webkit-text-stroke`、`text-shadow` 和半透明背景；成片用 canvas 的
`measureText` + `strokeText` / `fillText` + 圆角底色矩形。对齐在文字块内部
生效，文字块本身仍由 `(x, y)` 这个中心点定位。

## 6. 不做什么

- 不做可回编辑的文字图层（后续：图层 schema + 渲染顺序 + 导出合成）；
- 字体选择与整块旋转已在 2026-10-18 补齐；仍不做逐字排版和自动换行
  （换行由用户输入）；
- 行距与字距已在 2026-10-18 补齐；字距非零时逐字绘制，避免浏览器间
  `letterSpacing` 支持差异；
- 不动小程序。
