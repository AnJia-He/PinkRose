# 微信小程序常用修图版设计

## 1. 目标与结论

本次把 `mini/` 从“快速风格修图”完善成可日常使用的手机修图小程序，重点不是
照搬 Web 端全部专业能力，而是覆盖普通用户最常用的修图路径：

**选照片 → 自动推荐 / 套风格 → 手动微调 → 人像或裁剪 → 对比 → 保存。**

采用“常用修图版”范围，保留现有三个 tab：

- `修图`：空态选择照片；编辑态完成主要修图。
- `作品`：查看、再次精修、保存和删除本地成片。
- `我的`：本地空间、默认风格、服务与登录状态、隐私入口。

## 2. 首版范围

### 2.1 必做

- 拍照和系统相册选图。
- 点击照片显示原图；抬手恢复当前成片，继续使用按住看原图。
- 12 套内置风格和当前风格强度。
- 一句话 AI 修图、建议提示、生成中停止、失败重试。
- 手动调色：亮度、对比度、高光、阴影、色温、饱和度。
- 人像：磨皮、美白、红润。
- 裁剪：90° 左/右旋转、水平翻转、1:1 / 4:5 / 3:4 / 16:9、取消、完成。
- 撤销、重置当前工具、重置全部调整。
- 前后对比；对比期间不写参数、不换底图。
- 保存到系统相册，成功后同时写入本地作品集。
- 本地作品墙、原生大图预览、删除、从成片再次精修。
- 上次修图草稿恢复；照片临时文件失效时明确回到空态。
- 微信登录、服务状态、模型状态、API 地址配置。

### 2.2 不做

以下能力继续留在 Web 端，不进入本次小程序实现：

- 批量处理。
- RAW / DNG 解码。
- 相机桥、USB / PTP/IP、Canon / Sony 遥控。
- 视频调色、照片电影、实况照片兼容包。
- 图层、文字、贴纸、形状、拼图、长图、证件照。
- 局部画笔、液化、克隆和需要高内存的复杂蒙版。

这些不是“后续顺手带一下”的轻功能。小程序包体和 WebGL 缓冲都有上限，
硬塞会造成真机黑屏、内存退出或操作卡顿。

## 3. 现有基础

当前工程已经有：

- `pages/index`、`pages/works`、`pages/me` 三个页面和底部 tabBar。
- WebGL2 渲染管线，共享参数、预设和 shader。
- 风格缩略图 sprite、AI 对话、撤销、全尺寸导出和双路径存相册。
- 本地作品集：全尺寸 JPG、256px 缩略图、150 MB 上限。
- 微信静默登录和 Bearer 会话。
- 真机已知约束：不要在被 WebGL canvas 覆盖的区域放过可点控件。

设计是在这些能力上扩展，不重写现有渲染和导出链路。

      ├─ 照片舞台
      ├─ 风格栏

          ├─ AI 对话

  ├─ 空态：去修一张
  └─ 作品墙

## 5. 修图页布局

```text
┌─────────────────────────────┐
│ 换一张        PinkRose  保存 │
├─────────────────────────────┤
│                             │
│           照片舞台           │
│                             │
├─────────────────────────────┤
│ 原图  日系  胶片  黄昏 ...   │
├─────────────────────────────┤
│  AI     调色    人像   裁剪  │
├─────────────────────────────┤
│ 当前工具面板 / AI 输入区      │
│                             │
├─────────────────────────────┤
│ 修图        作品        我的 │
└─────────────────────────────┘
```

### 5.1 照片舞台

- 保持当前深色背景和等比居中。
- 照片上不放滑块、按钮、浮层或工具面板。
- 舞台绑定按住看原图。移动超过阈值或系统触摸取消时恢复成片。
- 照片最小可视高度按窗口高度计算，不允许被面板压成一条。

### 5.2 风格栏

- 横向滚动，每格 96–108rpx 宽。
- 缩略图来自真实渲染结果，不用固定示意图冒充。
- 当前风格使用薄荷绿描边和名字高亮。
- 点“原图”清空风格参数；手调参数后退出当前预设态。
- 风格强度只在选中非原图风格时出现，范围 0–100。

### 5.3 工具行

四个工具加一个对比动作：

`AI`、`调色`、`人像`、`裁剪`、`对比`。

- 同一时刻只展开一个工具面板。
- 再点当前工具收起面板。
- 切换照片时关闭所有面板。
- 生成中只允许收起面板，不允许裁剪或换底图。
- 所有按钮最小命中区 88rpx × 88rpx。

`对比`不是面板：按住显示原图，抬手恢复成片；按钮位于照片外。

## 6. 工具面板

### 6.1 AI 面板

默认展开，也是第一次进入编辑态的主要修图入口。

```text
┌───────────────────────────┐
│ 对 PinkRose 说一句          │
│ [ 天空再蓝一点…       ]  ↑ │
│ 建议：亮一点 / 肤色自然些     │
│ 对话记录（有消息时向上滚动）   │
└───────────────────────────┘
```

- 输入框 placeholder 每轮结束后更新为针对当前照片的建议。
- 用户消息和 AI 回复保留在对话区，不自动消失。
- “在想…”和“正在修…”都显示在当前回复气泡内，附停止按钮。
- 失败回复带“再试一次”；重试只在照片和参数未变化时可用。
- 生成期间显示秒表；超过 5 秒切换为真实等待秒数。
- 生成成功只换底图，不清除当前手动参数。

### 6.2 调色面板

第一行是参数组切换：`基础`、`光线`、`色彩`。首版实际只展示：

| 组 | 参数 |
| --- | --- |
| 基础 | 亮度、对比度、饱和度 |
| 光线 | 高光、阴影 |
| 色彩 | 色温 |

每根滑杆显示名称、当前值、默认值。双击名称或点右侧复位只清这一项。
面板底部提供“本组重置”和“全部重置”。

参数值沿用共享 `Adjustments`，不在页面另造一套数值协议。

### 6.3 人像面板

| 参数 | 范围 | 默认 |
| --- | --- | --- |
| 磨皮 | 0–100 | 0 |
| 美白 | 0–100 | 0 |
| 红润 | 0–100 | 0 |

- 只使用现有肤色门控 shader，不声称自动识别五官。
- 拖动时实时预览；松开后才写入草稿持久化。
- 没有检测到明显肤色时仍允许调整，但显示提示：
  “这张照片没有明显肤色区域，效果可能很弱。”

### 6.4 裁剪面板

面板提供：

- 左转 90°、右转 90°。
- 水平翻转。
- 比例：原图、1:1、4:5、3:4、16:9。
- 取消、完成。

裁剪采用“生成新底图”语义，完成后记入当前草稿，不增加 AI 消耗。
生成新底图时保留当前调色参数；取消不改变任何像素。

裁剪框的拖动与缩放在第二阶段实现；若首轮只完成比例和旋转，按钮不能提前显示。

## 7. 保存与作品

### 7.1 保存

点顶栏“保存”后直接走完整保存流程：

1. 关闭原图预览和打开的面板。
2. 全尺寸导出。
3. 存到系统相册。
4. 相册成功后异步写入本地作品集。

保存中显示遮罩、禁止重复点击、禁止生成和裁剪同时使用画布缓冲。
相册权限被拒绝时：

- 主按钮“去设置”。
- 次按钮“先存进作品”。
- 不允许只说“失败了”而没有下一步。

### 7.2 作品卡片

- 两列网格，缩略图 `aspectFill`，圆角 16rpx。
- 点卡片打开原生大图，可左右滑。
- 长按弹出“删除这张作品吗？”。
- 大图操作区提供“再次精修”：把成片作为新底图打开，参数归零。

“再次精修”从已经烘焙的成片开始，不回放原始参数；界面不把它说成非破坏编辑。

## 8. 我的页面

### 8.1 本地数据

- 作品张数和占用空间。
- 清空本地作品；二次确认。
- 0 张时按钮置灰且不能触发操作。

### 8.2 默认风格

- 原图起手或任一套内置风格。
- 保存到本机 storage。
- 只影响下一张新照片，不改变当前照片。

### 8.3 服务状态

集中显示：

- 微信登录：已登录 / 登录失败。
- 修图服务：正常 / 连不上 / 服务端配置缺失。
- AI 模型：已配置 / 未配置 / 连接失败。

只显示状态，不展示密钥明文，不在日志里输出密钥。

### 8.4 隐私与权限

- 相机权限用途。
- 相册读取与保存用途。
- AI 修图会把用户主动提交的预览发送给服务端。
- 本地作品不会自动云同步。

## 9. 状态与持久化

页面状态分为四层：

1. `view`：当前工具、面板、对话、忙闲。
2. `photo`：底图路径、尺寸、是否已烘焙。
3. `recipe`：完整 `Adjustments`、当前预设、强度。
4. `draft`：本机可恢复的草稿摘要。

草稿写入 `storage` 时只保存：

- 复制进 `USER_DATA_PATH` 的照片路径。
- 原图宽高。
- `Adjustments`。
- 当前预设和强度。
- 最后编辑时间。

临时路径不能直接写入草稿，因为它可能在微信重启后失效。
恢复草稿失败时不弹长篇错误，清掉坏草稿并回到空态。

## 10. 后端与微信配置

### 10.1 地址

- 开发：允许 `API_BASE_OVERRIDE` 指向本机 mock 或局域网服务。
- 真机调试：手机和电脑同一 WiFi，后端通过开发代理访问。
- 正式体验版 / 发布版：`API_BASE` 必须是以 `https://` 开头的已备案域名，
  并在微信公众平台加入 request 合法域名。
- 发布配置不保留本机 IP、localhost 或临时覆盖地址。

### 10.2 微信登录

- 小程序使用 `wx.login()` 获取 code。
- 服务端用正式 AppID / Secret 换 openid，不把 Secret 打到客户端。
- 正式 AppID 替换测试 AppID 后才允许预览和上传体验版。
- 测试账号和 mock 通道只用于开发，不进入发布版导航。

### 10.3 发布前检查

- 移除“载入测试照片”和“试一试登录”两个开发入口。
- 移除测试照片资源。
- 确认隐私保护指引已填写相机、相册、网络请求用途。
- 确认请求域名、上传域名和业务域名配置与代码一致。
- 确认包体低于微信主包限制，图片、字体和测试素材已压缩。

## 11. 交互与错误规则

- 所有异步操作都有进行中状态，不出现“看得见但点不动”的按钮。
- 所有错误说明“哪里不对 + 下一步怎么做”。
- 用户取消权限、取消分享、主动停止生成都算正常结束，不弹错误。
- 保存、生成、裁剪三者互斥，避免争用同一块 WebGL 缓冲。
- 工具面板切换不触发重新解码原图。
- 草稿恢复和作品页回到前台时不重复上传、不偷偷调用 AI。

## 12. 视觉规范

延续现有 PinkRose 深色视觉，不更换品牌方向：

- 背景：`#151517`。
- 主强调：薄荷绿 `#2dd4bf`。
- 正文：高对比白；辅助文字：灰。
- 字体：MiSans 子集；品牌字标继续使用现有衬线字。
- 圆角：按钮 12rpx，面板 20rpx，照片舞台 24rpx。
- 面板进入 / 收起动画 180–220ms，不弹跳。
- 动态数字使用等宽数字，避免秒表和滑杆数值抖动。

## 13. 测试与验收

### 13.1 自动检查

- `node scripts/sync-mini-shared.mjs --check`。
- `npx tsc -p mini --noEmit`。
- 现有 `smoke.cjs`、`smoke-say.cjs`、`smoke-works.cjs` 全通过。
- 新增工具面板冒烟：调色值进入渲染、撤销恢复、重置只清当前组。
- 新增裁剪冒烟：旋转/比例改变输出尺寸，取消不改底图。
- 新增草稿恢复冒烟：重启小程序后照片和参数恢复；坏路径回空态。
- 截图覆盖 iPhone 390 × 844 和窄屏 375 × 667。

### 13.2 真机验收

- 相机和相册三种权限框行为正确。
- WebGL 画布不是纯色，导出不是黑图。
- 所有工具按钮都能点击，没有控件被 canvas 吃掉触摸。
- 滑杆拖动跟手，连续拖动不会重复创建管线。
- 保存后相册能看到全尺寸成片，作品页有缩略图。
- 大图预览、删除、再次精修和清空作品正常。
- 微信重启后可恢复最近草稿；临时文件失效时回到空态。
- 弱网、断网、服务端 503、AI 超时都有下一步提示。

## 14. 实施顺序

1. 页面骨架与状态：工具行、面板切换、照片/草稿状态。
2. 调色与人像面板：共享参数、滑杆、撤销、重置。
3. 裁剪链路：旋转、比例、完成/取消。
4. 作品再次精修与草稿恢复。
5. 我的页面服务状态、默认风格和隐私说明。
6. 开发通道清理、自动冒烟、真机验收和发布配置。

每一阶段完成都必须保持现有拍照、风格、AI、保存和作品功能可用，
不做一次性大重写。

## 15. 完成标准

达到以下条件才算“常用修图版完成”：

- 用户不输入文字也能完成一次完整手动修图并保存。
- 用户输入一句话的路径仍然可用，且失败可恢复。
- 风格、手动调整、人像和裁剪不会互相覆盖参数。
- 保存、相册权限、作品集和草稿恢复形成闭环。
- 发布版没有本机 IP、测试照片、测试按钮或密钥泄露。
- 自动检查和 iPhone 真机验收全部通过。
