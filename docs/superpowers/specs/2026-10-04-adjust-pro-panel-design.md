# 「调色」专业面板设计（2026-10-04）

> 用户原话：「**调色这个界面就相当于一个专业的 P 图"软件"**」（配了一张抖音调色教学
> 截图，画面里是「色彩平衡」：色轮 + 青红 / 洋红绿 / 黄蓝三条轴），
> 问「给谁用」→ 答：**给所有人**。
>
> 本文是**设计**，不是实现。实施计划另出（`docs/superpowers/plans/`）。

---

## 0. 一句话

「调色」那一屏从"八根滑块"扩成一个像专业修图软件的面板：**老八根一根不动**，往上加
一族专业工具（自然饱和度 / 色彩平衡 / 分离色调）和三个专业手感（渐变轨 / 双击归零 /
数字可改）。**全部本地算**（不花钱、不联网、拖了立刻见），「说人话」那条路本轮不碰。

## 1. 依据（为什么是这几件工具）

2026-10-04 把八家产品的调整面板逐个查过（Lightroom 手机/桌面、醒图、美图秀秀、
泼辣、Snapseed、VSCO、Capture One、像素蛋糕；原始材料在
`.superpowers/scratch/color-survey/`）。三条结论：

1. **基本盘（八家全有，6~9 根）**：亮度/曝光、对比度、高光、阴影、饱和度、色温；
   最常见的加项 = **自然饱和度、清晰度、暗角**。
   → **我们现在的八根正好是"基本盘 + 2"**，唯一缺的是自然饱和度。
2. **"专业向"多出来的**（按出现面）：色轮/色彩平衡、曲线、HSL 分色、分离色调/颜色分级、
   色阶、可选颜色、校准、局部调整、LUT。
3. **最主流的分组词**：光效(Light)、色彩/颜色(Color)、细节(Detail)、效果(Effects)、
   曲线、HSL、色调分离/颜色分级。

**为什么"不做 Lightroom 级面板"这条旧口径不再适用**（2026-09-21 spec §2.2「八滑块放哪」：
"常驻会让界面变成 Lightroom，**冲淡对话感**"）：那条护的是**对话**。2026-10-04 起
「调色」是**独立一屏**（`/app/adjust`，**那一屏没有对话栏**）—— 把这一屏做专业，
不会挤到对话那条路。旧 spec 那一行已加指针（本文）。

## 2. 范围

### 2.1 这一批做

| # | 做什么 | 一句话理由 |
|---|---|---|
| 1 | 老八根**一根不动**（名字 / 顺序 / 范围全不变） | 基本盘是对的，不给普通人添乱 |
| 2 | 补「**自然饱和度**」（第 9 根） | 基本盘里唯一缺的；它和「饱和度」的区别是"艳的地方少动"，不塑料 |
| 3 | 新增「**色彩平衡**」：色轮 + 三条颜色轴 | 用户看到的那件；Capture One 有整页，Photoshop 是经典三轴 |
| 4 | 新增「**分离色调**」：亮部色 / 暗部色 / 强度 | 落日、复古片最常用的手法；行业普及度高、实现便宜 |
| 5 | **分组**：光效 / 色彩 / 色彩平衡 / 分离色调 / 效果（可折叠） | 用行业通用词分组（见 §1.3） |
| 6 | **滑块手感三件套**：色温渐变轨、双击归零、数字可改 | 专业感的来源（用户当场问的就是这个） |

### 2.2 排队第二批（排了序，不在本批）

**曲线** → **HSL 分色** → 色彩平衡的「阴影/中间调/高光」分层 → **局部调整**（蒙版/画笔）
→ LUT / 预设导入（§8.2 的旧账）。

- **曲线不进第一批**：它要一个全新的"拖点编辑器"控件（还要 LUT 纹理、多一遍渲染），
  值得单独一轮。
- **局部调整**是一个**子系统**（多 pass + 选区 UI + 状态），不是一个工具 —— 谁提都
  先记在这儿。

### 2.3 明确不做

局部调整、LUT 导入、AI 自动设色轮（见 §5）—— 三件都写进"第二批之后再说"。

## 3. 面板长什么样

### 3.1 分组与顺序

| 组 | 里面 | 备注 |
|---|---|---|
| **光效** | 亮度 / 对比度 / 高光 / 阴影 | 老八根的前四根，位置一个不动 |
| **色彩** | 色温 / **自然饱和度**★ / 饱和度 | 老两根顺序不变，新的插在饱和度前（它俩是兄弟） |
| **色彩平衡**★ | 色轮 + 青—红 / 洋红—绿 / 黄—蓝 | 组名直接用工具名（Capture One 的做法） |
| **分离色调**★ | 亮部颜色 / 暗部颜色 / 强度 | 同上 |
| **效果** | 清晰度 / 暗角 | 老八根的后两根 |

★ = 新增。**组按这个顺序从上到下排**：普通人的八根全在最上面（第一屏看到的就是
熟悉的那些），专业工具往下滚才出现。

### 3.2 折叠

- 每组一个标题行，**默认全展开**；点标题收起 / 展开。
- **收起状态不持久化**（刷新回全展开）—— 理由：不为此引入新的存储状态；而且
  "专业工具"藏起来就等于没做。
- 面板**自己滚**（`.panel` 本来就是滚动容器），整页不滚。

### 3.3 色彩平衡的控件

- **色轮**：88px 圆盘（色相环）+ 一个可拖的点。拖动点 = 整体往那个色偏；
  **双击回中心**（= 三轴归零）。
- **★ 色轮和三根轴是同一组值的两种表达**：拖色轮 = 同时写三根轴（零和分解：
  Δr+Δg+Δb=0，纯色偏、不动明暗）；拖某一根轴 = 只改那一轴，色轮上的点跟着走到
  新的色偏方向。**不新增第三套参数**。
- **无障碍通路是那三根轴**（都是普通滑块、键盘可走、读屏可读）：色轮对键盘/读屏
  不友好，所以它 `aria-hidden`、只是个快捷方式；**三轴能到色轮能到的每一个位置**。
- 三根轴的轨道用渐变（青→红 / 洋红→绿 / 黄→蓝），两端各一小字标色名 —— 和视频里
  那件长得一样。

### 3.4 分离色调的控件

- 两条**色相带**（彩虹渐变轨道，0°~360°，右边显示度数）+ 一条**强度**（0~100）。
- 色相带就是 §3.5 那条"渐变轨道"能力的复用（同一套控件，换一条渐变）。
- 强度 = 0 时这一组等于关闭（效果为零，见 §4 的零值等价）。

### 3.5 滑块手感三件套

1. **色温的轨道改成蓝→黄渐变**（学 Lightroom）：一眼知道往哪边是暖。
2. **双击滑块本体复零**：双击轨道或圆点 → 回到 0（试效果不满意不用拖回来）。
   ⚠️ 单击数字不归零 —— 单击数字是"输入"（见下一条），两条不能打架。
3. **数字可点着改**：点右边的数字 → 变成输入框 → `Enter` / 失焦提交、`Esc` 取消；
   输入非法（非数字）当取消，超范围**钳到边界**。

## 4. 怎么算（引擎）

全部在**同一个 fragment shader** 里加 uniform，**不引入第二遍渲染、不引入纹理**
（那是曲线的事，所以曲线排第二批）。插入点（★ = 新）：

```
0 清晰度（必须最前，原注释有理由，别动）
1 色温
2 ★色彩平衡   —— 跟色温挨着：同为"整体色偏"
3 曝光（线性空间）
4 高光 / 阴影
5 对比度
6 饱和度
7 ★自然饱和度 —— 跟着饱和度
8 ★分离色调   —— 收尾（在暗角之前）
9 暗角（要像素坐标，一直是最后）
```

- **色彩平衡**：三轴 = 三个通道的加减（青—红管 R、洋红—绿管 G、黄—蓝管 B），
  做法和色温那条 `c.r += …` 同一路数（简单、可解释）。
- **自然饱和度**：按像素已有的饱和度**反向加权** —— 越艳的推得越少、越淡的推得越多
  （这正是它和"饱和度"的区别，也是它不塑料的原因）。
- **分离色调**：按明暗给权重（亮部走亮部色、暗部走暗部色），把色偏乘进权重里。

**★★ 零值等价（硬验收）**：新参数**全为 0** 时，渲染结果必须与改动前**逐像素一致**
—— 只在零值处失效的 bug（比如 `pow(0)` 型）会让老画面悄悄变样，这条专门抓它。

**CPU 对照实现（`src/core/tone.ts`）本批不动**：它只给「照着这张调」的拟合当模型
（六个参数）。三件新工具**不进去**，理由是自洽的：照调返回的参数是**从 ZERO 长的**
（新参数必然是 0），所以"CPU 模型"和"真实渲染"不会背离。⚠️ 实现时别顺手往
tone.ts 里加 —— 加了反而要给拟合加维度（那是另一件事）。

## 5. 与「说人话」那条路的关系

**本批：新工具只有手动。** 理由：色轮这类东西"模型没有标尺"（它说不出该往哪偏、
偏多少度），乱设比不设坏。`server/prompt.ts` 一个字不动。

- `normalizeDeltas` 按 `PARAM_KEYS` 过滤 —— 新键在里面，所以模型万一输出了会被
  接受；**不承诺、不引导、不写进 prompt**（合同上不算一条路）。
- 以后要不要教 LLM 认新参数：**未决**，等第一批稳了再评估（记在 §2.2 之后）。

## 6. 参数清单（实现与测试的唯一依据）

| 字段 | 界面名 | 范围 | 组 |
|---|---|---|---|
| （现有八个） | 亮度 / 对比度 / 高光 / 阴影 / 饱和度 / 色温 / 清晰度 / 暗角 | -100~100 | — |
| `vibrance` | 自然饱和度 | -100~100 | 色彩 |
| `cbCyanRed` | 青 — 红 | -100~100 | 色彩平衡 |
| `cbMagentaGreen` | 洋红 — 绿 | -100~100 | 色彩平衡 |
| `cbYellowBlue` | 黄 — 蓝 | -100~100 | 色彩平衡 |
| `splitHiHue` | 亮部颜色 | **0~360** | 分离色调 |
| `splitLoHue` | 暗部颜色 | **0~360** | 分离色调 |
| `splitAmount` | 强度 | **0~100** | 分离色调 |

- 新增一张 **`PARAM_RANGE` 表**（默认 -100~100；上面三个例外照写），
  `clampAdjustments` / 面板滑块 / 输入框**都从它取范围** —— 一处定义。
- 色轮**不是参数**（是 `cb*` 三轴的二维视图，§3.3）。

## 7. 数据与兼容（改不动的老东西）

| 地方 | 怎么办 |
|---|---|
| `ZERO` / `clampAdjustments` / `toUnit` / `PARAM_KEYS` / `PARAM_LABELS` | 逐字段**列全**新的 7 个（缺一个 = 那一个静默失效） |
| **旧会话 / 旧作品** | `clampAdjustments` 现有写法对缺键→0（`clampOne(undefined)` 已经回 0）—— **补一条测试**把它钉住，别让"老数据 NaN"这种事发生 |
| 6 个预设 | **不动**（套用时其余参数归零，和今天一致） |
| 「照着这张调」(`colorMatch` 模块) | **不动**（只拟合六个）；**套用时参与颜色的新参数（自然饱和度 / 三条色彩平衡 / 分离色调强度）在 App 的合流点被归零** —— 拟合从 `ZERO` 起跑，它的世界里这五条就是 0；清晰度/暗角照旧保留（它们是构图与局部细节，不在"参考图长什么样"的世界里） |
| 作品详情页「这张图怎么来的」 | 自动带上新参数（走 `isChanged` + `PARAM_LABELS`）—— 检查那一列的宽度/换行 |
| 会话落盘 / 恢复 | params 本来就是整块 JSON，自动带上；**恢复要走归一化那条路**（同上测试覆盖） |
| `server/` 全部 | **不动**（prompt / validate / quota 都不碰） |

## 8. 测试与验收

**单元**
1. `shared/adjustments`：新键的 ZERO / clamp / `PARAM_RANGE` / **喂一个"缺新键的老
   params"**走一遍 → 全是 0、不许 NaN。
2. `AdjustmentPanel.test.ts`：键数从 8 → 15（它在读源码守这个数）。
3. `kit/Slider`：双击复零、数字输入的提交/取消/钳制。
4. presets 套用后新键归零（防止"套个预设把色轮留着"）。

**验收（真浏览器、真照片 —— 不用合成图）**
5. **零值等价**：新参数全 0，同一张真图渲染与改动前逐像素一致（§4）。
6. **三件工具各拍一张**：白炽灯偏色照片 → 色彩平衡纠回来；落日照片 → 分离色调
   加暖；人像 → 自然饱和度不塑料。★ 用真实照片（这条项目吃过亏，见
   `color-match-feature` 的教训）。
7. **手感**：双击归零、数字改值、键盘走查（Tab 能到每一条；色轮不抢焦点）。
8. 探针：`check:layout`（面板变长 → 照片不被挤小、面板自己滚、窄屏不溢出）、
   `check:copy`（新文案通读）、`r9_e2e` / `adjust_flow`（面板交互跑一趟）。
9. **老会话回归**：打开一条改版前的老会话 → 画面与当时一致、参数不 NaN。

## 9. 风险

| 风险 | 对策 |
|---|---|
| **"廉价滤镜味"**（2026-09-21 spec 原话："自研八滑块调出廉价味，整个产品就废了"） | 三件新工具的效果曲线**用真图调**；范围宁可保守；验收第 6 条写死 |
| 面板变长、普通人被吓到 | 老八根置顶 + 分组折叠 + 面板自己滚（§3.2） |
| 色轮对键盘/读屏不友好 | 三轴是等价通路，色轮 `aria-hidden`（§3.3） |
| 「给所有人」和"30 秒线"打架 | 面板是"想调才来"的地方；对话那条路一个字不动 |
