# 相机间隔拍摄 — 2026-10-20

## 目标

在相机桥已有单张快门的基础上，提供摄影工作流常用的间隔拍摄，不引入新的
厂商协议，也不假设相机自带走时器。

## 交互

- 只有 `capabilities.shutter` 为真时出现。
- 张数 2–20，间隔 1–60 秒。
- 开始后按钮变为「停止 X/Y」，并显示已拍张数。
- 停止、关闭相机桥或按 Esc 都会取消下一次快门。
- 拍到的照片不断刷新到列表；若开启自动导入，结束后把整组新照片一次交给批量入口，
  避免每拍一张就替换当前编辑器。

## 实现

- 前端按顺序调用现有 `POST /api/camera/shutter`，每次成功后再等待间隔，避免
  长曝光时多个快门请求重叠。
- 间隔等待使用可取消的 `setTimeout`；取消时立即唤醒循环并停止后续抓拍。
- 间隔期间的轮询新照片先暂存，结束后按 id 去重，再统一走自动导入。
- gphoto2 和自定义 `CameraControlProvider` 共用这套逻辑，不新增服务端接口。

## 边界

- 本机没有真实相机，已验证的是假执行器、UI 状态和 WebKit 390px 布局；
  实机长曝光、USB 锁和相机缓冲仍需硬件验收。
- 不使用相机内建间隔器；请求间隔从上一次下载完成之后开始计算。

## 验证

- `src/ui/CameraBridge.test.tsx`：两拍后整组导入、停止后不再触发下一张。
- `src/styles.ruler.test.ts`：控件使用现有设计刻度。
- `npm run check:camera-live`：WebKit 390px 控件可见且无横向溢出，8/8。
