# 文案规范

**为什么有这份文件**：2026-09-30 用户指着顶栏那三个词说「换个专业的说法，现在太口语化了」，
而我当天上午刚做完一轮完整的界面测试、**一条都没发现**。

没发现的原因不是疏忽，是**缺一维**：那套检查量的全是「能不能用」
（图加载了没有、溢出不溢出、按钮在不在首屏），而文案是「好不好听」。
机器没有判据，所以它从来没被测过 —— 也没有任何一份写下来的标准，
让我（或者下一个人）能对着核。

这份文件就是那份标准。它不长，但**每一条都是能对着看的**。

---

## 一、两种语域，各自守各自的地方

这个产品有**两张脸**，它们不该说同一种话：

| | 门面（落地页） | 工具（App 里） |
|---|---|---|
| 对谁 | 还没用过的人 | 已经在用的人 |
| 干什么 | 让他**相信**这东西对他有用 | 让他**知道现在发生了什么、下一步按哪** |
| 语气 | 有温度、有画面、说人话 | 短、准、不加戏 |
| 例子 | 「拍的时候顾不上。」「脸还是原来那张脸。」 | 「存好了，在左边「作品」里。」「这张图打不开，换一张试试」 |

⚠️ **两张脸都要"说人话"，但"人话"不等于"聊天"**。
2026-09-30 踩的那一脚正是在这儿：顶栏原来写「怎么用 / 效果 / 不必担心」，
读起来像从对话里截出来的半句 —— 因为两个是动词短语，中间那个又孤零零一个词。
用户的原话是「太口语化了」。

## 二、硬规矩（可以逐条核的）

### 1. 导航和按钮：完整短语、长度接近、**不劝人**

- ✅ `对话修图` `效果对比` `历史记录`（落地页顶上那三个，**2026-10-03 换的**）
- ❌ `怎么用`（动词短语，像半句话） ❌ `不必担心`（**在劝人** —— 指路牌不该劝人，
  它只回答"这边是什么"）
- ❌ `不怕改错`（2026-09-30 用过一版，**10-03 换掉了**）—— 它和 `不必担心` 是
  同一类话：**在劝人**。指路牌只报名字，读者自己会判断值不值得点。

### 2. 同一件东西，全站只有一个名字

★ **2026-10-04：「调色」搬进左栏**（用户原话：「那个微调照片的放在导航栏单列出来」
—— 他嘴里还是 09-30 之前的旧名字「微调」，同一件事）。两条落下来：

1. **顶栏不再是"四颗按钮"，是"这张照片怎么办"那三颗**（下载或分享 / 保存 /
   新的一张）。判据很简单：**这三颗都是"把图拿走"，调色是"改这张图"** ——
   不是一类东西就别摆一排。这条有测试钉着（`App.test.tsx` 的 `topbarButtons()`），
   往顶栏再加一颗改图的按钮会红。
2. **左栏那一列从现在起是"四个地方"**：这张照片（修图 / 调色）、改过的那些
   （对话）、存下来的那些（作品）。每一支都有自己的网址（`/app/adjust`），
   因为左栏那个亮点回答的是"我在哪" —— **它不能同时有两个答案**
   （做成一颗开关的话，「修图」和「调色」会一起亮）。
3. ★ **调色那一屏没有对话栏**（用户看完第一版补的：「调色就是对图片微调的
   界面区**不是**对话区」）。他把界面上这两块看成两个**区**：修图页右边是对话区
   （说话改），调色那一屏右边是微调区（拖滑块改）。窄屏上这条规矩本来就有
   （写了"三样东西抢竖向空间"的理由），现在**放到所有屏上**了 ——
   那条 CSS 因此删掉，改在 `App.tsx` 里**不渲染**（结构上的，比"渲染了再藏"硬）。
4. ★ **「调色」那一格一直在**（当天第三遍，我上一版做反了）。用户原话：
   「**调色要一直在导航栏**，没有图片的时候显示图片的地方提示还没有照片不就好了？
   但是微调的按钮要**一直在**，你这也要靠我？」
   —— 我做的"没有照片就把那一格藏起来"被一句话否掉，**想窄了**：
   **顶栏那三颗是「对这张照片做什么」，左栏这一列是「这里有哪几件事」。**
   一件事在不在，不该随手上有没有照片变；**该换的是"没东西可看"那块地方** ——
   没照片时「调色」那一屏说的是「还没有照片。」+ 一颗「选一张照片」
   （`ui/AdjustEmpty.tsx`），和对话列表那条空态同一条句式（§3.7）。
   ⚠️ 它**不是**欢迎页：欢迎页是"登录之后的第一张脸"，要介绍这个产品是什么
   （标志 + 那句话 + 背景的图片球）。两屏长得一样 = 用户看到的"点了没反应"。

★ **2026-10-03：落地页整页过了一遍文案**（用户原话：「落地页还是用专用名词吧」）。
一句话概括就是 —— **每样东西叫它正经的名字，别绕着说**。落下来两条规矩：

1. **同一个能力，落地页和 App 里不许有两个叫法。** 这一轮对齐的是：
   「每一步都退得回去」→ **回到这一步**（App 那颗按钮上的原话）、
   「手机直出 / 调完之后」→ **原图 / 调色后**（和它底下的图例本来就是同一件事）、
   「拖滑块」→ **手动调色**、拍摄信息那一格改叫 **原图的拍摄信息不会丢**。
   例外的词也是特意留的：**消除路人**（行业里通用的名字，比"把后面那个人去掉"
   更像一个能力）、**曝光 / 天空 / 路人**（摄影里现成的词）。
2. **例子归例子，名字归名字。** 示范句（「天空再蓝一点」「脸太暗了」）**保持人话**
   —— 那一节演示的正是"你平时怎么说就怎么说"，把例子也换成术语，它就自己打
   自己的脸。术语出现在**挨着它的那句话里**。

### 3. 不许写**产品做不到**的事（这条最要紧）

一句话写下去就是承诺。写之前先问：**这句话在什么情况下是假的？**
落在假的那一半上的用户，会觉得整个产品都在骗他 —— 而且这也是《广告法》
第二十八条说的那件事（"商品/服务的…内容、提供者、**形式**、质量…与实际情况
不符，且对购买行为有实质性影响"）。

#### ★ 怎么改：**说清哪半是真的，别声称例外不存在**

行业里做得最被认可的是 Apple 讲「私密云计算」那一套：它**不**声称"不联网"，
而是说清楚**哪些在设备上算、哪些要发出去、发出去时怎么保护**。
把这个当卖点讲，比笼统喊一句"不上传"可信得多 ——
而且"本地处理"这类说法**已经被读者警惕了**（搜一下能看到一整批
"别被'本地处理'四个字骗了"的文章），说它是两头输。

同一条道理用在绝对话上：**敢说"例外也会告诉你"，比声称"没有例外"更可信。**

#### 已经改掉的（2026-09-30，改之前的样子记在这儿防回潮）

| 原来写 | 为什么假 | 现在 |
|---|---|---|
| 「**不用上传**，不用排队」 | 拖滑块确实不出设备；但**说一句话**就会把一张 1024 的预览送到服务器让模型看 | 「拖滑块、换预设是在你自己手机里算的，不联网也照样用。要「把后面那个人去掉」这种本事，得让云上的模型看一眼这张照片，那一步需要联网。」 |
| 「**山里没信号也照样改**」 | 只对调色成立，生成式编辑必须联网 | 同上（h2 也从「不用等，也不用找信号」改成「当场就变，山里也能改」） |
| 「**尺寸一点没缩**」 | 在"浏览器扛不动超大图、自动缩过一档"时是假的 —— 而那种情况 App 自己老实说了"导出的图会比原图小一点"，落地页却说得斩钉截铁 | 「尺寸、拍摄时间、地点，都原样留在文件里。唯一的例外是手机扛不动的超大图 —— 那种情况我们会当场跟你说清楚。」 |
| 按钮「**免费试用**」 | 「试用」蕴含"试完要付费"，而**额度怎么定至今没定案**（设计缺口里躺着） | 「**免费开始**」—— 只承诺"开始这一步不要钱"，无论以后额度怎么定都是真的 |

⚠️ **还没定的**：免费额度策略本身（一次生成约 1.3 万 tokens）。等定了，
该说在**定价/额度那一页**，不是按钮上。

#### ★ 额度怎么说（2026-09-30 用户定案）

上面那句"等定了"三天后就定了，答案是**不写额度**：

> **"免费额度"这四个字不写**（读着像营销，而且"送多少"本身还没定），
> 只提示**一天大概能做多少** —— 而且**单位是照片张数，不是 tokens**。

数取自设计文档 §6.6 防滥用那一栏（「每人每天 **20 次**生成」），
落成一句话，说在 **App 上传前那一屏**（就是"用户使用时"那一刻）：

> 一天大概能改二十来张照片。 ← **2026-10-03 已从界面上撤掉，见下**

⚠️ 写「大概」、不写「最多」：当时**那道闸门还没做**（后端是串行队列 + 上游 429
退避，没有按人计数），所以那句话说的是**预期**，不是已经生效的规矩。

★ **2026-10-03：这句话下线了。** 用户看过上传前那一屏之后说「这些全都不要」——
三个示范句胶囊（连带"不知道从哪说起？点一个试试"）、「也可以把照片直接拖到
这一块上。」和这一句，**三样一起撤了**。**不是因为它说错了**，是那一屏要更干净
（撤掉之后只剩：标志、一句话说清这是什么、那条对话输入框）。原文记在这儿防回潮。
额度本身没变 —— 闸门 2026-10-02 就做了（后端每人每天 20 次，超了返回 429），
现在还对用户说这个数的只剩**超限那一条提示**：
「今天改得够多了（一天大概二十来张），明天再来。」（`server/app.ts`）。
等哪天要在界面上显示"今天还能改 N 张"，那才需要把它做成计数器。

⚠️ **位置有讲究**：说在**使用的当口**，不说在按钮旁边。CTA 旁边挂限额，
会把"免费开始"这个动作变沉 —— 而落地页到现在，按钮底下也**一个字都没加**。

### 4. 对用户说「你」，不说「您」

全站一致，别混。也别自称「本产品」「我们团队」——这个产品在跟用户**当面说话**，
不是在发公告。

### 5. 出错的话 = 哪不对 + 怎么办

只说了"不行"的话是死胡同（§3.7）。现成的例子：
- 「这张图打不开，**换一张试试**」
- 「没有这个账号，**去注册一个吧**」
- 「刷新一下页面，**再试一次**」
- 存失败那条横幅尤其要紧：它还得当场给一个能拿到图的按钮

### 6. 助手开口那半句，全站一种写法

聊天里助手回应前会垫半句"好"。原来四种写法混着（`好啦` / `好，` / `好了` / 模型自己
生成的 `好嘞`）—— 分开看都不难听，摆在一起像不同的人写的。
**固定文案统一用「好，」**（欢迎语「准备好啦，说说想怎么改？」是另一个功能，不算）。

★ 2026-10-05：**模型那一半也管住了**。上面这条当时只治住了我们自己的固定串，
而 `reply` 是**模型生成的** —— 它照样开口就"好嘞"。用户拿着截图指出来的，原话
「模型回答是有点问题的，我认为是有点歧义的」；同一句里还有第二处毛病：
「尽量让你看不出来」—— **省掉宾语**（看不出什么？）读起来像要**瞒着用户**，
而且那是生成那条路做不到的保证（§3 那条）。两条规矩写进了 `server/prompt.ts`
的 `ROUTER_SYSTEM`，由 `server/prompt.test.ts` 逐字钉着：
① 开头不许自己垫语气词；② 不许承诺「看不出来」，要说清**改了哪儿**。

> ★ 2026-10-05：从旧步骤再改会**先问一句**（「后面还有 N 步，从这改会把它们
> 去掉。」+「继续改 / 算了」）；点「算了」之后的收尾句是「好，那就不动这一步。」
> —— 同样以「好，」开口。**那句回复（"好，这就去改。"）推迟到点「继续改」
> 之后才说**：先说了再点「算了」就是"说了不做"。
>
> ★ 2026-10-06 起它**又往后挪了一格**：那句话在**生成成功那一刻**才说 ——
> **和图片同时出**（用户原话「对话区 AI 回复的太快，我认为它跟图片应该是
> 同时出的」）。原来它一冒出来用户就干等十来秒，两半像两条不相干的回复；
> 生成失败 / 被「停止」时**不说这句**，只说各自那句（失败、停了）。

## 三、怎么核（这一维怎么才不会再漏）

```bash
npm run dev            # 另一个窗口
npm run check:copy     # 把**用户真正看得到的字**全部打出来
```

它不判断好坏（好不好听没有机器判据），它做的是**逼你读一遍**：
从**运行中的页面**捞，因为源码里大半字符串是给我自己看的（注释、日志），
而且有相当一部分话只出现在**边界状态**（出错、空、等待）——
那些恰恰是最少被人读过的字。

改完文案就跑一下，通读一遍。**审文案这件事的漏洞从来不是"没能力判"，
是"没人读"。**

## 四、改文案之前先问的三句

1. **这句话在什么情况下是假的？**（== 产品真的做得到吗）
2. **它和旁边那句是不是同一个调子？**（== 两张脸有没有串）
3. **往前翻，同一个东西前面叫什么？**（== 是不是又多了一个名字）
