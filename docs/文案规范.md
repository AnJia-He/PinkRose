# 文案规范

**为什么有这份文件**：2026-09-30 用户指着顶栏那三个词说「换个专业的说法，现在太口语化了」，
而我当天上午刚做完一轮完整的界面测试、**一条都没发现**。

没发现的原因不是疏忽，是**缺一维**：那套检查量的全是「能不能用」
（图加载了没有、溢出不溢出、按钮在不在首屏），而文案是「好不好听」。
机器没有判据，所以它从来没被测过 —— 也没有任何一份写下来的标准，
让我（或者下一个人）能对着核。

这份文件就是那份标准。它不长，但**每一条都是能对着看的**。

---

## 一、两种语域，各自守各自的地方

这个产品有**两张脸**，它们不该说同一种话：

| | 门面（落地页） | 工具（App 里） |
|---|---|---|
| 对谁 | 还没用过的人 | 已经在用的人 |
| 干什么 | 让他**相信**这东西对他有用 | 让他**知道现在发生了什么、下一步按哪** |
| 语气 | 有温度、有画面、说人话 | 短、准、不加戏 |
| 例子 | 「拍的时候顾不上。」「脸还是原来那张脸。」 | 「存好了，在左边「作品」里。」「这张图打不开，换一张试试」 |

⚠️ **两张脸都要"说人话"，但"人话"不等于"聊天"**。
2026-09-30 踩的那一脚正是在这儿：顶栏原来写「怎么用 / 效果 / 不必担心」，
读起来像从对话里截出来的半句 —— 因为两个是动词短语，中间那个又孤零零一个词。
用户的原话是「太口语化了」。

## 二、硬规矩（可以逐条核的）

### 1. 导航和按钮：完整短语、长度接近、**不劝人**

- ✅ `怎么改` `效果对比` `不怕改错`
- ❌ `怎么用`（动词短语，像半句话） ❌ `不必担心`（**在劝人** —— 指路牌不该劝人，
  它只回答"这边是什么"）

### 2. 同一件东西，全站只有一个名字

| 叫什么 | 指什么 | 出现在哪 |
|---|---|---|
| 修图 / 对话 / 作品 | 左栏那三屏 | 导航 |
| **对话** | 改过的那些照片（一次会话 = 一张照片，**过程**的家） | 左栏导航、会话列表那一页 |
| **调色** | 那八个参数（亮度…暗角） | 顶栏按钮、面板标题、详情页那一栏。**2026-09-30 之前叫「微调」，现在统一成「调色」** —— 落地页和详情页本来就在用它，改的是面板和按钮 |
| 作品 / 我的作品 | 存下来的那些图 | 左栏、页面标题、详情页的「← 作品」 |
| 选一张照片 | 上传那个动作 | 上传前那一屏 |

（`shared/adjustments.ts` 里那份给模型看的措辞是**另一套**，而且注释说明了
那是故意不同的 —— 那个不算。这份表只管界面这一侧。
⚠️ **「对话」和「作品」是两样东西，别混**：对话是过程（改过哪些），作品是结果
（存下来的图）—— 详见 `docs/superpowers/specs/2026-10-01-sessions-design.md` §6.1。）

### 3. 不许写**产品做不到**的事（这条最要紧）

一句话写下去就是承诺。写之前先问：**这句话在什么情况下是假的？**
落在假的那一半上的用户，会觉得整个产品都在骗他 —— 而且这也是《广告法》
第二十八条说的那件事（"商品/服务的…内容、提供者、**形式**、质量…与实际情况
不符，且对购买行为有实质性影响"）。

#### ★ 怎么改：**说清哪半是真的，别声称例外不存在**

行业里做得最被认可的是 Apple 讲「私密云计算」那一套：它**不**声称"不联网"，
而是说清楚**哪些在设备上算、哪些要发出去、发出去时怎么保护**。
把这个当卖点讲，比笼统喊一句"不上传"可信得多 ——
而且"本地处理"这类说法**已经被读者警惕了**（搜一下能看到一整批
"别被'本地处理'四个字骗了"的文章），说它是两头输。

同一条道理用在绝对话上：**敢说"例外也会告诉你"，比声称"没有例外"更可信。**

#### 已经改掉的（2026-09-30，改之前的样子记在这儿防回潮）

| 原来写 | 为什么假 | 现在 |
|---|---|---|
| 「**不用上传**，不用排队」 | 拖滑块确实不出设备；但**说一句话**就会把一张 1024 的预览送到服务器让模型看 | 「拖滑块、换预设是在你自己手机里算的，不联网也照样用。要「把后面那个人去掉」这种本事，得让云上的模型看一眼这张照片，那一步需要联网。」 |
| 「**山里没信号也照样改**」 | 只对调色成立，生成式编辑必须联网 | 同上（h2 也从「不用等，也不用找信号」改成「当场就变，山里也能改」） |
| 「**尺寸一点没缩**」 | 在"浏览器扛不动超大图、自动缩过一档"时是假的 —— 而那种情况 App 自己老实说了"导出的图会比原图小一点"，落地页却说得斩钉截铁 | 「尺寸、拍摄时间、地点，都原样留在文件里。唯一的例外是手机扛不动的超大图 —— 那种情况我们会当场跟你说清楚。」 |
| 按钮「**免费试用**」 | 「试用」蕴含"试完要付费"，而**额度怎么定至今没定案**（设计缺口里躺着） | 「**免费开始**」—— 只承诺"开始这一步不要钱"，无论以后额度怎么定都是真的 |

⚠️ **还没定的**：免费额度策略本身（一次生成约 1.3 万 tokens）。等定了，
该说在**定价/额度那一页**，不是按钮上。

#### ★ 额度怎么说（2026-09-30 用户定案）

上面那句"等定了"三天后就定了，答案是**不写额度**：

> **"免费额度"这四个字不写**（读着像营销，而且"送多少"本身还没定），
> 只提示**一天大概能做多少** —— 而且**单位是照片张数，不是 tokens**。

数取自设计文档 §6.6 防滥用那一栏（「每人每天 **20 次**生成」），
落成一句话，说在 **App 上传前那一屏**（就是"用户使用时"那一刻）：

> 一天大概能改二十来张照片。

⚠️ 写「大概」、不写「最多」：**那道闸门还没做**（后端现在是串行队列 + 上游 429
退避，没有按人计数）。所以这句话说的是**预期**，不是已经生效的规矩。
等哪天真加了闸门，这句再改成「今天还能改 N 张」—— 那时候它就是个计数器了。

⚠️ **位置有讲究**：说在**使用的当口**，不说在按钮旁边。CTA 旁边挂限额，
会把"免费开始"这个动作变沉 —— 而落地页到现在，按钮底下也**一个字都没加**。

### 4. 对用户说「你」，不说「您」

全站一致，别混。也别自称「本产品」「我们团队」——这个产品在跟用户**当面说话**，
不是在发公告。

### 5. 出错的话 = 哪不对 + 怎么办

只说了"不行"的话是死胡同（§3.7）。现成的例子：
- 「这张图打不开，**换一张试试**」
- 「没有这个账号，**去注册一个吧**」
- 「刷新一下页面，**再试一次**」
- 存失败那条横幅尤其要紧：它还得当场给一个能拿到图的按钮

### 6. 助手开口那半句，全站一种写法

聊天里助手回应前会垫半句"好"。原来四种写法混着（`好啦` / `好，` / `好了` / 模型自己
生成的 `好嘞`）—— 分开看都不难听，摆在一起像不同的人写的。
**固定文案统一用「好，」**（欢迎语「准备好啦，说说想怎么改？」是另一个功能，不算）。

## 三、怎么核（这一维怎么才不会再漏）

```bash
npm run dev            # 另一个窗口
npm run check:copy     # 把**用户真正看得到的字**全部打出来
```

它不判断好坏（好不好听没有机器判据），它做的是**逼你读一遍**：
从**运行中的页面**捞，因为源码里大半字符串是给我自己看的（注释、日志），
而且有相当一部分话只出现在**边界状态**（出错、空、等待）——
那些恰恰是最少被人读过的字。

改完文案就跑一下，通读一遍。**审文案这件事的漏洞从来不是"没能力判"，
是"没人读"。**

## 四、改文案之前先问的三句

1. **这句话在什么情况下是假的？**（== 产品真的做得到吗）
2. **它和旁边那句是不是同一个调子？**（== 两张脸有没有串）
3. **往前翻，同一个东西前面叫什么？**（== 是不是又多了一个名字）
