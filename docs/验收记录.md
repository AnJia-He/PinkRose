### 2.2 附加证据（设计文档 §10 点名"单元测试碰不到、要真浏览器 + 真数据库"的两条）

① **cookie 真的被浏览器接受**（不是只有响应头上有）：

```
Set-Cookie: rx_session=<票>; HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000
浏览器里存下来的：name=rx_session  domain=localhost  path=/  httpOnly=true
                 sameSite=Lax  secure=false  到期 2026-10-25（约 30 天后）
document.cookie 里读出来是空字符串 → HttpOnly 真的生效，页面脚本偷不走这张票
```

② **同名并发注册（真数据库的唯一约束）**：同一个名字同时发两个注册请求 →
**一个 200、一个 400**，失败那句是「这个名字有人用了，换一个吧」。
没有"两个都成功"，也没有 500。（两次独立复现，用了两个不同的名字。）

③ 第 2 条那个"前端拦住了"是数出来的：填三个坏名字、点三次提交，打向
`/api/login` 或 `/api/signup` 的请求数 = **0**。也就是说那三句提示都来自前端共用的
那份规则（`shared/account.ts`），压根没到后端。

### 2.3 顺带把**生产构建**也走了一遍（8787、同源、没有代理）

日常调试走的是 5173（vite 代理 `/api`），而真实用户拿到的是构建好的那一份。
在 `http://127.0.0.1:8787/`（后端直接发 `dist/`，同源）重走了一遍关键三步：
首屏是登录页 ✅ → 用「小明」登录 HTTP 200 进修图界面 ✅、cookie 照样被收下
（httpOnly=true、sameSite=Lax）→ 刷新后还在 ✅。付费调用次数 **0**。

## 我错了什么 / 计划哪里讲不通

> 老规矩（§13 那次事故留下的）：这一节**不许写"全部通过"**。下面全是我这一步真的踩到的。

**1. 验收表里「点退出 → 刷新」这一行，在今天的界面上做不到。**

不是 bug，是排期；但表本身是错的，它会让人以为"退出"这一段就该能用。

**2. 「现有那套检查必须照旧全绿」这句讲不通——`npm run check:layout` 是红的，而且不是我弄红的。**
它红在 `page.setInputFiles: Timeout 30000ms`：那条脚本（2026-09-23 写的，早于登录页）
打开页面第一件事就是往 `input[type="file"]` 里塞照片，而页面现在**先给登录页**，没有那个 input。
**它是被 Task 7（前端登录页）弄红的，而 Task 7 的报告里一个字都没提 check:layout**——
也就是说那条检查在加完登录页之后**根本没人跑过**。
为了分清"是检查缺一步"还是"版面真的坏了"，我做了个探针：给那条脚本加上"先登录"三步之后，
**它全绿**，两档 × 两态的**判据数字一条没变**（手机 390×844：画布 350×233、红圈直径 42；
桌面 1280×600：画布 750×500、红圈直径 90）。所以坏的是**检查**，不是界面。
探针的完整 diff 留在 `.superpowers/sdd/2026-09-25-accounts-foundation/task-8-layout-fix-proposal.diff`。
**我没把它并进去**：改那条脚本不是这一步的授权范围，而且"检查用哪个测试账号"得你拍板

**3. 我把注册的成功码写成了 201。** 实际是 **200**（`server/app.ts` 里就是

教训：验收脚本里的"该看到"必须先去代码里核一遍，别照着直觉写。

**我是先看到红、才回头去读那张表的**——顺序反了。

**5. 第一次跑"登录"那一条判红了，其实是我的脚本抢跑。** 点完「登录」立刻取样，

**6. 「验收记录 §13/§15/§17 指向一份不存在的文档」——这句话我查下来不完全对，所以我按查到的事实写。**
